## 순서
1. `import-credigraph` 최신에서 새 브랜치 `e-gift-1025`.
2. 조문 확인: §53의2(혼인·출산 공제 — 금액·기간·§53 과의 관계) · §47②(10년 합산) · §53 현행 금액 재대조 → 설계 부록 B 에 행 추가.
3. 계산기: `gift_tax` 에 §53의2 · 10년 합산 입력(과거 증여가액·기납부세액 — §58 공제 포함 여부 원문 확인) — 기본값이면 기존 결과 그대로(테스트로 고정).
4. 추출·slots: 증여재산가액 · 증여자↔수증자 관계 · 수증자 성년 · 혼인/출산 여부 · 10년 내 증여 이력. 필수 = 증여재산가액(없으면 그것만 묻기, Solar 0), 나머지는 보수 가정 + '가정:' 줄 + 청하기 한 문장(주식과 같은 §2-4 방식). 경우 나누기가 필요한 값이 있는지 판단(혼인 공제 대상 여부 등) — 필요하면 사용자 확인.
5. pipeline 갈래 연결(`GIFT_CALC`): 주식 갈래 구조(`_stock_plan`·`_stock_finish`)를 본뜬다 — 결론 문단 = 계산기 · 작문은 세액 금지 · 단계 표 · NOT_MODELED(평가·재산 종류별 평가는 계산 안 함) + 청하기. outcome 이름 예 `gift_calc`·`gift_missing` → **프론트 `lib/outcome-groups.ts` 에 이름 추가 필요한지 확인**(관리자 대시보드 묶음).
6. 테스트(calc·api) → 로컬 회귀: 새 증여 시나리오 세트(`eval/local/gift_set.jsonl` — 현금·부동산 가액·성년/미성년·배우자·조부모(세대생략)·혼인 공제·10년 이력·금액 없음) + 위 평가 세트 증여 질문 라우팅 표(on/off) + 주식 회귀.
7. 배포는 사용자 확인 뒤: push(import-credigraph·main) → 사용자 터미널 `& "C:\Program Files\Git\bin\bash.exe" backend/deploy/deploy.sh` → **.env 는 바꾸지 말고 먼저 off 스모크**(`python -m eval.run_demo_eval --tag gift-off-smoke --prefix eval-g --only W01,V01,E01,C01,O01,X01,S01,S03,X07` → 직전 `e-on-smoke_10241956`(S03·X07 은 `bd1024_r1`)과 outcome 대조) → `GIFT_CALC=on` 은 사용자 결정, 켜면 서버 .env 수정 + `sudo systemctl restart neo-luddite-api` → 운영 증여 시나리오 몇 개 + 스모크 다시.
