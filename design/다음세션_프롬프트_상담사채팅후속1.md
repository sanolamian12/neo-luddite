## 이번 범위
1. **#4 `/audit/chat-logs/<라이브 id>` 서버 오류 해소**: 서버에서 스토어를 부르지 않게. 정적 id 는 지금처럼, 라이브 id 는 클라이언트에서
   대화를 당겨(`useConversationRecord` 또는 `useEnsureConversations`) 적재 중엔 스피너(`LoadingBlock`), 끝났는데 없으면(권한 밖 포함) "찾을 수 없습니다" 안내.
   `AuditExperience` 가 스토어 변화에 반응하게(구독). 들어오는 두 링크(admin 풀 상세 · 인용 피드백)에서 실제로 열리는지.
2. **#5 경로 B 방의 세무사 쪽 원 대화**: 세무사 방 헤더에 원 대화 링크를 경로 B 방에도. 원문 열람은 0040 조건 ③(방이 있는 대화)으로 이미 열려 있다 — DB 변경 없어야 한다.
   어떤 화면으로 보낼지는 아래 "물을 것" 결정대로.
3. 둘 다 사장님 원문을 세무사에게 보이는 화면이므로 **§3.7 규칙**: 라이브 대화를 보여 주는 새 화면은 `useEnsureConversations`/`useConversationRecord` 로 직접 당긴다.

## 착수 전에 사용자에게 물을 것
- **경로 B 방에서 세무사가 보는 원 대화 화면**: ① 읽기 전용 원문 화면(기본안 — 전사만, 코멘트·평가 쓰기 없음. 일감 밖에서 검수 기록이 생기지 않는다)
  / ② `/audit/chat-logs/<id>` 감사 작업 공간 그대로(코멘트·평가를 달 수 있음 — 검수 흐름·정산과 섞일 수 있다).
  ①이면 경로 A 방의 링크(→ 신청 상세)도 같은 화면으로 모을지 함께 묻는다.
- **라이브 id 의 `/audit/chat-logs` 작업 공간에서 쓰기(라인 피드백·세션 평가)를 허용할지**: 지금 링크로 들어오는 사람은 admin(풀 상세)·세무사(인용 피드백).
  기본안: 동작은 지금 코드 그대로 두고 오류만 고친다(허용 범위 변경은 별도 결정).
- **스냅샷 vs 최신**: `getStoredConversation` 은 정지 스냅샷(`snapshotPayload`)을 먼저 준다. 방에서 보는 원 대화는 스냅샷(검수와 같은 기준, 기본안) / 최신 payload 중 어느 쪽인지.
