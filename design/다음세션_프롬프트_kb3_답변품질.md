## 2. 풀 문제 (앞 세션에서 실제로 본 것)

1. **쟁점 어긋난 근거에 끌려감** — C48("세무조사 연기 신청 가능? 사유는?") 프로덕션 답이 **연기(국기법 §81의7)** 를 **중지(§81의8④)** 조문으로 설명했다. 근거 1위 심판례가 '중지 요청 거부' 사건(조심 2026부1219). 같은 질문 로컬 실행은 §81의7 을 맞게 썼다 = 회차마다 흔들린다.
2. **남의 사건 사실 옮김** — numeric_guard 는 근거에 **있는** 수를 통과시킨다. C30("아버지가 제 명의 통장에 넣어둔 돈") 답이 사용자가 말하지 않은 "미성년자"를 전제로 "10년간 2,000만 원 공제"를 설명했다(kb3 끔 답엔 없었음 — kb2·kb3 중 어디서 왔는지 미확인).
3. **질문 밖으로 퍼짐** — C48 이 가산세 감면 '정당한 사유'로, C16 이 매입세액 불공제(§39)로 길게 흐른다.

## 3. 워크플로우 (순서대로 · 단계마다 사용자 확인)

1. **진단(코드 0 · DB 쓰기 0)** — `wire_v1/kb3_wire_check.py` 하네스(= `run_clinic` 직접 호출 + `store.record_chat_turn` 바꿔치기)로 C48·C30·C16·C41 을 각 3~5회. 회차마다 주입 근거(corpus·사건번호·쟁점 줄)와 답변을 나란히 놓고, 문제 1~3 이 **어느 근거에서** 오는지 가른다(특히 C30 "미성년자" 출처).
2. **대응안 고르기** — 진단 결과를 보여주고 사용자에게 고르게 한다. 후보:
   - (a) 프롬프트 규칙 보강: "근거의 쟁점이 질문의 쟁점과 다르면 그 근거를 쓰지 말 것", "질문이 묻는 제도(연기/중지 등)의 조문을 근거에서 확인하고 다른 제도의 조문으로 대신하지 말 것", "사용자가 말하지 않은 신분·속성(미성년자·법인 등)을 전제하지 말 것". 비용 0, 효과는 회차 흔들림 속에서 측정 필요.
   - (b) 근거에만 있는 사실 탐지(numeric_guard 확장): 답 문장의 수치가 **사용자 발화·엔진엔 없고 KB3 근거에만** 있으면, "사례로 밝혀 쓴 문장"인지 보고 아니면 제거. 기존 guard 와 같은 결정적 코드.
   - (c) 쟁점 적합성 게이트: 심판례 카드의 쟁점 줄과 질문을 Upstage 로 한 번 대조해 어긋난 카드를 뺀다. 턴당 Upstage 호출 +1(FIFO 게이트 k=3·전시 부하 고려).
   - (d) 컷·쿼터 조정(.env 만): 벤치 근거(0.40·쿼터 2 합격)를 뒤집는 일이라 마지막 수단.
   추천 = (a) + (b) 먼저, 부족하면 (c).
3. **구현 + 로컬 검증** — 같은 하네스로 전·후 비교(문항당 5회 이상). 판정형 경로 판정 불변 · 판정형 날조 guard 후 0 · **C16·C48 이 다시 미지원/되묻기로 떨어지지 않는지**(배선 이득을 잃지 않기).
4. **배포** — 응답 모양 그대로면 백엔드만: push → `backend/deploy/deploy.sh`. 서버 `.env` 변경이 필요하면 사용자 확인 후.
5. **프로덕션 확인** — 같은 질문 1~2턴, 대화 ID 접두는 이번에도 구별되게(`kb3q_` 등).
