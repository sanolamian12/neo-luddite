# design/ — 여러 세션에 걸친 공사의 설계 마스터

이 저장소는 원래 코드(`backend/`, `frontend/`, `supabase/`)와 기록(`history/`)만 추적하고
`docs/` 는 로컬 전용이다. 그런데 한 기능을 여러 세션에 나눠 구현할 때는 **설계 마스터와
다음 세션 인수인계 프롬프트가 기기에 묶여 있으면 안 된다** — PC를 옮기거나 클론을 새로 뜨면
사슬이 끊기고, 다음 세션이 설계를 처음부터 다시 지어낸다.

그래서 그 두 종류만 여기에 둔다(2026-09-21).

| 넣는 것 | 넣지 않는 것 |
|---|---|
| 설계 마스터(`*_설계.md`) — 결정·데이터 모델·단계표·진행 기록 | 접속 정보·키·`.env` 값 |
| 세션 인수인계 프롬프트(`다음세션_프롬프트_*.md`) | 실 고객 자료, 대화·답변 원문 데이터 |
| | 완료 후 아카이브 — 끝난 공사는 `history/` 요약으로 남기고 여기서 지운다 |

데모 계정(`<id>@demo.local` / `demo1234`)은 이미 `supabase/seed` 와 e2e 스펙에 있으므로 무방하다.

## 규칙

- **진행 기록은 설계 문서 안(§ 진행 기록)에 쌓는다.** 단계가 끝날 때마다 커밋한다.
- **설계가 현실과 어긋났으면 본문을 고친다.** 기록만 덧붙이고 본문을 두면 다음 세션이 옛 설계를 믿는다.
- 각 세션은 끝나면서 **다음 단계 프롬프트 파일을 여기에 새로 쓴다.** 그게 사슬이다.
- `docs/doing/` 은 그대로 로컬 작업 공간이다(측정 자료, PDF, 팀 공유본 등).
