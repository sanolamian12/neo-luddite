# 다음 세션 시작 프롬프트 — 관리자 사용 현황 모니터링

아래를 새 세션 첫 메시지로 붙여 넣는다.

---

관리자 계정의 사용 현황 모니터링·대시보드를 만든다. 설계는 `design/관리자_사용현황_모니터링_대시보드_설계_1021.md` — 먼저 끝까지 읽어. §4 의 D1(질문 원문 = B안)·D3(M1 운영 배포 10/21~22 → 확인 직후 게시, 11/23 본선 최종발표까지 1개월치 데이터가 목적)은 확정이고, D2·D4·D5 는 권장안대로 진행하되 바꿀 게 있으면 시작할 때 한 번에 물어봐.

배경: 사장님 커뮤니티(경리나라·아프니까 사장이다)에 URL 을 올린다. 관리자 화면에서 ① 유입 경로별 방문 ② 채팅 세션·질문량 ③ 사장님 가입 ④ 질문의 양·질 ⑤ 세무사 연결 수요(카드 노출→클릭→성립)를 경로별로 봐야 한다.

순서: §3 의 M1(수집 깔기)부터, **오늘~내일(10/21~22) 운영 배포가 기한**. 화면(M3)은 뒤로 미루고 수집만 먼저 내보낸다(확인은 SQL). 프론트는 main 에서 새 브랜치를 따서 작업(e-calc-1019 변경 섞임 금지). M2(백엔드 chat_turns 기록 보강)는 미리 브랜치로 만들어 두고 10/23 17시 보고서 제출 직후 배포한다.

지킬 것:
- 답변 내용·라우팅은 바꾸지 않는다. 백엔드는 기록부(`store.record_chat_turn`·`pipeline._recorded`)만.
- 마이그레이션: 0061 적용됨, 0062 = 가상 세무사 "(AI)", M2 는 0063. 운영 적용은 내가 터미널에서 한다 — 명령만 정리해 줘.
- `npm run build` 금지(dev 서버가 떠 있다). `tsc --noEmit` + vitest(PGlite) 로 확인.
- 배포 git: 프론트=main push, 백엔드=import-credigraph push 후 `backend/deploy/deploy.sh`.
- 기존 `admin_usage_overview`(0049)는 지우지 말고 옆에 새 RPC 를 둔다.
- 끝나면 `history/` 에 기록하고 설계 문서 머리에 완료 표시.
