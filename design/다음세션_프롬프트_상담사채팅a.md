## 이번 (a) 범위
1. **마이그레이션 `0037`**
   - `public.conversation_pool_consents` (설계 §3.1) + RLS
   - `mask_conversation_payload(jsonb) returns jsonb` — 설계 §3.2 규칙표. 치환 결과와 `{규칙: 건수}` 리포트
   - `grant_pool_consent(conversation_id)` / `revoke_pool_consent(conversation_id)` — 동의·마스킹·등재를 한 트랜잭션에
   - `list_pool_cases()` — 세무사·admin 전용, 유효 동의만(`revoked_at is null and expires_at > now`), 원문 테이블 미조인
2. **동의 UI (사장님)** — 경로 A 신청 시트에 체크 한 줄 + "무엇이 가려지는지 보기"(마스킹 미리보기 + 리포트).
   `/consultations` 에 동의 상태·만료일·[동의 철회].
3. **`/audit/pool` (세무사, 읽기 전용)** — 비식별 사례 목록·상세. 상단 고지 문구(설계 §4.2). 연결 요청 버튼은 (c)에서.

## 검증 (이 프로젝트 관행)
- 마스킹 규칙 **단위시험**: 양성(전화·사업자번호·계좌·이름…)과 **음성**(`1,000-2,000` 같은 금액, 연도, 세법 조문 번호를 지우면 안 된다) 둘 다.
- 역할별 RLS 검증(psycopg 트랜잭션 + 롤백): 사장님은 본인 동의만 / 세무사는 `list_pool_cases()` 로만 / 철회 즉시 사라짐 / 만료 경과분 제외 / 세무사가 `conversation_pool_consents` 직접 조회 불가.
- 브라우저 E2E: 사장님 동의 → 세무사 풀에 뜸 → 철회 → 사라짐. 412px 확인.
- tsc 0 · lint 0 · build ✓. E2E 가 만든 대화·동의·`rag.chat_turns` 는 끝나고 지운다.
