# 상담 답변 표

2026-10-13 회의 후속: 금액과 계산 과정을 답변 안에서 비교할 수 있게 한다.

## 표시 방식

- 기존 답변에 포함된 GitHub Flavored Markdown 표를 의미 있는 HTML table로 렌더링한다.
- 열 머리글, 가로 구분선, 강조 문구를 보존한다. 숫자는 자릿수가 일정한 글꼴로 표시하고 Markdown 정렬 지시를 따른다. 정렬 지시가 없으면 숫자·금액·비율만 우측 정렬한다.
- 넓은 표는 답변 안에서만 좌우 스크롤한다. 첫 열은 고정하고, 넘치는 표에만 스크롤 안내와 키보드 포커스를 제공한다.
- 원래 세그먼트 ID와 출처 배지는 유지한다. 사용자 입력은 원문으로 표시하고 AI 답변에만 Markdown을 적용한다.
- 일반/게스트 상담, 원격 답변과 역할 데모의 AI 답변이 공통 renderer를 사용한다.
- `/demo/tables`에서 두 열 금액 표와 여섯 열 계산 표를 확인할 수 있다. 모든 수치는 표시용 가상 예시이며 법률 판단이나 세액 계산 검증을 의미하지 않는다.

## 백엔드 전달 형식

기존 `message.segments[].text`에 Markdown 표를 포함하면 된다. API 스키마 변경은 없다.
표의 머리글·구분선·본문은 하나의 세그먼트 안에 함께 전달한다. 표 도중 세그먼트를 나누면 별개의 Markdown 블록으로 해석된다.

```markdown
한 줄 요약입니다.

| 항목 | 금액 | 비고 |
| --- | ---: | --- |
| 예시 항목 | 1,000,000원 | 입력값 |
| **합계** | **1,000,000원** | |

계산 전제와 확인할 내용을 이어서 설명합니다.
```

각 셀의 수치와 의미는 모델/계산 함수가 결정한다. UI는 값을 바꾸거나 계산하지 않으며, 서술형 답변을 임의로 표로 변환하지 않는다. 셀 안의 `|`는 `\|`로 이스케이프한다. 원시 HTML은 실행하지 않는다.

## 확인 기록

- 전체 단위 테스트 113/113 통과. 실제 렌더러를 통해 표 값·강조·출처 앵커, 이스케이프된 구분자, 코드 블록, 사용자 원문, HTML/링크 처리를 확인했다.
- 변경 파일 ESLint, TypeScript 검사, 프로덕션 빌드 및 `git diff --check` 통과.
- Chromium에서 1440px / 390px / 320px, 밝은/어두운 테마, 첫 열 고정, 가로 스크롤, 키보드 포커스와 안내의 반응형 변경을 확인했다.
- 두 열 표는 320px에서도 스크롤 없이 표시된다. 여섯 열 표는 모바일 답변 너비 안에서만 스크롤하며 페이지 전체의 가로 넘침이 없다.
- 일반 상담 화면에도 표시용 응답 데이터를 넣어 표·출처가 함께 나타나는 것과 새로고침 후 보존을 확인했다. 이는 UI 검증이며 실제 모델의 표 생성이나 세금 계산 정확도 검증은 아니다.
