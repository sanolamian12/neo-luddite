## 0. 결정 (10/7, 다시 논의하지 않음)

| # | 결정 |
|---|---|
| D1 | 순서 = **LLM1(추출) → KB3 검색 → LLM3(법령 선택) → LLM2(작문)**. 뒷단 배치(작문 뒤 번호 붙이기)는 라벨만 고치고 틀린 설명은 못 고치므로 기각 |
| D2 | LLM3 는 후보 중 **고르기만**(번호 생성 금지). 정확성은 법령명+조(+항) **키 조회**가 맡는다 |
| D3 | 작문 뒤 **코드 대조**: LLM3 가 고른 조문·엔진 근거·사용자 발화 밖 법령을 인용한 문장을 뺀다(LLM 아님) |
| D4 | 시점 차이(사례 카드의 옛 조문 번호 vs 현행)는 후보에 현행 제목·쟁점을 보여 줘서 LLM3 가 거르게 한다 |
| D5 | 원천 = `네오러다이트 법령/` 법제처 PDF(현행본, 사용자 수집). 원문 파싱은 코드, **요약(쟁점 한 줄)은 Solar** |
| D6 | Solar 는 몰리면 먹통 → 적재 생성은 **순차 1건 + 간격**(시간이 들어도) |
| D7 | 띄어쓰기 한계(법제처 PDF 는 글자 단위 줄바꿈 → 줄 끝 공백 소실, 좌표로도 못 가름) 감수. DRF 본문 API(lawService)는 현 OC 키 미신청 |

## 1. 진단 근거 (10/7 오프라인 감사, 세무사 판정 아님)

KB3 단독 회차(`kb3_only_132842.json`) 시민 48문항: 자문 46턴 · 법령 인용 58개 중 **54개가 근거 카드에 있던 조문**, 근거 밖 4개.
그런데 법령을 인용한 26턴 중 10턴 안팎이 무관 조문이거나 설명이 틀림 — C48 연기→국기법 §48(가산세 감면), C26 비거주자 1주택→§118의2(국외자산),
C27 상증법 §45 를 '과세표준'으로(실제 재산취득자금 증여추정), C43 조특법 §32 를 '세액감면 승계'로(실제 양도세 이월과세), C30 §76·§46.
→ **"근거 카드에 있는 조문만 허용"하는 화이트리스트로는 거의 못 잡는다.** 기준은 LLM3 가 질문에 맞다고 고른 현행 조문이어야 한다(D3).

## 2. 구성

| 자리 | 파일 | 내용 |
|---|---|---|
| 파싱 | `backend/scripts/law_pdf_parse.py` | PDF → `backend/data/laws/articles.jsonl`. 17개 법 43파일 **8,500조(현행 8,423)**, 원문 조 머리 대조 누락 0. 시행 예정본(`[시행일: …] 제N조`) 별도 줄, 부칙·별표 제외, 항(①…) 분리 |
| 인용 정규화 | `backend/api/law_cite.py` | `「소득세법」제88조`·약칭(상증세법·국기법·조특법…)·`제2조 및 제47조`·상대 인용(`시행령 제N조`, 문맥 법 기준) → (법령명, 조번호). KB3 인용 적중 **97.7%(심판례)·98.0%(질의회신)** — 미스는 개정으로 사라진 조문·교육세 등 |
| 쟁점 한 줄·임베딩 | `backend/scripts/law_ingest.py` | Solar `emit_gist`(issue 한 문장 + 사용자 표현 키워드) → `gists.json`, Upstage passage 임베딩 → `embeddings.npz`. 파일럿 = 국기법·소득세법·상증법 1,363조 |
| LLM3 | `backend/api/law_select.py` | 후보(근거 카드 law_articles + 카드 '조문:' 줄 + 질문 속 조문 + 조문 벡터 검색 6) 최대 16 → Solar `emit_law_picks` 최대 4(temperature 0) → `[관련 법령]` 블록(고른 항만 발췌, 1,600자 상한) + 인용 규칙 → 사후 대조 |
| 배선 | `api/pipeline.py` `_law_step`·`_law_checked` | 자문·판정 두 경로. 출처 배지는 고른 조문만(카드 law_articles 대신). LLM3 켜지면 심판례 카드 '조문:' 줄은 프롬프트에서 뺌. numeric_guard 출처에 조문 원문 추가 |
| 조문만 자문 | 같은 곳 · `llm._ADVISORY_SYSTEM_LAW` | 사례 근거 0건(off_issue·no_precedent)인데 LLM3 가 조문을 고르면 조문 일반 안내 — outcome `law_advisory` |

스위치(서버 `.env`): `LAW_SELECT=on|off`(기본 off) · `LAW_CITE_CHECK=drop|off`(기본 drop) · `LAW_ONLY=on|off`(기본 off) · `LAW_DB_DIR`(기본 backend/data/laws).
