## 1. 할 일 후보 (단계마다 내 확인)

1. 진단(코드 0·DB 쓰기 0): 세무사 domain_id 가 걸린 것 — consultation_requests/rooms/offers(expert_id), audits·line_feedback·session_evaluations(auditor_id),
   ledger_entries, expert_likes, expert_agents·room agent(0044), kb3 세무사 전용 RAG(0043), 우편. 강등 후 각각 어떻게 둘지 표로.
2. 규칙 정하기: 진행 중 상담(대기·수락)·상담방은 종료/이관? 원장·검수 기록은 보존? 카드 즉시 숨김. 재신청 허용?
3. `revoke_expert(domain, reason)` admin RPC(0035 방식 단일 전이) + 사용자 우편 알림 + 관리자 화면 버튼(전문가 관리 상세).
4. 처리방침 영향 확인.

## 2. 함정

- 0047 `guard_profile_identity` 는 호출자가 admin 이어야 role 변경 통과.
- `auditors` 행은 FK(상담·원장) 때문에 지우지 말 것 — 0049 탈퇴 처리처럼 정지·비식별.
- 로컬 `.env.local` = 프로덕션 Supabase. **운영 마이그레이션 적용은 auto mode 가 막으니 사용자가 터미널에서 실행.**
- 시험 계정은 SQL 이메일 계정으로 만들고(소셜 불필요) 관리자 화면 삭제 + 남는 "탈퇴한 세무사" 행(참조 0 확인 후) 정리.
