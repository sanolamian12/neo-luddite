## 1. 현재 구조 진단 (10/10 코드 실측)

### 1-1. 운영 중인 파이프라인 = v1 `backend/api/pipeline.py::run_clinic`
- 배포 브랜치 `import-credigraph`. **v2(LLM1/LLM2 분리·D3/D4 되묻기 상한)는 `agentic-v2` 워크트리(`../Neo-Luddite-v2`)에만 있고 운영에 없다.**
- 모든 Solar 호출은 function-calling 강제. 턴당 Solar 4~5회(추출·쟁점게이트·LLM3·작성) + 임베딩 2회.
- 흐름: ⓪ 명시 연결요청 정규식 → ① `extract_engine_inputs`(병의원 경비 9종 스키마) → 빠진 필수값이면 `write_followup` → etype 이 9종 밖이면 **자문 경로**(KB3 검색 → 쟁점게이트 ∥ LLM3 → `write_advisory`) → 9종이면 결정변수 검증 → `clinic_expense_engine` 판정 → `write_segments`.
- **세금 계산기는 없다.** `clinic_expense_engine.py` 는 경비 인정 여부·인정액만, `creator_tax_engine.py` 는 어디서도 import 안 됨.
- 운영 v1 되묻기는 질문 수·턴 수 상한이 없다(빠진 것 전부 한 번에). 브레이크는 `handoff.is_stalled`(3턴)뿐.
- `/api/chat` 은 `occupation != "clinic"` 이면 `run_coming_occupation`(준비중 안내)으로 끝난다(`main.py` chat()).

## 2. 목표 구조 (R4 의 도착점) — "Solar 가 지휘하고 도구가 사실·계산을 댄다"

```
사용자 발화 + 대화 이력
  └ [Intake / 라우터 · Solar 1회]  ─ 대화 전체를 읽고: 세목 분류(넓게) · 독립 검색질의 재작성 · 슬롯 채움 · 다음 행동 결정
        ├ ask_user   : 그 과제의 입력 목록 중 "결과를 바꾸는 것"만 1~2개. 기본값으로 진행 가능하면 묻지 않고 가정 명시
        ├ law_search : laws.articles (현 LLM3 — 후보는 벡터, 선택은 Solar, 조문번호 생성 금지)
        ├ case_search: KB3 (질의회신·심판례·세무사 사례) + 쟁점게이트
        ├ calc_*     : 결정론적 파이썬 함수 — calc_income_tax(근로), clinic_expense_engine(경비판정), …
        └ handoff    : 세무사 전환(R3 화면)
  └ [Writer · Solar 1회] ─ 도구 결과만 근거로 서술. 숫자는 도구 출력에서만(numeric_guard 유지). 가정·출처·한계 명시
```

원칙
1. **LLM1/2/3 을 버리지 않는다** — 셋을 "도구"로 재배치한다. 엔진은 경비판정 도구로 존치(판정 권위 유지).
2. **되묻기 목록은 도구 시그니처에서 나온다.** "무엇을 물을지"를 LLM 판단에 맡기지 않는다(9/25 결론: 72% 미달 원인 = 과제정의). 계산기가 받는 입력 = 물을 수 있는 목록, 기본값이 있는 입력 = 가정 명시하고 안 물음.
3. **가정 먼저 답하고 좁혀 간다**(브라우저 Claude 패턴): "1인 가구·4대보험만 공제로 가정하면 약 ○○원 → 부양가족이 있으면 알려주세요". 데모 체감이 가장 큰 차이.
4. 도구 호출 상한 한 턴 3~4회, 목표 지연 ≤ 현재(8~12초).
5. **질문 범위를 연다**: 세목 분류는 `rag/taxonomy.py` 17개 카테고리 기준. 엔진·계산기가 없는 세목도 "듣고 → 법령·사례로 안내 → 필요하면 세무사"로 응대. 9종 목록을 사용자에게 내미는 일은 없다.

### 스펙 7 대응표 (브라우저 Claude ↔ 우리)
| Claude | 우리 |
|---|---|
| 웹검색으로 2026 세율표·개정안 확인 | `laws.articles` (version current/future 필드로 현행·개정 구분) |
| 단계별 직접 계산 | `calc_*` 결정론 함수 |

| 모르면 모른다 | 폴백 사다리(R1-c) + 세무사 전환 |
| 홈택스 확인 권고 | Writer 규칙 |
> 우리 쪽이 못 하는 것: 실시간 웹검색(법령 DB 재적재 주기에 의존). 데모 범위에선 문제 없음.

## 3. 제약 (모든 단계 공통)
- **국내 AI 트랙**: 제품 구동 경로의 모델 호출은 Upstage 만(`solar-pro3`, `embedding-query/passage`). Claude 는 코드 작성·전문 수집까지. RAG 내용 = 원문 또는 Upstage 생성(D9). 변환·적재 스크립트에서도 Claude API 호출 금지.
- KB = **KB3 단독**(RAG_SOURCE=kb3). KB2 유래 문제는 무시.
- 배포: 백엔드 = `import-credigraph` push + `backend/deploy/deploy.sh`, 프론트 = main push(Vercel). 새 응답 모양(Zod 모름)이면 **프론트 먼저**. `ChatRequest`/`Message` 에 필드 추가 시 Zod 가 조용히 지우는 함정 확인.
- 운영 DB 마이그레이션은 SQL 을 준비하고 **사용자가 터미널에서 실행**(auto mode 차단).
- 사용자 dev 서버가 떠 있으면 `npm run build` 금지 — tsc 로 확인, 운영 E2E 는 Vercel 화면.
- 메모리 벡터 인덱스: KB3·법령 재적재 후 **서버 재시작 필요**.
