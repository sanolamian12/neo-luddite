## 왜 이 일이 남았나 (§7 실측)
Realtime 서버는 채널마다 `"Subscribed to PostgreSQL"` 준비 신호를 **순서대로 ~250ms 씩** 보낸다. 채널이 많을수록 뒤 컬렉션이 늦다.
(c)에서 이중 구독을 없애 채널 27 → 13, 마지막 준비 6.6 → 2.6초까지 줄였지만 **거기서 멈췄다**. 더 줄이려면 준비 신호가 한 번만 오게
**컬렉션들을 채널 하나에 묶어야 한다.** 남은 값: 로그인 직후 첫 화면 admin 3.6~4.7초(2단계 실측, 흔들림 포함) · 사장님 1.0 · 세무사 3.7.

## 착수 전에 사용자에게 물을 것
- **어디까지 묶나**: 14개 전부 한 채널 / 역할별로 묶기(세무사·사장님·admin) / 첫 화면에 필요한 것만 한 채널 + 나머지는 지금대로.
- **실패 처리**: 묶은 채널 하나가 죽으면 전부가 멎는다 — 재구독 정책(지금은 컬렉션별)을 어떻게 할지.
- **목표값**: admin 첫 화면 몇 초면 끝난 것으로 볼지(지금 3.6~4.7초).
- 이 공사를 끝으로 **설계 마스터를 history/ 로 접는지** — README 의 약속대로 지울지, 참조용으로 더 둘지.
