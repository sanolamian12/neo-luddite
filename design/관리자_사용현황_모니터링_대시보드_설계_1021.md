## 0. 목표

'경리나라'·'아프니까 사장이다' 같은 사장님 커뮤니티에 우리 URL 을 올린 뒤, **관리자 계정 한 화면에서** 다음 다섯 가지에 답할 수 있게 한다.

## 2. 설계

### 2.1 퍼널 하나로 묶는다

```
방문(visit) ─▶ 첫 질문(chat_started) ─▶ 질문 n개(chat_turns)
                     │                        └▶ 세무사 카드 노출(chat_turns.handoff_reason)
                     │                               └▶ 연결 버튼 클릭(handoff_click)
                     │                                     ├ 회원 → 연결 성립(consultation_requests)
                     │                                     └ 비회원 → 로그인 이동 → 가입/로그인(auth) → 연결 성립
                     └▶ 가입(auth: is_new)
```
모든 단계가 **visitor_id → 유입 경로(첫 방문의 utm/referrer)** 로 거슬러 올라가게 만든다. 이것이 이번 설계의 뼈대.

### 2.2 유입 경로 표시 규칙 (게시 링크)
- 게시 URL 에 UTM 을 붙인다: `https://neo-luddite.vercel.app/?utm_source=<채널>&utm_medium=community&utm_campaign=<게시글 코드>`
  - 채널 코드 예: `kyungrinara`(경리나라), `apsa`(아프니까 사장이다). 게시글마다 campaign 을 달리하면 글 단위 성과도 본다.
- **❓D2 단축 경로 `/r/<코드>`** (권장): 커뮤니티가 쿼리스트링을 자르거나 모바일 앱 인앱 브라우저가 referrer 를 지우는 경우 대비. `/r/apsa1` → 첫 방문 정보 기록 → `/` 로 이동. 코드→(source, campaign) 표는 DB 테이블(`analytics.campaigns`)로 두고 관리자 화면에서 추가.
- UTM 이 없으면 referrer 호스트로 분류(`cafe.naver.com` → naver_cafe, `m.search.naver.com` → naver_search, 없음 → direct).
- **첫 방문 기준(first-touch)** 으로 귀속. 같은 브라우저가 다른 링크로 다시 오면 그 방문의 source 는 따로 남기되, 가입·연결 귀속은 첫 방문 source.

### 2.3 이벤트 수집 — 1st-party, 새 스키마 `analytics`
외부 분석 도구를 쓰지 않는다(도메인 데이터가 한 DB 에 있어야 경로×질문×연결 교차가 되고, 쿠키 동의 배너·외부 전송 문제가 없다).

**식별자** (모두 브라우저 생성, 개인정보 아님)
- `visitor_id` = uuid, localStorage `nl_vid` (첫 방문 시 생성, first-touch 정보도 함께 `nl_ft` 에 보관)
- `session_id` = uuid, 30분 무활동 시 갱신(sessionStorage + 마지막 활동 시각)
- 로그인하면 이벤트에 `user_id`(auth uid)를 함께 실어 **visitor ↔ 회원** 연결.
- IP·UA 원문 저장 안 함. 기기 구분은 클라이언트에서 `mobile|desktop` 만.

**테이블** `analytics.events`
| 컬럼 | 비고 |
|---|---|
| id bigserial, ts timestamptz default now() | 서버 시각 |
| visitor_id text, session_id text, user_id uuid null | |
| event text | 화이트리스트(아래) |
| path text | 쿼리 제거 |
| conversation_id text null | chat_turns 와 조인 키 |
| source, medium, campaign, ref_host text | **해당 visitor 의 first-touch** 를 매 행에 복사(집계 단순화) |
| device text | mobile/desktop |
| props jsonb | 이벤트별 소량(크기 상한 2KB) |

**이벤트 화이트리스트**
| event | 언제 | props |
|---|---|---|
| `visit` | 세션 시작 1회 | landing path, 이번 방문의 utm/referrer |
| `chat_started` | 대화의 첫 질문 전송 | conversation_id(local-… 포함) |
| `handoff_click` | 세무사 카드에서 연결/신청 버튼 | expert_id, instant, logged_in, reason |
| `handoff_login_redirect` | 비회원이 "간편 로그인하고 바로 연결" | expert_id |
| `auth` | 로그인 완료(앱이 세션을 받은 직후 1회) | is_new(가입 직후 판정), provider |
| `optout` | 관리자가 "이 브라우저 집계 제외" 켬 | — |

- 쓰기 = RPC `analytics.track(p_events jsonb)` security definer, **anon 실행 허용**(챗이 비로그인이라 필수). 서버에서: 화이트리스트·길이 검증, 한 번에 ≤20건, visitor 당 하루 ≤500건(초과 무시), user_id 는 클라이언트 값 무시하고 `auth.uid()` 사용.
- 테이블 읽기 = 정책 0(관리자 RPC 로만). 보관 180일 후 pg_cron 파기.
- 프론트 전송: `lib/analytics.ts` 하나(`track(event, props)` → 메모리 큐 → 2초/페이지 숨김 시 `fetch keepalive` 로 RPC 일괄 호출). 실패는 삼킨다(화면 영향 0).

**팀 방문 제외(중요 — 초기 숫자가 작아서 우리 테스트가 지표를 오염시킨다)**
- admin·auditor 로그인 이벤트가 찍힌 visitor 는 집계에서 자동 제외 + `/admin/usage` 에 "이 브라우저 집계 제외" 토글(localStorage `nl_optout`, 켜면 track 자체를 안 보냄).
- 데모 계정(seed 8개) user_id 도 제외 목록.

### 2.6 관리자 화면 — `/admin/usage` 2판
한 페이지, 위에서 아래로 Q1→Q5 순서. 기간 선택(오늘/7/30/90일 + 사용자 지정은 나중) · 경로 필터(전체/채널별) — 필터는 페이지 전체에 걸린다. 차트는 지금처럼 직접 SVG(새 라이브러리 안 넣음, 구현 때 dataviz 스킬 참고).

1. **KPI 줄 (6칸, 직전 같은 기간 대비 증감)**: 방문자 · 채팅 세션 · 질문 수 · 신규 사장님 가입 · 세무사 연결 클릭 · 연결 성립. 우측 위 작게 "지금 접속 중 n"(최근 10분 visitor) — 게시 당일 반응 보기용.
2. **퍼널**: 방문 → 질문한 방문자 → 카드 본 세션 → 연결 클릭 → 연결 성립, 그리고 방문 → 가입. 단계별 수·전환율 가로 막대.
3. **유입 경로 표 (핵심)**: 행=source(+campaign 펼치기), 열=방문자 · 질문한 비율 · 세션당 질문 · 가입 · 연결 클릭 · 연결 성립. 정렬 가능.
4. **일별 추이**: 기존 턴 막대를 확장 — 방문자/세션/가입 시리즈 토글, "표로 보기" 유지.
5. **질문 분석**: 세목(tax_topic) 분포 · 질문유형 분포 · 답변 결과 묶음(답함=verdict·advisory·law_advisory·calc·stock_calc / 되묻기=missing_inputs·calc_ask·calc_missing·stock_missing·ratio_guide / 자료없음=no_precedent·undecided·off_issue / 세무 외=off_topic / 혼잡=congested / 세무사요청=handoff_request) — 이 묶음표는 `lib/outcome-groups.ts` 한 곳에 두고 라벨 누락도 같이 고친다. 아래에 **최근 질문 목록**(D1=B 일 때): 시각 · 경로 · 세목 · 결과 · 마스킹 원문 · 그 세션에서 연결 클릭 여부. 세목·결과로 거르기.
6. **세무사 연결 수요**: 카드 노출 사유별(explicit/advisory/no_precedent/stalled) 노출→클릭 전환 · 최근 연결 요청 목록(시각 · 경로 · 세목 · 즉시/신청 · 상태 · 가상 세무사 여부).
7. 기존 카드(전체 사용자·역할별·provider·상담 신청 상태) 는 맨 아래 "계정 현황"으로.

`/admin/dashboard` 의 "최근 7일" 카드는 새 KPI 6칸 중 4칸(방문자·세션·가입·연결 클릭)으로 바꾼다.

**RPC** (모두 security definer · `is_admin()` 검사 · `p_days` 1~180 · `p_source` null=전체 · KST 일자)
- `admin_traffic_overview(p_days, p_source)` → KPI·직전기간·퍼널·일별·경로표 (jsonb 하나)
- `admin_question_stats(p_days, p_source)` → 세목·유형·결과 분포
- `admin_question_feed(p_days, p_source, p_topic, p_outcome, p_limit, p_offset)` → 질문 목록(D1=B)
- `admin_handoff_demand(p_days, p_source)` → 사유별 퍼널 + 최근 요청 목록
- `admin_campaigns_*` → 단축 코드 목록·추가(D2 채택 시)
- `admin_usage_overview` 는 손대지 않고 남김(테스트·대시보드 전환 후 정리).

조인 규칙: `chat_turns.conversation_id` = `events(chat_started).conversation_id` → visitor → first-touch. 회원은 대화가 `local-…` 에서 서버 id 로 옮겨질 수 있으니(`adopt()`), 옮겨진 뒤 id 로 `chat_started` 를 한 번 더 보내거나(권장, 프론트 1줄) user_id 경유로 귀속.
