## 1. 팀장님 파일 두 곳을 한 줄씩 고쳤습니다 (알림)

세무사 가입을 "소셜 가입 → 신청서 → 관리자 승인" 흐름으로 바꾸면서, 팀장님 파일 두 곳에 한 줄씩 손댔습니다. 다음 작업 때 덮이지 않도록 알려 드립니다.

- `components/auth/auth-screen.tsx` — 가입 화면 안내문 아래에 "세무사이신가요? → 세무사 가입 신청 안내"(`/expert/apply`) 링크 한 줄을 넣었습니다. live에서만 보입니다(`!isPrototype`).
- `lib/account-route.ts` — 일반 회원이 로그인한 뒤 돌아갈 수 있는 경로에 `expert/apply`를 추가했습니다.

## 2. 그쪽 화면에 아직 없는 운영 기능

프로토타입 화면에는 없지만 운영에서는 이미 돌아가고 있는 것들입니다. 앞으로 화면을 바꾸실 때 이 기능들이 있다는 걸 알고 계시면 충돌이 줄 것 같습니다.

| 기능 | 위치 | 한 줄 설명 |
|---|---|---|
| **3자 상담방** | `/rooms/[roomId]` | 고객·세무사·세무사 AI가 한 방에 있습니다. AI 스위치가 2개(고객 쪽 기본 ON, 세무사 쪽 기본 OFF)이고 대기 표시는 3분입니다. 프로토타입의 "참여 요청" 개념과 이어 붙일 자리입니다. **화면이 아직 옛 shadcn 톤이라** luminous로 옮기려고 합니다(아래 4번) |
| **에이전트 설정 서버 저장** | 스튜디오 "변경 저장" | 프로토타입은 브라우저에 저장하지만, live는 `expert_agents` 테이블에 저장합니다(2MB 상한). 방마다 어떤 에이전트를 쓸지도 지정할 수 있습니다 |
| **세무사 사례 서버 상태** | 스튜디오 지식 모음 | 초안 → 게시 → 공용 승인 대기 → 공용(KB3 검색에 반영). 관리자 승인 화면은 `/admin/pipeline/kb3-share`입니다 |
| **소셜 로그인** | 로그인·가입 화면 | 소셜이 기본입니다. 이메일 칸은 "이메일 또는 기존 아이디로 로그인"을 펼쳐야 보입니다 |
| **세무사 가입 신청 · 승인 · 승인 취소** | `/expert/apply`, 관리자 "세무사 가입 승인" | 회원이 신청하면 관리자가 등록번호를 직접 조회한 뒤 승인하고, 그 계정이 세무사가 됩니다. 승인 취소(강등)도 됩니다. 진행 중 상담은 정리되고, 고객에게는 중립 문구가 나갑니다 |
| **관리자 사용자 · 사용 현황** | 관리자 메뉴 | 회원 목록, 역할, 사용량 요약입니다 |

## 3. 제안 — 화면과 저장을 `services/*` 로 나누기

매번 병합할 때 부딪히는 자리가 대부분 "팀장님 화면 파일 한가운데에 저희가 live 조건문을 넣은 곳"이었습니다. 그래서 경계를 하나 정했으면 합니다.

- 화면은 `frontend/services/*`의 함수만 부릅니다(예: `expertAgents.save()`, `contributions.submit()`, `contributions.review()`).
- 서비스 안에서 `isPrototype`이면 지금처럼 브라우저에 저장하고, live면 서버를 부릅니다. live 구현은 저희가 채웁니다.
- 새 화면을 만드실 때 저장이나 조회가 필요하면 서비스 함수 이름과 입출력 타입만 먼저 정해 주시면 됩니다(프로토타입 구현은 지금처럼 그대로 두셔도 됩니다).

이번에 남겨 주신 `design/session-learning-contributions.md`의 백엔드 요구(자기 검토 금지, 불변 제출본, 이벤트 이력, 게시와 크레딧의 원자성, 철회 시 검색 제거)는 **그대로 서버 모델로 옮길 계획**입니다. 계약이 바뀌면 그 문서만 고쳐 주시면 따라가겠습니다.

## 4. 저희 쪽 다음 작업 · 여쭐 것

다음 작업 순서는 이렇습니다.
1. "상담에서 가르치기"를 live로 엽니다. 원천은 세무사가 직접 입력하거나 붙여넣은 것만 쓰고, 채팅방 원문 불러오기는 고객 동의 UI가 생긴 뒤로 미룹니다.
2. 기여 원장과 관리자 검토를 위 계약대로 서버에 만듭니다(지금 있는 단순 승인 흐름을 이 모델로 흡수합니다).

여쭐 것:
- **3자 상담방 화면**을 팀장님이 디자인해 주실지, 아니면 저희가 luminous 토큰으로 옮겨 놓고 나중에 다듬어 주실지 정하고 싶습니다. `/rooms`는 지금 고객(민트) 팔레트로 잡히는데, 세무사가 같은 방에 들어오는 화면이라 이게 맞는지도 봐 주세요.
- **데모 아바타 PNG 8장이 장당 약 2MB(합계 약 16MB)**입니다. 저장소와 현장 데모 로딩을 생각해서 WebP나 512px 정도로 줄여 주실 수 있을까요? 원하시면 저희가 변환해도 됩니다.

감사합니다.
