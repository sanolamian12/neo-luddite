# 세무사 승인 취소(세무사 → 회원 강등) 설계

> 작성 2026-10-08 밤. 앞 기록 = `history/261008_관리자_세무사가입승인_사용현황_0049.md`. 출발 프롬프트 = `design/다음세션_프롬프트_세무사_승인취소_강등.md`.
> 진단은 코드 0 · DB 쓰기 0(읽기 전용 트랜잭션 조회)으로 했다. 마이그레이션 번호 예정 = **0050**.

## 0. 진단에서 알게 된 것 (핵심 3개)

1. **역할만 바꾸면 반만 끊긴다.** 권한 판정이 두 종류다.
   - **역할(role) 기준** → `profiles.role='user'` 로 바꾸는 순간 자동으로 끊김:
     원문 열람(`can_staff_read_conversation`), 신청 수락·거절(`transition_consultation`), 제안(`make_offer`), 풀(`list_pool_cases`),
     카드 편집(`expert_profiles_self`), 방 AI 스위치(`set_room_agent_switches`), 에이전트 설정(`expert_agents`), 백엔드 쓰기·세무사 사례 API(`WRITE_ROLES`, 프로필 캐시 60초).
   - **domain_id 기준** → 역할이 바뀌어도 **그대로 남음**:
     채팅방 읽기·**메시지 보내기**(`consultation_rooms_member_read`·`is_room_member`·`consultation_messages_member_insert` — 열린 방이면 강등자가 계속 "세무사"로 글을 쓸 수 있다. 트리거가 `sender_id = expert_id` 면 `sender_role='auditor'` 로 박는다),
     자기 앞 신청·제안 읽기(`consultation_expert_read`·`consultation_offers_expert_read`), 검수 건 CRUD(`audits_owner`), 코멘트·세션평가(0013 owner 정책), 리뷰 읽기·확인표시, 이의(`inquiries_owner`), 원장 읽기.
2. **우편으로는 강등 사실을 못 알린다.** 강등되면 role user 가 되고, 회원 화면에는 일반 우편함이 없다(0049 기록 §3). → 알림은 `/expert/apply` 상태 화면으로.
3. **재신청이 지금은 막혀 있다.** `review_expert_application` 승인은 `auditors` 행이 이미 있으면 `an expert record already exists` 로 실패한다. 강등 후 행을 남기므로(FK) 재승인 경로를 따로 열어야 한다.

부수 발견(탈퇴 경로, 0048/0049): `expert_agents.expert_id` 는 auth.users FK 가 없어 **탈퇴 후 고아 행**이 남고, `kb3.documents.expert_id` 는 `on delete set null` 이라 **공용 승인된 세무사 사례가 작성자 없이 공용 KB 에 남는다**(카드 머리줄에 이름 포함).

- 상담 신청: auditor pending 2 · auditor2 accepted 1 · auditor3 pending 1 / 제안 0 / 방: auditor2 open 1 / 하트 0

## 3. RPC — `revoke_expert(p_domain text, p_reason text)` (0035 방식 단일 전이)

- **admin 만**. 사유 필수(신청자에게 보임). 대상 `profiles.role='auditor'` 이고 `auditors` 행이 있어야 함. 관리자 계정 불가.
- 대상 auditors 행 `for update` 로 잠그고, 위 표 #1~#18 을 **한 트랜잭션**에서 처리. 0047 `guard_profile_identity` 는 호출자가 admin 이라 통과.
- 고객 알림은 기존 헬퍼(`_consultation_mail`·`_offer_mail`·`_room_mail`) 재사용, 고객 1명당 묶지 않고 건별(현재 규모에서 충분).
- 반환: 처리 건수 jsonb(`{requestsDeclined, requestsCompleted, offersWithdrawn, roomsClosed, auditsCancelled, kb3Archived, …}`) → 관리자 화면 결과 토스트.
- 멱등: 이미 revoked 면 오류(`already revoked`).
- 반영 시차: 백엔드 프로필 캐시 60초, 열려 있는 세무사 탭은 다음 토큰 갱신·새로고침까지 /audit 에 남지만 RLS 로 빈 화면·쓰기 실패.

### 재승인 (`review_expert_application` 수정)
- 승인 시 `auditors` 행이 **revoked** 면 오류 대신 재활성(이름·연락처·자격·note 갱신, status active), `expert_profiles` 새로 insert. 원장·검수 이력은 그대로 이어짐. active·suspended 행이면 지금처럼 오류.

## 4. 화면

- **관리자 › 전문가 상세**(`components/admin/auditor-detail-view.tsx`): "승인 취소" 버튼(위험) → Dialog: 영향 미리보기(진행 중 신청·제안·열린 방·draft 검수·사례 수, 읽기 전용 `admin_expert_revoke_preview(domain)`) + 사유 입력 + "취소" 입력 확인 → 결과 건수 표시.
- 전문가 목록: status `revoked` 라벨 "승인 취소", 필터 추가(`AuditorStatus` 타입 확장). revoked 행엔 정지/복구 버튼 없음.
- `/expert/apply`: 최근 신청서가 `revoked` 면 "세무사 승인이 취소되었어요" + 사유 + "다시 신청" (반려 화면 재사용).
- 고객 상담·제안 화면: 상태값이 기존 값(declined·completed·withdrawn·closed)이라 분기 추가 없음. note `expert_revoked` 로 문구만 구분할지는 선택.

## 5. /privacy 영향

- §3 보유: "세무사 승인이 취소되면 신청서는 30일 뒤 파기, 세무사 카드(소개·연락처)는 즉시 삭제" 추가.
- §1/§4: 승인 취소 후에도 **이름은 과거 상담·검수 기록에 남는다**(관리 기록 보존 목적) 한 줄. 새로 받는 항목은 없음(취소 사유는 관리자 작성).
