### 2.2 설계 (`4613f1a`)
- `backend/api/upstage_gate.py` — 프로세스 내 **FIFO 번호표 게이트**. `threading.Semaphore` 는 새치기가 돼 순서 보장이
  안 되므로 Condition + deque. k = `UPSTAGE_MAX_CONCURRENCY`(기본 3, env 로 재배포 없이 조정).
- **단위 = Upstage 호출**. `llm.bounded_client()` 가 `_Gated` 대리를 돌려줘 `.create()` 마다 `slot()` — 호출 지점 14곳 + 임베딩을
  한 자리에서 잡고, 새 호출도 자동으로 줄에 선다. 슬롯은 SDK 재시도까지 감싼다(멈춘 호출은 실제로 Upstage 자리를 쓰고 있다).
- **대기 상한 = 챗 턴 합계**(`turn_budget`, 스레드 로컬 예산). 호출마다 상한을 두면 한 턴이 3~4배를 기다린다.
  예산 없는 스레드(백그라운드)는 무기한 대기.
- 혼잡 예외가 폴백에 삼켜지지 않게 `write_advisory`·`verify_decisive`·retriever 4곳(`_shared_query_vector` 포함) except 앞에서 재발생.
  `/api/chat` 이 받아 `pipeline.congested_response()` — HTTP 200 + "지금 상담 요청이 몰려 답변을 드리지 못했습니다. 잠시 후 같은
  질문을 다시 보내 주세요." + `meta.congested=true`, `rag.chat_turns.outcome='congested'`(outcome 에 check 제약 없음 → 마이그레이션 불요).
  500 이 아닌 이유: 프론트(`services/chat.ts`)는 비정상 status 를 오류로 던진다 — 200 이면 평범한 말풍선.
- `/health` 에 `upstageGate`(capacity·active·waiting·peakWaiting) — 전시 중 줄 길이 확인용.
- 전제: `uvicorn --workers 1`. 워커를 늘리면 k 가 워커 수만큼 곱해진다.

## 3. C — 판정형 날조 수치

### 3.1 측정 (`docs/doing/P8B_측정자료_260918/c_fabricated_numbers.py`)
- 답변 수치 토큰(금액·인원·비율·기간)을 (종류, 값)으로 정규화 — 금액은 원 환산("200만원" = "2,000,000원").
  출처 = 질문 + 엔진 블록 + 주입 근거(P8 A 고정 fixture) + `load_norms()`.
  - known: 출처에 있음 / derived: **사용자·엔진 수**의 종류를 지킨 산술(금액±금액, 금액×비율, 금액÷인원, 인원=금액÷금액, 100−비율) / fab: 둘 다 아님.
- 1차판은 아무 두 수의 사칙연산을 derived 로 봐서 "20명 = 5+15" 같은 우연이 걸렸다 → 종류 제한. 2차판은 근거(남의 사안) 속
  "1인당 10만원"으로 틀린 "20명"이 2,000,000÷100,000 으로 통과 → **피연산자를 사용자·엔진 수로 한정**.
- P8 A 저장 출력(192회) 재채점(호출 0) → 새 생성 192회 → 걸린 문장은 전부 눈으로 확인.

  서로 모순이라 대부분은 틀렸다. **어느 값이 맞는지는 세무사 몫** — 그래서 가드는 값을 고치지 않고 문장을 빼고 확인 안내를 붙인다.

  20만원×20명=4,000,000원으로 계산됨"이라며 사용자 사실을 뒤집었다. P8 A 스모크의 "전 직원 10명"은 산술 추론이었다.
- car: "1,800만원 중 14,400만원(80%)"(단위 오류), "사적 사용분 40%인 7,200,000원", "4,800,000원(18,000,000×20%)" — 산술 오류.

### 3.4 구현 (`eb7636d`)
- `backend/api/numeric_guard.py` `drop_unsourced_numbers(raw, sources, derive_from)` — 출처 없는 수치가 든 세그먼트를 빼고,
  하나라도 뺐으면 "한도·세율·기한 같은 기준 수치는 … 세무사 확인이 필요합니다." caveat 1문장. 다 빠지면 원문 유지.
  문장 단위 제거 이유: 숫자만 지우면 "기본 한도( )와" 같은 깨진 문장이 남는다. 조문 번호·달력 날짜의 '일'은 토큰 아님.
- `pipeline._number_sources()` — sources = 질문·**이전 사용자 발화만**(앞선 답변의 날조를 근거로 되살리지 않게)·엔진 블록·규범·근거,
  derive_from = 질문·사용자 발화·엔진 블록. 판정형·자문 경로 둘 다.
- `_WRITE_SYSTEM` 규칙 5: 판정·근거·규범에 없는 수치(한도액·세율·비율·기한·연도)나 사용자가 말하지 않은 인원·금액 금지.
- 측정 스크립트 정규식은 제품 가드와 동일하게 맞춤(제품 변경 시 같이 고칠 것).
- 한계: 우연히 맞는 틀린 산술은 놓칠 수 있다(피연산자 한정으로 줄임). 출처에 있는 수를 엉뚱하게 쓴 것(혼입)은 대상 아님(P4·P7 지표).
  정당한 법정 수치도 출처에 없으면 빠진다 — 필요한 법정 수치는 **L0 규범(세무사 승인)** 으로 넣는 게 제품 구조상 올바른 길.
