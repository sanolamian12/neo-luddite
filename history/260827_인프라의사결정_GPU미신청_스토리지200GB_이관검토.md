## 1. 현재 시스템 실태 (코드 근거)

- **LLM**: Upstage Solar Pro API 호출뿐, 로컬 GPU 추론 없음 (`backend/api/llm.py`)
- **임베딩**: Upstage `embedding-query`/`embedding-passage` API (4096차원), 로컬 임베딩 모델 없음 (`backend/api/rag/embeddings.py`)
- **벡터스토어**: Supabase Postgres + pgvector, vanilla RAG (`backend/api/rag/store.py`)
- **의존성**: `requirements-api.txt`에 torch/transformers/faiss/vllm 등 GPU 라이브러리 전무
- **배포**: Oracle Cloud E2.1.Micro(x86, Ubuntu 22.04), systemd + Caddy, CPU-only
- **실측 RAM**: 1GB + swap 2GB 보강 — GPU가 아니라 이 RAM이 데모 동시접속의 실질 병목
- **백엔드는 로컬 파일 런타임 의존성 없음** — `backend/api` 전수 검색 결과 CSV/로컬 read 없음, 상태는 전부 Supabase에 있음 → 향후 인프라 이관 시 데이터 마이그레이션 불필요

## 2. GraphRAG / Agentic RAG 고도화 검토

`backend/api/rag/retriever.py`에 향후 확장 인터페이스 경계만 설계돼 있고 구현은 아직 없음.

| 방식 | GPU 필요 여부 |
|---|---|
| Agentic RAG (Upstage API 오케스트레이션 — 쿼리 분해, 재귀 검색, self-critique) | 불필요 |
| GraphRAG (그래프 DB + Upstage 임베딩) | 불필요 |
| 로컬 리랭커 / 로컬 그래프 임베딩 모델 | 있으면 유리 (미계획) |
| 로컬 LLM 파인튜닝 / 로컬 추론 서빙 | 필수 (국내 트랙 100% 조건상 위반 소지 있어 미채택) |

**팀 확정 답변**: 로컬 리랭커·로컬 그래프 임베딩·로컬 LLM 파인튜닝·로컬 추론 서빙 전부 사용 안 함. → 고도화는 API 오케스트레이션 확장 범위 내에서 진행, CPU 인프라로 충분.
