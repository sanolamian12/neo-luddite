# KB3 소스 2 — 국세청 질의회신 본 수집 (2,000건)

- 일자: 2026-09-25 밤 ~ 2026-09-27 01시 (판례 단계 1~3 과 같은 세션)
- 설계 마스터: `design/KB3_요지수집_설계.md` §9 · 다음 세션: `design/다음세션_프롬프트_KB3_RAG적재.md`

## 1. 결과 한 줄

> **국세청 질의회신 2,000건을 받아 정리본 1,995건(요지 + 회신)을 만들었다. 판례에 없던 공제 질문이 여기 있다. 병의원 전용 키워드(한의원·요양급여·치과)는 2018 이후 문서가 거의 없다.**

## 2. 왜 (사용자와 정한 것)

- 판례 본 수집에서 공제 키워드가 판례 요지에 안 나온다는 게 수치로 확인됨 → 사용자: "세무사 계정으로 노가다로 심기 어려워 홈페이지 의존, **가능한 한 풍부하게**" → 질의회신으로 확대.
- 결정 3가지(9/25): **본문 = 요지 + 회신** · **목표 2,000건** · **2018 이후만**.

## 3. 경로 (실측)

law.go.kr `lawSearch.do?target=ntsCgmExpc`(국세청 법령해석 136,535건, 기본 = 제목 검색) → 결과의 `법령해석상세링크`에 `ntstDcmId` 가 바로 있음 → taxlaw `action.do ASIQTB002PR01`(판례와 같은 호출).
law.go.kr 상세(`lawService`)는 OC 키에 **미신청 목록**이라 막혀 있다(팀장 계정에서 신청하면 열릴 수 있음 — 필요 없어서 안 함). 기재부 해석 `moefCgmExpc` 2,330건도 같은 구조(`--source moef_qna`, 미수집).

## 4. 진행

| 실행 | 설정 | 결과 |
|---|---|---|
| 파일럿 | 키워드 4 × 5 | 18건(2018 이후 16), 적중 17/18 |
| 1차 | 51 키워드 × 40, 검색 2쪽 | +1,237 → 1,255. 01~05시 PC 절전으로 정지 → 08:19 재시작 |
| 2차 | × 80, 검색 4쪽 | → 1,811. 16:27 다시 절전 정지 → 20:54 재시작 → 1,911 |
| 재시도 ×2 | 같은 명령 | → 1,982 (raw 2,000 = 상한) |

## 5. 계측 (정리본 1,995)

요지 20자↑ 99.9% · 링크 100% · 세목 99.9% · **키워드 적중 100%** · 회신 100%(중앙 214자) · 관련 법령 98% · 근사중복 170 · 판례 수집본 겹침 0.
세법: 소득세 1,065 · 상증 317 · 법인 201 · 부가 163 · 조특 115. 연도 2020~2025 가 대부분.

## 6. 알게 된 것

1. **판례와 질의회신은 정반대** — 판례는 본문검색이라 잡음(적중 63%), 질의회신은 제목검색이라 적중 100%. 판례는 본문이 첨부, 질의회신은 회신 문장이 본문.
2. **2018 이후로 자르면 얇은 주제**: 한의원 0 · 요양급여 0 · 치과 1 · 의료업·의료기관 3 · 부양가족 4 · 의료비 10. law.go.kr 사본에 최근 질의회신이 적은 건지 원래 적은 건지는 모른다(날짜순 정렬은 확인).
3. **서버 시간대** — 낮 문서당 1~3초, 밤엔 2MB 응답(`trilPsagList`)이 연속 실패. 큰 수집은 낮에.
4. **PC 절전이 최대 적** — 두 번 멈췄고 감시(Monitor)도 같이 멈춰 보고가 빠졌다. 사용자 요청으로 `powercfg /change standby-timeout-ac 0` 적용(원래 60분) — **수집 끝났으니 되돌릴지 사용자 확인 필요**.
5. 감시 오탐 한 번: 재시작하면 raw 파일명 날짜가 바뀌는데 감시가 옛 파일만 셌다 → 전 파일 합산으로 고침.

## 7. 다음

단계 4(제품 세션): 판례 487 + 질의회신 1,995 적재 설계 — 권위 등급 라벨 두 개(법원 / 국세청 해석), 본문(판례 = 요지, 질의회신 = 요지 + 회신), 근사중복 처리, precision 계측 먼저, 프로덕션 DB 쓰기 전 사용자 확인.
