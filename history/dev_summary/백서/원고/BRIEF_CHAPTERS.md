## 쓰는 법
1. 담당 교훈을 전부 읽고 **같은 뿌리끼리 묶어 원칙**으로 만든다. 원칙 하나 = 교훈 1~5개. 게임 편 비율은 교훈 353 → 원칙 180이었다.
2. 원칙을 4~7개의 **절**(`<h2><span class="sec-num">N.k</span> 제목</h2>`)로 나누고 절마다 `sec-intro`.
3. 원칙마다 `<div class="principle"><h3>원칙 문장</h3><p>설명</p>` + 사례 1~3개 `<div class="case"><div class="case-tag">사례 · 주제</div><p><b>무슨 일이</b> … <b>왜 몰랐나</b> … <b>잡은 방법</b> …</p></div>`.
4. 장 머리: `ch-head`(ch-num, h1, ch-sub) → `lead`(이 장이 누구를 위한 것인지, 이 자리의 실수가 왜 그럴듯하게 틀리는지, 교훈 몇 개를 몇 갈래로 묶었는지) → `summary`(이 장의 원칙 전체 목록 ol).
5. 장 끝: `checklist` "작업 전후 점검표" — 질문형 10~15개.
6. 마크업은 견본의 클래스만 쓴다: chapter, ch-head, ch-num, ch-sub, lead, summary, sec-num, sec-intro, principle, case, case-tag, xref, checklist. `<section class="chapter" id="chN">`로 감싼다. 인라인 스타일·스크립트 금지.

## 사례를 쓰는 법
- 배경은 "한 AI 세무 상담 챗봇"이다(장 lead에서 한 번 소개: 사장님이 세무 질문을 하면 LLM이 근거 지식(RAG)을 찾아 답하고, 세무사가 답을 검수해 지식으로 되돌리는 제품. 국내 LLM API 하나로 만들었다). 독자는 이 제품을 모른다고 가정한다.
- **내부 고유명사는 풀어 쓴다**: KB2 → "문장 단위로 다시 쓴 지식 사전", LLM1 → "질문을 받아 사실을 뽑고 되묻는 앞단 모델", L0/L1/L2 → 처음 한 번 설명. 파일명·함수명·마이그레이션 번호·커밋 해시는 이해에 꼭 필요할 때만, 짧게.
- 수치는 원문 그대로 살린다(예: 커버리지 20% → 64%, 72% 기준선, 16/16).
- **감사 데이터 출처**: 검수 코멘트·5점 평가 중 평가자 계정 이름으로 들어간 것은 감사 모드 LLM의 산출물이다. 사람(세무사)의 개입은 승인과 원문·인용 대조뿐이다. "세무사가 캘리브레이션했다"고 쓰지 않는다. 오히려 이 출처를 두 번 오독한 일 자체가 좋은 사례다.
- 비밀값·실명·전화번호·IP 금지. 사람은 직무로 부른다("대표", "1저자").
- 「후일담」(10월 사실)은 원칙을 뒷받침할 때만 한 문장으로.

## 문체
- 한국어 평서 "~다". 짧은 문장, 한 문장에 한 가지. 게임 편 문체를 그대로 따른다.
- 원칙 문장은 명령·원칙형 한 줄(40자 안팎, 길어도 60자).
- 처음 나오는 기술 용어(RAG, 임베딩, RRF, RLS, Realtime 등)는 그 장에서 한 번 풀어 준다.
