## 2. KB 3층 검색 — 로드맵과 P1~P4 (09-16 ~ 09-17)

### 2-1. 진단과 설계 (09-16)
**결과** — PO의 질문은 "세무사가 보는 사전형 KB를 코사인 매칭하면 매칭률이 나쁘지 않겠나"였다. 코드를 보니 한 칸 앞선 사실이 있었다. 그 KB는 프론트 정적 시드라 **검색 경로에 아예 없었다**(품질 기여 0). 적재 함수는 있었지만 호출자가 없었다. 그 위에서 3층 구조를 설계했다.

| 층 | 내용 | 취급 |
|---|---|---|
| L0 규범 | 답변 절차, 해석 원칙, 오류 패턴 | 검색하지 않고 프롬프트에 상시 주입 |
| L1 사전 | 용어집, 판례노트, 직업군 | doc2query 증강 후 검색 |
| L2 경험 | 현행 KB2 | 그대로 |

세 층은 RRF 순위 융합으로 합친다. 권위 서열은 엔진 판정 > L0 > L2 > L1이다. 단계는 P1~P4로 정했다. 같은 날 P1 원본을 "백엔드 md + 로더 경계"로 확정했고, master 시드를 L0로 재분류했다. **코퍼스 확장 6규칙**(계측 먼저 · precision 감시 · 한 번에 한 소스 · 라이선스 · 권위 등급 · 소급 가능)도 이 자리에서 고정됐다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 프로덕트 오너 | 질문 제기, 단계 승인, 불변 원칙(디폴트 rag 유지), (c) 확정 지시, 6규칙 지시 |
| 지식 엔지니어 | 진단(검색 경로 밖, 호출자 없는 적재 함수, 하드 폴백 = 경쟁), 3층·권위 서열·RRF·doc2query 설계 |
| AI 엔지니어 | 평평한 근거 이어 붙이기 → 출처 라벨 분리 필요, `load_norms()` 경계 |

**맞물린 자리** — 결정타는 실측이었다. 규범 시드 전문이 17.4k자로 시스템 프롬프트의 17배라 요약이 필수였다. 요약이 붙는 순간 "빌드 시 JSON 내보내기"의 편익이 사라졌다. 사람이 읽는 해설(프론트 시드)과 AI가 따르는 규범(백엔드 md)을 다른 문서로 선언해 "두 원본" 문제를 없앴다.

### 2-2. P1·P2 — 규범층과 RRF 융합 (09-16)
**결과** — 규범 md 3종(1,314자)이 모든 작문 프롬프트에 들어간다. 판정은 어떤 경우에도 엔진 권위라는 문구도 함께 들어간다. md에 한 줄을 더하자 답변 논지가 따라 바뀌었다('가사' 0 → 5/8). 문안은 Claude가 쓴 초안이라 세무사 검토본 PDF를 보냈고, **"수정 없음, 확정"** 회신을 받았다. `FusionRetriever`(RRF + 쿼터 + 백필)는 `?ragSource=fusion`으로 얹었다. 110문항 4-way 벤치 2회에서 **useful 최고(75.5 / 81.8%), precision 동률**이었다. 같은 날 배포했다.

| 포지션 | 맡은 몫 (결과) |

### 4-2. P8 A — 디폴트 fusion 전환, KB2 합성 오류원, 엔진 증빙
**결과** — **프로덕션 디폴트 검색이 rag 단독에서 fusion으로 바뀌었다(9/18 11:09 KST).** 전제 둘을 먼저 확인했다. fusion의 query 임베딩을 턴당 3회에서 1회로 줄였다(결과 16/16 동일). 한 번도 재지 않았던 판정형 경로에서 혼입·모순을 192회 쟀다(fusion ≤ rag, 통과). 측정 중 곁가지 둘이 나왔다.
- **KB2 오류원**: KB2 문장이 오류로 지적된 [AI 답변]을 그대로 옮겨 적은 경우가 활성 446건 중 최소 30건이었다. 합성 입력에서 그 [AI 답변]을 빼 옮김을 30.9% → 1.1%로 낮췄다(다음 재구조화부터 적용). 법리 오류 1건(1,500만원 한도)은 세무사 확인 후 은퇴시켰고, 31건은 세무사 검토 목록으로 넘겼다.
- **엔진 증빙**: 엔진이 모든 복리후생비(명절 떡값 포함)에 "회원권 명의"를 요구하던 것을 조건부 증빙으로 정정했다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 프로덕트 오너 | 통과선 fusion ≤ rag, 되돌리기 조건, 원칙 갱신("디폴트 전환은 근거로 판정"), 증빙 항목, 은퇴 범위. 세무사에게 오류 공유 |
| 지식 엔지니어 | query 임베딩 공유, 옮김 스캔(하한 30), 은퇴 1건, 검토 목록 31건 |
| AI 엔지니어 | `_synthesis_view`(drop) + 규칙 6·7, 엔진 `rule_복리후생비` 증빙 |
| 백엔드 | 서버 설정 `RAG_SOURCE=fusion` + 재시작(코드 기본값은 rag), 전환 전후 계측 |

**맞물린 자리** — 판정형 측정에서 fusion 쪽 모순 하나가 "kb2의 틀린 문장을 검수 선례로 인용"한 것이었다. 그것을 거슬러 올라가 KB2 합성의 구조적 오류원을 찾았다. 규칙만으로는 모델이 따르지 않아(20%) 입력에서 빼는 쪽을 골랐다. 원래 혼입처럼 보였던 "회원권 명의"는 근거가 아니라 엔진에서 왔다. 근거 코퍼스의 검수 코멘트(감사 모드 Claude 산출물)가 이미 "환각 증빙"으로 지적해 두었던 것이다.

**검증** — 임베딩 16/16, 판정형 192회(걸린 문장 전수 확인), 합성 드라이런 13문서 × 2, 전환 스모크(자문·판정형·되묻기). → [EV](../7_평가검증/EV_2026-09_W07_0913-0919.md). **결정** — "디폴트는 바꾸지 않는다"(9/16)가 뒤집혔다. → [DL](../8_결정교훈/DL_2026-09_W07_0913-0919.md)

「후일담」 10/6 프로덕션 챗은 KB3 단독(`RAG_SOURCE=kb3`)으로 다시 전환됐고, KB2는 범위 밖이 됐다.

### 4-3. P8 B·C — Upstage 큐 게이트, 날조 수치 가드, 세무사 자료
**결과**
- **B 전시 동시 부하**: 프로덕션 동시 N=1~4에서 120초 멈춤은 N=4에서만 나왔다. Upstage 호출 단위 FIFO 게이트(k=3, 챗 턴 대기 합계 30초 초과 시 HTTP 200 혼잡 안내)를 배포했다. **N=4·6·8 216턴에서 멈춤 0 · 오류 0 · 혼잡 0**이었다. 타임아웃 단축은 하지 않았다.
- **C 날조 수치**: 판정형 답변이 접대비 한도를 64회 중 23회 근거 없이, 회차마다 다른 값으로 말했다. 작문 규칙 5 + 출력 가드(`numeric_guard`)로 **날조 수치가 든 답변을 29/192 → 0**, 자문은 11/96 → 0으로 만들었다.
- **복리 카드↔본문**: 카드(전부인정)와 본문("복리후생비가 아닌 급여성 상여", 드물게 "인정되지 않습니다")이 충돌했다. 맞는 쪽인 카드에 맞춰 엔진 근거 문구를 고쳤다(본문 "전액 인정" 명시 21 → 53/64).
- **세무사 확인 대기 3건**: KB2 31건, 복리 문구 법리, 접대비 한도 등 기준 수치를 PDF(읽는 자료) + 엑셀 회신표(답 적는 곳)로 묶었다. KB2 31건 반영(D)은 회신 대기다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 백엔드 | `upstage_gate.py`(Condition + deque 번호표), 호출 14곳 + 임베딩 일괄 게이트, 턴 예산, 혼잡 응답, `/health` 게이트 상태 |
| AI 엔지니어 | `numeric_guard.py`(문장 단위 제거 + caveat), 출처 = 이전 사용자 발화만, 규칙 5, 복리 근거 문구 |
| 프로덕트 오너 | 부하 승인, 대기 30초, 백그라운드도 같은 FIFO, 타임아웃 단축 안 함, 가드는 값을 안 고침, D 대기, 세무사 자료 형식, 인프라 이전 보류 |
| 리서치 | 제품 검토 31건과 KIIS 맹검 표본 30건이 겹치지 않음을 대조로 확인(bigram 최대 0.30) |

**맞물린 자리** — 게이트를 턴이 아니라 Upstage **호출** 단위로 걸어서, 백그라운드 재구조화와 챗이 같은 줄에 선다. 혼잡을 500이 아니라 200으로 돌려준 이유는 프론트에 있다. 프론트가 비정상 status를 오류로 던지기 때문이다. 날조 가드는 값을 고치지 않는다. 정당한 법정 수치가 필요하면 세무사에게 받아 **L0 규범(P6 승인 절차)** 으로 넣는다. 그러면 가드가 자동으로 통과시킨다. 이번 주의 규범층·거버넌스·가드가 한 경로로 이어진 자리다. 세무사 전달본에서는 내부 md의 "세무사 코멘트" 표기를 "검수 코멘트(AI 평가 도구 작성, 참고용)"로 정정했다.

**검증** — 부하 배포 전 124턴·배포 후 216턴, 날조 재채점·재생성 192 + 96회(걸린 문장 전수 확인), 복리 64 + 64회. 멈춤 0이 게이트 효과인지 시간대 차이인지는 분리하지 못했다. → [EV](../7_평가검증/EV_2026-09_W07_0913-0919.md). **전제** — `uvicorn --workers 1`. 워커를 늘리면 k가 곱해진다.
