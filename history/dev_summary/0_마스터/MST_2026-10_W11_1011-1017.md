## 1. R2 근로소득세 계산 갈래 (10-10 ~ 10-12)

**결과** — "연봉 5000인데 내년 소득세 얼마야"가 1턴에 답한다. 답은 결정론 결론, 숫자 없는 Solar 해설, 단계표 5행(줄마다 조문 배지), 가정 문장, 되묻기 질문으로 이루어진다. 계산 함수는 LLM을 쓰지 않는다. 총급여에서 지방소득세까지 조문 순서대로 계산하고, 단계마다 값과 근거 조문을 남긴다. 운영에서 W01~W05(계산 시나리오)가 전부 계산 갈래로 갔다. 상투 답변 0, 경비 판정 6/6을 유지했고, 계산 갈래 평균은 7.5~8.5초였다.

## 2. 세무사 피드백 F0·F1 — 계산 라우팅 · 법령 표 복원 (10-10 밤 ~ 10-12)

**결과** — 10/10 밤에 세무사 피드백(4문항 엑셀)이 왔다. 두 가지가 드러났다.
- **법령 DB에 표가 통째로 없었다.** 법제처 PDF의 표는 이미지라서 텍스트 추출에서 빠졌다(약 276조). LLM3가 소득세법 §55를 맞게 골라도 작문이 숫자를 쓸 수 없었다. 재현에서는 "현행 조문에는 세율표가 포함되어 있지 않다"는 틀린 말까지 했다.
- **계산이 안 나온 것은 회귀였다.** 앞서 프리랜서 질문을 막으려고 '종합소득세'를 비근로 신호로 넣었는데, 근로자도 "제 종합소득세는 얼마인가요?"라고 묻는다.

F0(라우팅 핫픽스)은 즉시, F1(표 복원)은 R3 앞에 했다. F1은 국가법령정보센터 Open API 원문의 상자 문자 표를 **232조·표 396개**에 복원했다. 운영에서 종합소득세율 8구간, 법인세율 호별 2표, 증여세율 5구간이 정확하게 나왔고, 날조 문서번호는 0이었다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 프로덕트 오너 | 피드백 대응을 **전부 추천안**으로 정했다. Q3·Q4(요건 넘버링·법령 우선 서열)는 R4 재정의로 흡수하고, 재평가는 F0+F1 뒤에 받는다. 재평가 요청 문서를 보냈다 |
| AI 엔지니어 | F0 — 라우팅은 세금 낱말과 계산 낱말이 함께 있을 때, 판단은 이번 발화로. 추출 이력 압축과 타임아웃 시 빈 추출. 근거에 없는 문서번호 인용 문장을 결정론으로 지우고 프롬프트 예시를 뺐다 |
| 지식 엔지니어 | F1 — `law_tables_api.py`로 같은 판 또는 같은 본문 조문에만 표 복원. 표 행은 결정론 세그먼트로 내고, 세율 질문은 '세율' 조문을 직접 보강한다 |

**맞물린 자리** — 세무사가 한 대화에 세목이 다른 4문항을 이어 물었다. 이것이 "대화 전체를 훑는 라우팅은 앞 질문 낱말이 뒤 질문을 막는다"는 것을 드러냈다. F0 뒤 X05(4문항 연속)에서 Q2는 계산, Q4는 자문으로 갔다. 표 복원은 쟁점 한 줄(gists)의 키를 옮겨 Solar 재생성 없이 끝냈다. 임베딩은 바뀐 215건만 다시 만들었다.

**검증** — F0 뒤 2회 52/52 실패 0. → [EV](../7_평가검증/EV_2026-10_W11_1011-1017.md). **교훈** — 표는 PDF가 아니라 API 원문에서 가져온다. 세목 이름을 라우팅 신호로 쓰지 않는다. 프롬프트 예시는 그대로 인용된다. → [DL](../8_결정교훈/DL_2026-10_W11_1011-1017.md). **남은 것** — 판과 본문이 달라 건너뛴 126조(우리 PDF가 구판).

## 3. Supabase egress 대응 · KB2 삭제 (10-12)

**결과** — Supabase egress가 293%(14.63/5GB)였다. 원인은 `vec_memory`였다. 재시작마다 4096차원 벡터 전량(법령 7,613 + KB3 5,101행)을 텍스트로 받아 1회 674MB가 나갔다. 배포 restart와 로컬 uvicorn이 원인이었고, **이 로드맵 세션의 로컬 서버도** 원인 제공자였다. 기동 적재를 지문 한 줄 + 서버 디스크 캐시로 바꿨다. 첫 기동 뒤 재시작은 전부 `cache 0.1초`(적재 12초 → 1.4초)가 됐다. 같은 날 KB2 스키마를 지웠다. DB는 421.6 → 336.8MB가 됐다.

| 포지션 | 맡은 몫 (결과) |
|---|---|
| 프로덕트 오너 | 별도 진단 세션의 처방을 이 세션에 끼워 넣었다. 순서는 F1 적재 먼저 → 배포 1회로 캐시 생성. **"kb2 날려버리자"** |
| 백엔드 | `api/rag/disk_cache.py`(지문 = 행 수·max updated_at·md5, 바이너리 커서, 원자적 기록) · 0052(`cron.job_run_details` 15.7만 → 1.2만 행 + 매일 정리) · `egress_audit.py` · `kb2_enabled()`로 kb2 API 23개·폴러·합성 차단 → 0053 `drop schema kb2 cascade` |
| 지식 엔지니어 | kb2 밖 의존 0 확인(뷰·FK·함수·트리거·cron·Realtime), 텍스트 백업(임베딩 제외 5.66MB) |

**맞물린 자리** — PO가 정한 순서(F1 표 적재 → 배포 1회)가 캐시 생성 시점과 맞물렸다. 표를 먼저 넣어야 지문이 한 번만 바뀌고 캐시를 한 번만 만든다. KB2는 10월 초 KB3 단독 전환(W10) 뒤로 쓰이지 않던 층이다.

**검증** — 재시작 3회 연속 `cache 0.1초`. **남은 것** — 다음 날 일별 egress 확인, `vacuum full`(사용자), `rag.passages` 전량 조회 427회(21만 행)의 경로.

## 4. R3 세무사 즉시 연결 · 팀장 프로토타입 병합 (10-12)

**결과** — 진단해 보니 live에서 비로그인 고객은 세무사 목록조차 볼 수 없었다. 로그인해도 신청 → 세무사 수락 → 상담 목록 → 채팅방 열기의 5단계였고, 세무사 AI의 첫 인사도 없었다. 이를 이렇게 바꿨다. 비로그인으로 질문 → 세무사 카드 → 가상 세무사 선택 → 간편 로그인 → 복귀 2초 → 방 2초 → 전환 장면 → 세무사 AI 첫 인사 3초. 로그인한 사장님은 1초에 연결된다. 고객 메시지에 세무사 AI가 9초에 답했고, 콘솔 오류는 0이었다.

|---|---|
| 프로덕트 오너 | R3-1 **선택 시 간편 로그인**(비로그인 그대로 방 연결은 RLS 전면 공사라 제외). R3-2 **즉시 연결은 데모용 가상 세무사만**(실제 세무사는 신청 → 수락 그대로) |

**교훈** — e2e가 RPC를 모킹해서 "비로그인은 목록을 못 본다"가 드러나지 않았다. → [DL](../8_결정교훈/DL_2026-10_W11_1011-1017.md)

## 5. A1 Solar Pro 4 운영 전환 (10-13)

**결과** — 결과보고서에 "Solar Pro 4로 운영"을 약속했고, Pro 3은 10/30에 종료된다. 두 모델 모두 `reasoning_effort`를 생략하면 추론이 꺼지므로 모델명만 바꾸면 됐다. 그대로 올리자 p50 9.9초로 미달했다. 작문은 Pro 4가 짧게 써서(출력 560 → 430토큰) 비슷했다. 늘어난 것은 **추출**이었다. Pro 4는 자동 호출에서 도구를 부르지 않고 산문을 써서, 강제 재호출이 겹쳤다. 이력 있는 턴은 자동 호출을 건너뛰고 곧바로 강제 호출로 가게 해서 **p50 7.7·p90 12.1초**가 됐다.

## 8. E 복합 사안 골격 · 쟁점 조문 · B 비교표 (10-15)

**결과** — 세무사가 10/14에 보낸 캡처(비상장주식을 아들에게 저가양도) 같은, 세금이 둘 이상 걸린 사례 질문에 계산기 없이 골격으로 답한다. 골격은 결론 문단(누가 어떤 세금, 조문 번호 없이) → `가정:` → `■ 세목(납세자)` → `■ 확인할 점` → (근거 있을 때만) `■ 검토할 대안`이다. 금액을 물으면 "세액은 세무사 확인" 문장을 코드로 붙인다. 이 일은 보고서에 쓰지 않은 시연 전용 항목(장부 P11)이다.

- **쟁점별 조문** — 복합 갈래에서 LLM3는 쟁점 조문(§101·§35)만 고르고 세율·공제·신고기한 조문은 한 번도 고르지 않았다. 질문 글에서 쟁점을 판별해 조문 키를 결정론으로 싣는다.
- **비교표(B①)** — "Markdown 표로 써라"는 규칙은 운영 2회 모두 무시됐다. 작문 도구에 `compare` 구조 칸을 필수로 주고 코드가 표를 조립하게 했다. 비교표가 g5에서 4/4 턴 나왔다(e1 0/4).

g1의 A3 17/20에서 시작해 g5 2회 162턴에서 **미달 0**이 됐다(p50 7.8·p90 12.6초).
