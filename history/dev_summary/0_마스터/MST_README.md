# 0. 마스터

## 개요

**한 주에 어떤 기능이 나왔고, 그 기능에 포지션들이 어떻게 맞물렸는지를 보는 곳이다.**
포지션 폴더(1~8)가 "누가 무엇을 했나"를 보여 준다면, 마스터는 같은 한 주를 **개발 주제(기능) 축**으로 다시 엮는다.
기능 하나는 보통 여러 사람의 손을 지난다. 이 제품에서는 대개 이렇게 흐른다.
1. PO가 정책과 범위를 정한다.
2. KE가 지식의 모양을 정한다.
3. AIE가 LLM에게 맡길 몫을 정한다.
4. BE가 스키마·배치·배포를 붙인다.
5. FE가 세무사와 관리자의 화면을 만든다.
6. RS가 그 결과를 실험으로 잰다.

그 흐름과 이음매를 한눈에 보면서 **팀을 조직하고 일을 배분하는(오케스트레이션) 관점**으로 쓰기 위한 폴더다.

**상세가 아니라 결과를 적는다.** 무엇이 가능해졌나, 무엇이 확정됐나, 무엇이 남았나.
구현 상세와 지뢰 이야기는 각 주제 끝의 링크를 따라 포지션 문서로 내려가서 본다.

## 주간 문서 읽는 법

| 절 | 내용 |
|---|---|
| **이번 주 한 줄** | 이 주의 성격 |
| **한눈에 — 주제 × 포지션** | 주제마다 누가 참여했나(● 주도·핵심 / ○ 보조), 결과, 상태 |
| **주제별 절** | 결과 → 포지션별 맡은 몫 → **맞물린 자리**(누가 넘기고 누가 받았나, 어디서 어긋났다 맞췄나) → 검증·결정·남은 것 → 포지션 문서 링크 |
| **그 밖에** | 주제로 묶기에 작은 단독 작업 |
| **다음 주로 넘어간 것** | 이 주 끝에 열려 있던 일 |

포지션 약자: `PO` 프로덕트 오너 · `AIE` AI 엔지니어 · `KE` 지식 엔지니어 · `BE` 백엔드·인프라 · `FE` 프론트엔드 · `RS` 리서치
(평가검증·결정교훈은 열이 아니라 각 주제의 "검증" "결정" 줄로 들어간다.)

## 월간 업무

### 2026년 8월 (W04~W05)

> **RAG가 "세무사가 들여다보고 고칠 수 있는 것"이 된 달.** 원문 기록은 8/27에 다시 시작한다(7/29 이후 공백이라 W01~W03은 비어 있다).
> KB가 평면 벡터 리스트라는 실체를 확인한 뒤, 중복을 걷어 내고, 세목을 붙이고, 거미줄 그래프로 그렸다. 수정 제안·기여·정산 규칙이 원화 기준으로 굳었다.
> 둘째 주에는 기능 없이 운영 DB를 정리하며 "논문 데이터"라는 기억을 바로잡았다.

### 2026년 9월 (W06~W09)

> **지식의 모양을 세 번 바꾸고, 사람과 사람을 앱 안에서 잇고, LLM에게 맡길 몫을 줄인 달.**
> KB2(문장 단위 사전)를 만들어 커버리지를 20 → 64%로 끌어올리고 일단락했다. 이어서 이미 있는 지식을 L0 규범 / L1 사전 / L2 KB2의 3층으로 갈라 프로덕션 디폴트를 fusion으로 바꿨다.
> 셋째 주에는 사장님과 세무사의 상담 연결을 앱 안으로 들였고, 백엔드를 12GB ARM으로 옮겼다. LLM1은 "72%를 넘은 회차 없음"을 근거로 역할을 줄였다.
> 마지막 주에는 밖에서 모은 국세청 질의회신(KB3)이 "답할 수 있는 범위"를 넓힌다는 것을 숫자로 확인했다. 그 사이 ICTC 카메라레디와 KIIS 요약문을 냈다.
