# 5. 프론트엔드 엔지니어

## 개요

**사장님·세무사·관리자 세 사용자의 화면이 실제로 움직이게 하는 사람이다.**
Next.js(App Router) + Supabase 클라이언트 + Realtime이다. 이 제품은 사용자 종류마다 화면 세계가 다르다.
- 사장님: 챗, 상담 연결
- 세무사: 검수실, 지식망, 프로필
- 관리자: 정산, 중복 정리, 수정 제안 승인, 상담 운영

검수 데이터 서비스(`frontend/services/*.ts`)의 상당 부분이 프론트에 있어서, 정산 같은 운영 로직도 이 자리를 지난다.

## 역할

| 축 | 하는 일 |
|---|---|
| **화면 기능** | 검수실, 지식망(클러스터·그래프·상세), 수정 제안, 정산, 상담 채팅, 프로필을 만든다 |
| **실시간** | Realtime 구독 순서, 준비 대기, 채널 수, 가시성 변화 대응을 맡는다 |
| **시각화** | d3-force 그래프, 방사형 이웃, 타임라인, 클러스터 색을 맡는다 |
| **UX 다듬기** | 실사용 피드백에 반응해 그때그때 고치고 배포한다 |

## 다루는 것

- `frontend/components/{audit,admin,auditor}/` · `frontend/app/`
- `frontend/services/*.ts` — Supabase 데이터 서비스(정산·ledger·conversation 등)
- `frontend/lib/` — 공용 모듈(예: `kb-cluster-colors.ts`)

## 다른 포지션과의 계약

- **← 지식 엔지니어**: 백엔드가 저장하는 **실제 값**(예: `"미분류"`)을 그대로 쓴다. 플레이스홀더 상수를 따로 만들면 문자열이 어긋난다.
- **← 백엔드**: 새 응답 필드는 Zod 스키마부터 맞춘다.
- **→ 프로덕트 오너**: 화면을 바꿀 때마다 배포해서 직접 써 볼 수 있게 한다.

## 이 자리에 필요한 역량

"그려졌는데 안 보인다"와 "이벤트가 안 온다"를 층별로 좁히는 습관. Realtime의 SUBSCRIBED가 곧 수신 시작은 아니라는 것을 아는 정도.
