# 결정 · 교훈 — W13 · 2026-10-25 ~ 10-31

> **이번 주 요지** — 결정은 **"표와 원문을 먼저 보고 범위를 정한다"** 로 모였다. 증여 계산 갈래는 라우팅 표를 보고 한 문항(S03)만 보냈다. 근거 식이 DB 원문에 없는 자리(조부모 + 합산)는 계산하지 않았다. 식이 이미지로만 있던 자리(§159)는 API 원문에서 복원했다. 부담부증여는 빼지 않고 계산에 넣었다. 지연 쪽은 **켜 놓고 지켜보다가, 해가 보이면 좁히고, 시연에는 끈다**는 단계로 갔다. 지뢰는 **"조건이 바뀌면 거꾸로 도는 것"** 이었다. 혼자 쓸 때 빨라지는 미리 시작이 동시 접속에서는 느려졌고, 주식에서 맞던 '께' 규칙이 증여에서는 방향을 뒤집었고, 배포 안 된 서버를 새 코드로 잰 줄 알았다.

## 결정

### 11/2까지 기능·성능을 최대로, 순서 ①③⑤④② (10-26, PO 확정)
- **무엇을**: ① 전 지표 재측정 → ③ E 확장 → ⑤ 관리자 사용 현황 → ④ 부하 재확인 → ② R6(팀 몫, 가장 나중).
- **기한**: 11/2. 시연(11/3~5) 예정 바로 앞이다.

### 증여는 S03만 계산 갈래로 (10-26, PO 확정)
- **무엇을**: 평가 세트 증여 질문의 라우팅 표를 먼저 보고, 세액 물음에 '내야'가 있는 S03(결혼 자금 1억)만 `gift_calc`로 보낸다. 혼인·출산 공제(§53의2)를 넣고, 이어서 10년 합산(§47② + §58)까지 넣는다.
- **종전대로 두는 것**: 한도 질문(S01·X07·D06), 제외 낱말(차용·무상 거주·명의 통장), '10년 한도'(C28). 주식 + 양도는 주식 갈래가 먼저다.

### 조부모 증여 + 10년 합산은 계산하지 않는다 (10-26, 구현 판단)
- **왜**: 근거인 시행령 §46의3②(세대생략 + 합산 할증 계산식)의 수식이 DB 원문에 없다.

### 부담부증여는 게이트에서 빼지 않고 계산에 넣는다 (10-26, PO 확정)
- **무엇을**: 증여세(수증자 인수 채무 공제) + **조건부** 양도세(증여자). 혼인 공제 §53의2⑤⑥ 확인 문장도 넣는다.
- **왜**: '전세 3억 낀 시가 10억 아파트' 증여가 채무를 빼지 않고 2억1,825만으로 과대 계산됐다.
- **기각**: 게이트에서 제외(권고였다).

### §159 계산식은 API 원문에서 복원한다 (10-26, PO 확정)
- **무엇을**: DB 원문에 없던 시행령 §159① 식을 법령 API 캐시의 상자 문자에서 `X = A × B ÷ C` 꼴로 복원해 적재한다. 공포번호는 달라도(36343 / 36737) 조문 본문이 같음을 확인했다.

### 첫 턴 미리 시작을 운영에서 켠다 (10-27, 구현 판단)
- **무엇을**: c19c13a, `LAW_PREFETCH=on`. 첫 턴만, 같은 검색어일 때만 결과를 쓰고, 실패하면 종전대로, 게이트가 붐비면 시작하지 않는다.
- **왜**: 시민 48 off/on 교대에서 p50 10.7 → 9.2초, p90 13.9 → 12.5초. 자료 없음·DB 밖·오류는 그대로였다.
- **조건**: 근거 배지 총수가 약간 낮았다. 다음 전체 회귀의 출처 표시율이 떨어지면 끈다.

### 미리 시작은 혼자 도는 턴일 때만 (10-28, 구현 판단)
- **무엇을**: b8509a9. 진행 중 턴 수 > 1이거나 게이트 사용 중 1+ / 대기 있음이면 건너뛴다.
- **왜**: 동시 8에서 켬이 끔보다 +8.5초 느렸다. 동시 첫 질문이 게이트를 비어 보이게 해서 모두 통과했다.
- **그동안**: `LAW_PREFETCH=on` 유지. 다음 날 같은 시간대에 끔·켬을 번갈아 새 조건을 판정하고, 켬이 여전히 느리면 시연 기간 off.

### 평소 on, 시연 11/3~5는 off (10-29, 구현 판단 — 권고)
- **무엇을**: 시연 기간에는 환경 변수 값을 off로 바꾸고 재시작한다.
- **왜**: ABBA 4회에서 켬 평균 22.6 / 끔 20.3초. 차이는 줄었지만 켬 A의 꼬리(p90 44초, 혼잡 1)가 남았다. 4회로는 흔들림과 갈리지 않는다. 시연에는 동시 접속 안정이 먼저다.

### 대문은 첫 화면과 서비스 소개만 가져온다 (10-27 미팅, PO 확정)
- **무엇을**: 팀장 프로토타입에서 첫 화면 + `/about`만. 발표·영상 커밋은 가져오지 않는다. 바닥글의 개인정보처리방침 링크는 본체 것을 남긴다.

## 교훈 — 밟은 지뢰

### 혼자일 때 빨라지는 것이 여럿일 때는 느려진다 — 미리 시작 (10-28)
- **무슨 일**: 미리 시작을 켠 뒤 부하 시험에서 동시 8 p50이 26.6초였다. 끈 상태는 18.1초였다.
- **왜 조용했나**: 효과는 시민 48 off/on 교대로 쟀고, 동시 부하는 그 뒤 ④에서 따로 쟀다. 게이트가 붐비면 시작하지 않는 안전장치도 있었다. 그런데 8명이 **동시에** 첫 질문을 보내는 순간에는 게이트가 아직 비어 보여서 안전장치를 모두 통과했다.
- **어떻게 잡았나**: ④ 부하 재확인을 순서에 넣어 두었고, 켬·끔을 같은 날 번갈아 쟀다.
- **이제의 규칙**: 지연을 줄이는 기능은 **단독 측정과 동시 부하를 둘 다** 본다. 동시성 판단은 "지금 게이트가 비었나"가 아니라 "지금 도는 턴이 몇 개인가"로 한다. 그래도 맨 처음 한 턴은 '혼자'로 보인다는 것을 알고 쓴다.

### 배포 안 된 서버를 새 코드로 쟀다 (10-28)
- **무슨 일**: 세 번째 부하 회(1028on2)를 새 조건 코드로 잰 줄 알았지만 서버는 여전히 c19c13a였다.
- **왜 조용했나**: `/health`에는 커밋이 없다. 응답은 정상이었다.
- **어떻게 잡았나**: 원문은 그 회를 "새 코드인 줄 알았으나 배포 안 됨"으로 정정했다(p50 23.8, 혼잡 3). 고친 코드는 02:5x UTC 이후에 배포됐다.
- **이제의 규칙**: 잴 때마다 서버의 `git log --oneline -1`과 서비스 시작 시각을 먼저 찍는다.

### 같은 조사가 갈래마다 다른 방향을 가리킨다 — '께' (10-26)
- **무슨 일**: 'X께 … 받'에서 X는 **주는 사람**이다. 주식 추출의 "'께' = 받는 사람" 규칙을 그대로 쓰면 증여의 방향이 뒤집힌다.
- **왜 조용했나**: 주식 갈래에서는 그 규칙이 맞았다.
- **이제의 규칙**: 추출 규칙을 다른 세목으로 옮길 때는 **그 세목의 문장 꼴**로 다시 시험한다. 증여는 주는 분의 이야기라 높임 꼴('사셨')이 많다. 주식의 `_HOLD_Y`·`_ACQ`('샀·산'만)도 그대로 못 쓴다.

### 단위 없는 수를 금액으로 읽는다 (10-26)
- **무슨 일**: `parse_amount`가 '10년', '17살'을 만원으로 읽었다.
- **이제의 규칙**: 단위가 있는 것만 금액이다.

### 계산 갈래를 켜자 과대 금액이 나왔다 — 부담부증여 (10-26)
- **무슨 일**: 일반 증여세 배포 뒤 '전세 3억 낀 10억 아파트' 증여가 2억1,825만으로 나왔다. 채무를 빼지 않았다.
- **왜 조용했나**: 일반 증여세 회귀(G1~G10·GM1~GM3)의 기대값은 모두 맞았다.
- **어떻게 잡았나**: 운영 배포 뒤 결함으로 드러났다.
- **이제의 규칙**: 계산 갈래를 켤 때는 **그 갈래로 들어올 수 있지만 모형에 없는 사안**(채무, 세대생략 등)을 먼저 적는다. 모형에 넣거나(부담부증여), 넣지 않는다고 답에 밝힌다(`NOT_MODELED_BURDEN`).

### 지연이 오르면 토큰과 속도를 먼저 나눈다 (10-26)
- **무슨 일**: 재측정 p50이 10.3초로 경고였다.
- **어떻게 잡았나**: 서버의 Upstage 호출 로그에서 토큰 수(그대로)와 생성 속도(84 → 67~73 tok/s)를 나눠 봤다.
- **이제의 규칙**: 토큰이 같고 속도가 떨어졌으면 공급자 쪽이다. 그때 줄일 수 있는 것은 호출 순서(겹치기)다.

### 기준 회차가 예외일 수 있다 — E01 (10-26)
- **무슨 일**: 부담부증여 스모크의 E01이 기준 회차와 달랐다.
- **어떻게 잡았나**: 10/19 이후 14회차를 겹쳐 보니 기준 회차가 뒤바뀐 예외였다.
- **이제의 규칙**: 스모크 차이는 **기준 한 회와만** 비교하지 말고 지난 회차들의 분포와 비교한다.

### 작은 것들 (10-26 ~ 10-28)
- 결과 파일 이름의 시각은 PC 시간대(UTC+11)다. 서버 로그(UTC)와 맞출 때 11시간을 뺀다.
- 작업 폴더의 .py는 CRLF(autocrlf)다. 파이썬으로 고칠 때는 `newline=""`로 읽고 쓴다(정규식 안 `\n`이 실제 줄바꿈이 된 일이 있었다).
- 서버 원격 명령은 한 줄로 보낸다. 줄을 나누면 뒷줄이 PC에서 실행된다.
- ingest는 jsonl 전부와 DB를 비교한다. 다른 날 복원분(조특법 2행)이 같이 들어갈 수 있다(이번엔 무해).
- 미리 시작 테스트는 스레드가 끝나길 기다려야 다음 테스트의 가짜 함수를 건드리지 않는다.
- 예시 글자(placeholder)가 입력값처럼 보이면 저장 버튼이 왜 꺼졌는지 모른다. 예시 앞에 '예:'.
- E2E로 만든 방문은 실제 집계에 남는다. 본선 데이터에서 빼려면 그 브라우저를 집계 제외로 둔다.
- `.next`에 지운 라우트의 옛 타입이 남으면 type check가 실패한다. `.next`를 지우고 빌드하되 dev가 꺼져 있을 때만.
