> **이번 주 요지** — 결정은 두 방향으로 모였다. PO 쪽은 **범위를 좁히는 결정**이었다. 텍스트 단계표, 간편 로그인, 가상 세무사만 즉시 연결, KB2 삭제, A6 현행 문구 유지가 그렇다. 구현 쪽은 9월부터 이어진 **"모델에게 부탁하지 않고 코드로 조립한다"** 를 끝까지 밀었다. 계산은 LLM 0, 표 행과 요건 목록과 쟁점 조문과 비교표는 결정론이고, 작문에는 숫자도 조문 번호도 맡기지 않는 자리가 늘었다. 지뢰는 세 종류였다. 첫째, **데이터에 없는 것을 모델이 지어낸 것**이다(표가 이미지라 빠진 법령, 프롬프트 예시가 날조 인용으로). 둘째, **가드나 측정이 엉뚱하게 작동한 것**이다(4천800만원 오독, 「」를 못 세는 정규식, 걸리면 원문을 돌려주는 가드). 셋째, **로컬이 운영 DB를 나눠 써서 생긴 것**이다(egress, 세션 풀, 법령 저장소).

## 교훈 — 밟은 지뢰

### 법령 DB에 표가 통째로 없었다 (10-10 밤 발견)
- **무슨 일**: 법제처 PDF의 표는 이미지라 텍스트 추출에서 빠졌다(약 276조). 소득세법 §47①·§55①·§59① 등. LLM3가 §55를 맞게 골라도 작문이 숫자를 못 썼고, "현행 조문에는 세율표가 포함되어 있지 않다"는 틀린 말까지 했다.
- **왜 조용했나**: 조문은 골라졌고 본문 글자도 있었다. 빠진 것이 이미지였으니 텍스트 검사로는 보이지 않았다.
- **어떻게 잡았나**: 세무사 Q1. 같은 조문이 Open API 본문에는 상자 문자 표로 있었다.
- **이제의 규칙**: 법령 표는 **API 원문**에서 가져온다. PDF는 표가 이미지다. 표가 바뀌면 apply → embed → ingest → 재시작 1회. 그리고 이 주 끝에 목 단위 표 44개가 또 빠져 있던 것을 찾았다. 표 복원은 한 번에 끝났다고 보지 않는다.

### 세목 이름을 라우팅 신호로 썼다 — 내 회귀 (10-10 밤 발견)
- **무슨 일**: 프리랜서 질문이 계산 갈래로 새는 것(G01)을 막으려고 '종합소득세'를 비근로 신호로 넣었다. 근로자도 "제 종합소득세는 얼마인가요?"라고 묻는다. 세무사 Q2에서 계산이 안 나왔다.
- **왜 조용했나**: 원문은 운영 측정에서 이 회귀가 왜 안 보였는지 적지 않았다. 세무사가 관용적 표현으로 묻자 드러났다.
- **어떻게 잡았나**: 세무사 피드백. 계산 함수 자체는 맞았다(3,148,750원).
- **이제의 규칙**: 세목 이름을 비근로 신호로 쓰지 않는다. 판단은 **이번 발화**로 한다(짧은 답이면 직전 발화까지). 대화 전체를 훑으면 앞 질문 낱말이 뒤 질문을 막는다.

### 프롬프트 예시가 그대로 인용됐다 (10-11 ~ 10-12)
- **무슨 일**: LAW_RULES의 "사례는 문서번호(예: 조심 2024서0560, 서면-2022-원천-4266)로만" 예시를 Solar가 증여세율 답에 실제 사례처럼 옮겨 적었다.
- **왜 조용했나**: 실제 문서번호 형식이라 사람이 봐도 그럴듯했다.
- **어떻게 잡았나**: 진단 중 증여세율 답에서.
- **이제의 규칙**: 프롬프트 예시에 실제처럼 보이는 문서번호·수치를 넣지 않는다. 근거에 없는 문서번호 인용 문장은 결정론으로 지운다.

### 재시작마다 674MB — egress 293% (10-12)
- **무슨 일**: `vec_memory`가 재시작마다 4096차원 벡터 전량을 텍스트로 받았다. 배포 restart와 로컬 uvicorn이 원인이었고, 이 로드맵 세션의 로컬 서버도 원인이었다.
- **왜 조용했나**: 기능은 정상이었다. 비용 화면을 열기 전까지 아무것도 보이지 않았다. `LAW_STORE=file`로 띄우면 운영 DB를 안 쓴다고 생각했지만 vec_memory는 따로 운영 DB에서 받았다.
- **어떻게 잡았나**: egress 293%를 두고 별도 진단 세션이 원인을 찾았다.
- **이제의 규칙**: 로컬 백엔드는 `VEC_MEMORY=off`로만. 배포는 모아서.

### 비로그인은 세무사 목록조차 못 봤다 — 모킹한 e2e (10-12)
- **무슨 일**: `list_experts`가 authenticated 전용 + `me.id is not null` 필터라 live의 비로그인 고객은 목록을 볼 수 없었다.
- **왜 조용했나**: e2e(`entry-response.spec.ts`)가 RPC를 모킹했다. 시험은 통과하고 운영은 막혀 있었다.
- **어떻게 잡았나**: R3 진단에서 live 흐름을 직접 따라갔다.
- **이제의 규칙**: 권한이 걸린 RPC는 모킹 없는 운영 E2E로 한 번은 본다.

### 테스트가 실패했는데 배포·커밋이 나갔다 (10-12)
- **무슨 일**: 테스트 체인을 `cmd; tail`로 이어서, 테스트 1개가 실패해도 다음 단계가 돌았다.
- **왜 조용했나**: `tail`의 종료 코드가 성공이라 체인 전체가 성공으로 보였다. 로직은 정상이고 기대값이 오기라 운영 피해는 없었다.
- **이제의 규칙**: 실패가 멈춰야 하는 체인은 `;`로 잇지 않는다.

### Pro 4는 자동 호출에서 도구를 부르지 않는다 (10-13)
- **무슨 일**: 모델명만 바꿨는데 p50이 7.2 → 9.9초. 작문은 짧아졌는데 추출이 길어졌다. 첫 턴 12/41, 이력 턴 14/16이 도구 대신 산문을 쓰고, 강제 재호출이 겹쳤다.
- **왜 조용했나**: 결과값은 같았다(강제 재호출이 채웠다). 기능 스모크는 "동등"이었다.
- **어떻게 잡았나**: 함수별 지연과 출력 토큰을 갈라 봤다.
- **이제의 규칙**: 모델을 바꾸면 기능 동등과 별개로 **함수별 지연**을 잰다. 규칙 문장으로 고쳐지지 않으면 호출 경로를 바꾼다.

### 측정 정규식이 「」를 못 셌다 (10-13)
- **무슨 일**: A4 실패 15턴 중 7턴은 측정 정규식이 「」 법령 이름을 못 센 것이었다.
- **왜 조용했나**: 실패율이 그럴듯한 크기였다. 답이 틀렸다고 읽기 쉬웠다.
- **어떻게 잡았나**: 실패 턴을 갈래별로 하나씩 분해했다.
- **이제의 규칙**: 지표가 나쁘면 답보다 **측정부터** 연다. 정규식을 고치면 옛 값을 병기한다.

### enum 값은 출력 토큰이다 (10-13 밤)
- **무슨 일**: 유형 분류를 잘 시키려고 enum 값에 긴 풀이(~20토큰)를 달았더니 추출 p50이 1.22 → 1.52초.
- **왜 조용했나**: 같은 시각에 모든 갈래가 ×1.2~1.4로 느려져서(시간대) 그 안에 묻혔다.
- **어떻게 잡았나**: 같은 시간대에 추출만 A/B.
- **이제의 규칙**: enum 값은 모델이 그대로 써서 돌려주는 글이다. 짧게 두고, 받은 뒤 코드로 정규화한다.

### p50은 쌍봉 분포의 틈에 걸린다 (10-13)
- **무슨 일**: 빠른 갈래 약 4초, 자문 약 10초. 거절되던 턴이 자문으로 옮기기만 해도 p50이 올랐다. 코드를 안 바꾼 함수도 시간대에 따라 ±12~30% 움직였고, h1에서는 전 함수가 1.6~2.3배 느렸다.
- **이제의 규칙**: 지연 미달이 나오면 journald 함수별로 **코드 무변경 함수부터** 본다. 그것도 느리면 시간대다.

### 셸 heredoc으로 소스를 고치면 글자가 바뀐다 (10-13, 10-15)
- **무슨 일**: 파이썬으로 정규식 `\b`·`\1`을 넣다가 제어문자(백스페이스·\x01)가 소스에 박혔다. 이틀 뒤에는 `\n`이 실제 줄바꿈이 됐다.
- **이제의 규칙**: 정규식과 이스케이프가 있는 소스는 Edit 도구로 고친다.

### 우리 규칙이 결론을 막고 있었다 (10-14)
- **무슨 일**: 세무사 2차 회신 Q3 2/2/2 "오히려 퇴보". 법령만 판 시스템 규칙 1("사안이 요건을 채운다고 단정 말 것")이 '제조업 = 배제 업종' 같은 조문 그대로의 결론까지 막았다. 긴 대화에서는 앞선 답 모양을 따랐다.
- **왜 조용했나**: 단정을 피하는 규칙은 안전해 보였다. 자동 판정에는 "결론이 먼저 나왔나"를 재는 줄이 없었다.
- **어떻게 잡았나**: 세무사 평가.
- **이제의 규칙**: 금지 규칙을 넣을 때는 그 규칙이 막는 **정당한 답**이 무엇인지 함께 적는다.

### 날조 가드가 진짜 요건을 지웠다 — 4천800만원 (10-14)
- **무슨 일**: `numeric_guard._won`이 '4천800만원'을 4천 + 800만 = 8,004,000으로 읽었다. 소득세법 §61의 4,800만원 요건 문장이 "출처 없는 수치"로 지워지고 "한도·세율·기한 … 세무사 확인" 문구가 붙었다.
- **왜 조용했나**: 가드가 작동한 결과가 "조심스러운 답"으로 보였다. 지워진 문장은 화면에 없으니 읽는 사람도 몰랐다.
- **어떻게 잡았나**: Q3 퇴보의 원인을 쫓다가.
- **이제의 규칙**: 천·백은 뒤의 만·억 단위에 묶는다. 계산용 숫자 파서는 `numeric_guard`가 아니라 `calc/income_tax_extract`를 쓴다.

### 오인용 하나가 문단·표를 통째로 지웠다 (10-15)
- **무슨 일**: 결론 문단에 조문을 쓰게 하자 '같은 법 시행령 제167조'를 상증법에 붙여 문단째 빠졌다. 표 셀에 블록 밖 조문이 하나만 있어도 표 세그먼트째 빠졌다. 머리+문장 한 세그먼트는 문장이 빠지면 세목 부분이 통째로 사라졌다.
- **왜 조용했나**: 인용 대조는 맞게 동작했다. 지우는 단위가 세그먼트였을 뿐이다.
- **이제의 규칙**: 인용 대조가 지우는 단위를 생각해 세그먼트를 자른다. 결론 문단엔 조문 번호를 쓰지 않고, 셀 속 조문은 지운다. 머리와 문장은 작문 직후 가른다.

### 파서가 다른 법을 전부 덮어쓴다 (10-15)
- **무슨 일**: `law_pdf_parse.py --laws X`는 articles.jsonl을 X만으로 덮어쓴다. 그대로 `ingest`하면 나머지 법이 전부 archived된다.
- **왜 조용했나**: 덮어쓰기는 로컬 파일 안에서만 일어난다. `ingest`를 돌리기 전까지는 아무 일도 없다.
- **어떻게 잡았나**: 적재 절차를 정비하다가, 실제 사고 전에.
- **이제의 규칙**: `--merge`로 파싱하고, 운영 ingest 전에 `ingest --dry-run`으로 "쓸 행 · archived 예정"을 확인한다. archived가 0이 아니면 멈춘다.

### 답변 턴이 경비 갈래로 샜다 (10-15)
- **무슨 일**: 상속세 대화 "아파트 한 채, 시가 15억 정도요" → 업무사용비율 되묻기, "어머니 살아 계세요" → 업무용승용차 판정 카드("인정 1,500,000,000원"). 추출이 답변 턴의 etype을 경비 유형으로 채웠다.
- **왜 조용했나**: 10/13부터 회차마다 간헐적이었다. g5는 기존 판정 줄로는 미달 0이었다.
- **어떻게 잡았나**: g5에서 2/2로 나왔다. `report_check`에 혼입 줄을 더했다(g5에 다시 매기면 ❌ 4).
- **이제의 규칙**: 짧은 답은 질문 꼴이 아니면 '답변'으로 못 박는다. 갈래를 고칠 때는 **검색 질의도** 같이 고친다(안 고치면 엉뚱한 조문으로 답했다).

### 한 줄짜리 결론 문단에선 가드가 무력했다 (10-15)
- **무슨 일**: 사용자 "1200만원" → 결론 문단 "120만 원"(g5 창 3건).
- **왜 조용했나**: `drop_unsourced_numbers`는 문장이 전부 걸리면 원문을 돌려준다. 본문에서는 답이 통째로 사라지는 것을 막는 장치였는데, 한 줄짜리 결론 문단에서는 날조를 그대로 내보냈다.
- **이제의 규칙**: 가드의 폴백은 **적용 대상의 길이**에 맞춘다. 결론 문단은 걸리면 뺀다.

### 로컬은 운영과 같지 않다 (10-13, 10-15)
- 로컬 `.env`에 운영 플래그가 없어 법령 갈래가 no_precedent로 보였다. 로컬 uvicorn 2대와 운영이 세션 풀(15)을 채웠다. 로컬도 법령을 운영 DB에서 읽어, 로컬 파일만 고친 표는 `LAW_STORE=file`로만 보였다.
- **이제의 규칙**: 로컬 스모크는 운영 플래그를 env로 맞추고, 1대만 띄우고, 무엇을 운영 DB에서 읽는지 먼저 확인한다.
