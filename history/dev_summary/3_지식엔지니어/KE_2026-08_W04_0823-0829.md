# 지식 엔지니어 — W04 · 2026-08-23 ~ 08-29

> **이번 주 요지** — 화면을 그리기 전에 **KB가 실제로 어떤 물건인지**부터 코드로 확인했다. `rag.passages` 한 테이블에 edge는 없고, 임베딩 단위는 **질문 + AI 답변 + 코멘트 번들**이다. 4096차원이라 인덱스를 못 타서 매 질문 **exact scan** 한다. 이 사실 하나에서 이번 주의 나머지가 나왔다. 번들 임베딩이 질문 텍스트에 끌려가기 때문에 0.85 클러스터는 오탐투성이였고, 진짜 중복의 신호는 `segment_id`였다. 저장 edge(`passage_edges`)로 전체 그래프를 그렸고, 적재 경로에서 세목이 "미분류"로 덮이던 구멍을 막고 413건을 소급 재분류했다. ### 소급 정리 — 의미 클러스터는 오탐, segment가 신호 (08-27)
- `find_duplicate_pairs()`(self-join, threshold 이상 쌍) + `find_duplicate_clusters()`(union-find로 transitive 클러스터화, maxScore 내림차순) + `get_passages_by_ids()`.
- 프로덕션(active 526) threshold 0.85 → **104개 클러스터, 390건(KB의 74%)**. 크기는 2건(39개)부터 9건(1개)까지였다.
- 원래 의심한 3건이 든 클러스터는 6건이었고, 하나씩 까 보니 이랬다.

| id | segment / 대화 | 판정 |
|---|---|---|
| `51f80d4c` · `a570f3b6` | 같은 segment(`_1_s2`), 같은 reviewer/auditor, **160ms 간격** | 진짜 중복(더블클릭 또는 재시도) |
| `d0d6125b` | 같은 대화, 다른 segment(`_1_s1`) | 정당한 별개 코멘트 |
| `ec2779de` | 같은 대화, 다른 segment(`_1_s0`) | 정당한 별개 코멘트 |
| `b4151f1f` | **다른 대화**(session_eval) | 합성 시나리오라 문구만 비슷한 오탐 |
| `dff35aea` | 같은 대화지만 session_eval(총평) 단위 | 별개 |

- **원인**: 번들 임베딩이 질문(A) 텍스트에 지배된다. 그래서 같은 대화의 다른 세그먼트나 같은 시나리오 템플릿으로 생성된 다른 대화가 0.85+로 잡히는 것이 구조적으로 불가피하다. union-find가 이를 증폭한다. A~B가 진짜 중복이어도 B~C가 임계값을 넘으면 무관한 C까지 딸려 들어온다.
- **정제**: 진짜 중복의 신호를 `conversationId` + `segmentId` 일치로 바꿨다(구현은 프론트 기본 선택 로직, → [FE](../5_프론트엔드/FE_2026-08_W04_0823-0829.md)). 자동 체크가 **286 → 45건(41개 그룹)** 으로 줄었다.
- 결과: **active 526 → 413건**(113건 retired, 누적 retired 116건). 같은 segment 재제출 그룹 0개, 남은 75개 클러스터(232건)는 의도대로 유지됐다. §3.1을 종결했다.
- 이 KB의 코멘트와 대화는 auditor 계정 이름으로 들어갔지만 **감사 모드 Claude 산출물과 합성 시나리오**다(README 규칙 1). "합성 시나리오라 우연히 비슷한 다른 대화"가 오탐의 한 축이었던 이유다.

## 그래프

### GraphRAG 재검토 — 검색 엔진 교체는 비채택 유지 (08-28)
"성능 트리거"가 아니라 "가치" 관점으로 다시 물었다.
- `Retriever` Protocol(`retriever.py:34`)이 이미 경계로 분리돼 있다. 나중에 GraphRAG 리트리버로 바꿔도 `pipeline.py`는 안 건드려도 된다. "지금 안 하면 나중에 힘들다"는 이유가 성립하지 않는다.
- 그래프가 풀어 줄 뻔했던 실제 문제(§3.1 오탐)는 이미 segment 휴리스틱으로 풀었다. 영구 그래프 스토어가 필요 없었다.
- 제품 논지가 "답변 품질"이 아니라 "답할 수 있는 범위"로 교정돼 있다. 그래프가 강화하는 다중 홉 추론·품질 축과 핵심 지표가 겹치지 않는다.
- 413건 규모에서는 구현 비용 대비 체감 이득이 없다.

**재오픈 신호**: ① §3.2 트리거(5,000~10,000건) 도달 ② occupation이 2개 이상이 되어 직업군 간 교차 참조 요구 발생 ③ 메타데이터 클러스터 + 국소 유사도 UI로 못 푸는 구체적 실패 사례.

PO의 정정으로 이 재검토는 "잘못 짚은 질문에 대한 올바른 답"이 됐다. → [DL](../8_결정교훈/DL_2026-08_W04_0823-0829.md)
