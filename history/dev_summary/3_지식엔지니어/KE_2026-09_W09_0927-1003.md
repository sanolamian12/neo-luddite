# 지식 엔지니어 — W09 · 2026-09-27 ~ 10-03

> **이번 주 요지** — KB3를 **모으고, 재고, 꽂을 자리를 짰다.** 소스 2인 국세청 질의회신을 2,000건 받아 정리본 1,995건을 만들었다. 판례와는 성격이 정반대다(제목 검색이라 적중 100%, 회신 문장이 본문). 그다음 DB를 건드리지 않고 메모리 안에서 precision을 쟀다. 질의회신은 시민 질문 useful을 **25% → 54%** 로 올렸다. 판례 요지는 짧아서 같은 갈래에서 거의 뜨지 않았다. 저장 자리는 `rag.passages`가 아니라 **별도 `kb3.*` 스키마**로 정정됐다. 밤에는 W5 설계대로 `kb3_store`, `Kb3Retriever`, 멱등 적재 스크립트를 짰다. 적재는 하지 않았다.

**KB3**는 외부에서 수집한 국세 지식이다. 소스 1은 판례(심판례) 요지 487건으로 지난주(W08)에 모았다. 소스 2가 이번 주의 질의회신이다.

## 단계 4a — 메모리 안 precision 계측 (09-27, DB 쓰기 0)

### 도구
- `scripts/kb3_ingest.py` — `stats` / `embed` / `search`. `MemoryKb3Retriever`가 numpy 코사인으로 찾는다.
- 벡터: `embedding-passage` 2,419회(배치 16, 약 8분) → `backend/data/kb3/embeddings.npz`(40MB, gitignore). 키는 **임베딩 텍스트의 sha1**이다. 4b 적재 때 그대로 재사용한다.
- 벤치: `bench_fusion.py --kb3 이름:범위:컷:쿼터`.

### 적재 범위 (PO 확정)
- 판례 **253**건: 적중 ∧ 근사중복 아님, 그리고 국세징수(원문 표기 "국세징수 302") 제외.
- 질의회신 **1,825**건: 근사중복 아님.
- 합계 2,078건.

### 본문 조립
질의회신의 `full_text`는 **회신만** 담고 있다(요지 미포함). 그래서 본문을 `요지: … \n회신: …`로 조립한다.

### 결과 (상세 수치는 → [EV](../7_평가검증/EV_2026-09_W09_0927-1003.md))
- 질의회신을 fusion에 붙이면(컷 0.40, 쿼터 2) 시민 useful **25.0 → 54.2%**, 병의원 far 31.6 → 40.5%, near 80.6 → 77.4%(−1문항).
- near −1문항은 kb3가 kb2·rag의 자리를 하나 가져간 것이다.
- 질의회신 점수대별 등급을 보면 **0.40 미만은 거의 잡음**이다. 컷 0.40의 근거다.
- **판례는 같은 갈래에서 질의회신에 밀린다.** 요지 중앙값이 120자라 코사인이 낮다. 0.45에서는 0회, 0.40에서는 158문항 중 10회(등급 2가 4회)다. 판례를 따로 부르려면 갈래를 나누거나 코퍼스별 컷이 필요하다.
- 판례 요지 최대 길이는 1,149자다. 설계의 429자는 파일럿 기준이었다.
- **걱정한 혼입은 없었다.** 민사 사해행위취소는 0회였다. 병의원 쪽 잡음은 "같은 분야 다른 쟁점"이었다(외국납부세액공제 → 한·러 조세조약 회신, 임원상여 → 임원퇴직소득 원천징수 가산세).

### 저장 자리 정정
설계 §7은 KB3를 `rag.passages`에 corpus만 달리해 넣는 안이었다. 그 테이블에는 corpus 칸이 없다. 넣으면 세 곳으로 샌다.

- 검수 선례 갈래
- KB 거미줄 그래프
