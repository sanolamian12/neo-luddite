# 지식 엔지니어 — W11 · 2026-10-11 ~ 10-17

> **이번 주 요지** — 지식의 중심이 **법령 DB(`laws.articles`)** 로 옮겨 온 주다. 세무사 피드백으로 법령 DB에 표가 통째로 없다는 것을 알았다. 법제처 PDF의 표가 이미지였기 때문이다. 국가법령정보센터 API 원문에서 **232조·표 396개**를 복원했고, 주 끝에 목 단위 표 44개를 더 찾았다. 그 위에서 일의 대부분은 "작문에 어떤 조문을 얼마나 실을지"를 코드로 정하는 것이었다. 세율 조문 직접 보강, 요건 호 목록, 위임 시행령 1개, 쟁점별 조문 키가 그렇다. 사례 자료(KB3)는 유형별로 줄였다. KB2는 의존 0을 확인하고 백업한 뒤 지웠다. 주 끝에는 세무사가 준 증권거래세법·4대보험을 적재했다(laws 8,878행).

## 법령 DB

### F1 — 법령 표 복원 (10-10 밤 ~ 10-12)
**laws.articles에 표가 통째로 없었다.** 법제처 PDF의 표는 이미지라 텍스트 추출에서 빠졌다(현행 약 276조, 휴리스틱 추정). 소득세법 §47①·§55①·§59① 등이 그렇다. LLM3가 §55를 맞게 골라도 작문이 숫자를 쓸 수 없었다. 재현에서는 "현행 조문에는 세율표가 포함되어 있지 않다"는 틀린 말까지 했다(세무사 Q1). 국가법령정보센터 Open API 본문에는 같은 표가 상자 문자(┌─┬)로 원문 텍스트에 있었다.

| 한 일 | 내용 |
|---|---|
| `scripts/law_tables_api.py`(fetch → apply) | API 원문 표를 **같은 판(공포번호) 또는 본문이 같은 조문에만** 복원. **232조·표 396개**. 판도 다르고 본문도 다른 126조는 건너뜀(우리 PDF가 구판인 조문, 별도 과제) |
| 쟁점 한 줄(gists) 키 이전 | 키 = 본문 sha1이라 표가 들어가면 키가 바뀐다. 옛 키에서 새 키로 옮겨 Solar 재생성 0 |
| 임베딩 | 바뀐 215건만 다시 |
| 표 행은 결정론 세그먼트 | 작문이 행을 생략하거나 "표 참고"로 넘겨서. `law_select.table_blocks` · `pipeline._table_segments`, 질문에 가장 가까운 조문 하나 |
| 세율 조문 직접 보강 | 세율 질문은 저장소에서 '세율' 조문을 직접 가져온다(`rate_article`). LLM3 후보 검색은 카드가 다룬 법령을 빼서 §55가 후보에 들지 못했다 |
| 표 조문 상한 | 1,800자 |

운영에서 종합소득세율 8구간, 법인세율 호별 2표, 증여세율 5구간이 정확했다.

표가 바뀌었을 때의 순서도 정했다. `law_tables_api.py apply` → `law_ingest.py embed` → `ingest`(사용자) → 재시작 1회(지문이 바뀌어 캐시 갱신). 캐시는 → [BE](../4_백엔드인프라/BE_2026-10_W11_1011-1017.md).

### 증권거래세법 · 4대보험 적재 (10-15 저녁)
세무사 자료(증권거래세법 3·4대보험 9 PDF, 판단표 xlsx 이미지)를 법별 폴더로 복사해 설계 부록 A 절차로 넣었다.

### 요건 호 목록 · 위임 시행령 (10-13 ~ 10-14)
- **`law_select.item_list`(10/13)** — 작문이 요건 목록을 끝내 쓰지 않으면, 답이 먼저 인용한 조문의 호를 원문 그대로 번호 목록으로 낸다. 호 속 '다만,' 단서는 뺀다. 세율 표(F1)와 같은 근거다. X03(차이 + 요건 복합 질문)은 규칙을 넣어도 산문으로 썼다.
- **요건 폴백 개선(10/14)** — 요건 부분 조문부터 찾는다. 시행령 인용이면 그 시행령이 받는 법률 조문의 호로 간다(§109② → §61①). '삭제' 호는 뺀다. 목록은 요건 부분 뒤에 둔다.
- **A5 위임 인덱스(10/13)** — 시행령 머리의 '법 제N조…대통령령'으로 후보를 넓히는 코드를 만들어 오프라인 A/B(`eval/a5_delegate_offline.py`)를 돌렸다. off·on 모두 10/10에서 시행령을 함께 골랐다. 넣지 않았다.
- **`law_select.delegated`(10/14, 지적 5)** — 정의·요건 유형은 고른 법률 조문을 첫머리에서 "법 제N조"로 받는 시행령 조문 1개를 결정론으로 보탠다. 세율 질문은 제외한다(§55에는 근속연수 같은 잡음이 붙는다). 조문 상한을 900 → 1,800자로 올렸다(`ARTICLE_CHARS_DEEP`). Q4는 §15 → 시행령 §11(수익 범위 전문) → §18 익금불산입으로 이어졌다.

A5와 `delegated`는 다른 장치다. A5는 LLM3의 **후보**를 넓히는 것이었고 이득이 없었다. `delegated`는 고른 뒤에 시행령 1개를 **결정론으로 덧붙인다**.

### 사례 자료(KB3) 줄이기 (10-14, 지적 2)
`_trim_cases_for_law`로 유형마다 사례 수를 정했다. 정의 = 0건, 요건 = 쟁점 게이트 'same' 1건, 세율 표가 나가는 답 = 0건이다. 쟁점 게이트는 'different'만 빼서 'related'가 다 들어오고 있었다. Q3에는 2020 다사업장 해석과 증여세 가업승계 특례가 들어왔다. 로컬에서 Q4의 '간접외국납부세액' 질의회신은 게이트가 same으로 봤다. 그래서 정의는 0건으로 정했다. 끄기 `ADVISORY_CASE_TRIM=off`.

### 복합 사안 블록 · 쟁점별 조문 (10-15)
- **복합 사안 블록** — 위임 시행령(§35 → 시행령 §26 기준금액)과, 고른 조문이 '제A조부터 제B조까지'로 부르는 조문군의 첫 조문(§60 시가, `law_select.referenced`), 쟁점이 같은 사례 1건을 싣는다.
- **쟁점별 조문(E §2-3)** — 복합 갈래에서 LLM3는 쟁점 조문(§101·§35)만 고르고 세율·공제·신고기한 조문(소득세법 §104·§105, 상증법 §56·§68)은 한 번도 고르지 않았다. `law_select.issues()`가 질문 글에서 쟁점(양도세 주식/부동산, 비상장 대주주, 부당행위, 증여 §35, 증여 일반, 증권거래세)을 판별하고 `ISSUE_LAWS`의 조문 키를 블록에 싣는다. 끄기 `ADVISORY_ISSUE_LAWS=off`.
  - 긴 조문은 항·호를 발췌한다(§104 4천 자 → 주식 11·12호).
  - 전체 조문에도 블록 머리에 법령 이름을 붙인다. 원문 머리는 '제53조(…)'뿐이라 소득세법과 상증법이 섞이면 모호하다.
  - 상한 14, 표 목록에는 넣지 않는다.
  - 증권거래세 키(§8①·§7①·§10①2호)는 미리 넣어 두었다. 적재 전에는 저장소에 없어 건너뛴다.
- **요건 항목 배지 보완** — 이름 없는 '시행령 제N조'가 허용 조문 중 하나로만 풀리면 법령 이름을 채운다. 물려줄 앞 문장 조문이 없으면 요건 조문(호 목록 있는 법률 조문) 배지를 단다.

대주주 조문이 없던 i1에서는 C1의 65% 보유를 '대주주 아닌 자 10%'로 잘못 읽었다. §167의8①을 더한 뒤 '4% 이상에 해당할 수 있음'이 나왔다. 작문 입력은 C1이 약 6~7k토큰(쟁점 조문이 없던 C4는 4.5k)이었다. 상장 대주주 §157은 블록에 싣지 않았다.
