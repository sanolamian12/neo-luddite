# 3. 지식 엔지니어

## 개요

**답의 근거가 되는 지식을 모으고, 구조를 짜고, 찾을 수 있게 만드는 사람이다.**
이 제품의 핵심 논지는 "KB는 세무사 검수로 자란다"였다. 지식이 어떤 단위로 쌓이고(번들, 문장, 카드),
어떤 구조로 묶이고(메타데이터 클러스터, 2단 트리, 3층), 어떻게 검색되는지(exact scan, RRF 융합, 권위 서열)가
전부 이 자리의 일이다.

8~9월에 KB는 세 번 모양을 바꿨다.
- **KB1**: `rag.passages` 평면 번들이다. 8월 말에 중복을 정리하고 세목을 분류했다.
- **KB2**: AI가 동적으로 카테고리를 만드는 2단 트리다. 9월 초~중순에 만들었다.
- **KB3**: 국세 심판례와 질의회신을 외부에서 수집했다. 9월 말에 시작했다.

## 역할

| 축 | 하는 일 |
|---|---|
| **KB 구조·적재** | 임베딩 단위, 적재 경로(ingest), 중복 키, 스키마 분리(`rag.*` · `kb3.*`)를 정한다 |
| **합성·재구조화** | KB2의 분류·합성·병합·대목 승계를 맡고, 세대가 바뀌어도 기여가 보존되게 한다 |
| **검색·융합** | 유사도 컷, top-k, L0 규범·L1 사전·L2 KB의 RRF 융합, 쿼터, 권위 서열을 정한다 |
| **외부 코퍼스 수집** | 수집 경로를 실측하고(robots 준수), 파일럿 → 세무사 승인 → 본수집 순서로 모은다 |
| **계측** | 커버리지와 혼입원을 재고, 코퍼스 분포를 본다 |

## 다루는 것

- `backend/api/rag/` — `store.py` · `ingest.py` · `retriever.py` · `taxonomy.py`
- `supabase/migrations/*rag*` — `rag.passages`, `passage_edits`, `passage_edges`
- `collectors/` — 외부 수집기, `*.jsonl` 수집본

## 다른 포지션과의 계약

- **← 프로덕트 오너**: 코퍼스를 넓히는 규칙을 받는다. 계측을 먼저 하고, 한 번에 한 소스씩 넣고, 라이선스와 권위 등급을 확인한다.
- **→ AI 엔지니어**: 검색 결과에 **출처 층과 권위 라벨**을 붙여 넘긴다. 라벨이 섞이면 답변이 근거의 무게를 구분하지 못한다.
- **→ 백엔드**: 무거운 배치(재분류·재구조화·edge 재계산)는 **타임아웃·레이트리밋·야간 예약**을 함께 설계해 넘긴다.
- **→ 프론트엔드**: 지식의 모양(번들 포맷, 클러스터 라벨)을 파싱 가능한 형태로 고정해 준다.

## 이 자리에 필요한 역량

벡터 검색의 구조적 한계(번들 임베딩은 질문 텍스트에 끌려간다)를 아는 것, 그리고 **"커버리지 20%"라는 숫자를 보면
데이터 경로를 의심하는 습관**.
