# 프로덕트 오너 — W05 · 2026-08-30 ~ 09-05

> **이번 주 요지** — admin "완료" 화면에 쌓인 7월 미확정 검수 항목을 치웠다. 처음에는 이것을 **ICTC 논문 데이터로 기억**했다. 기록을 다시 읽어 보니 제품 개발 작업이 남긴 검수 대기열이었다. 정체가 바로잡힌 뒤 삭제 범위를 정했다. 기준은 **"검수실(문장단위)에서 '제출됨'인 것만"** 이다. 한 단계 더 나간 `reviewed` 2건은 범위에서 뺐다.

## 운영 데이터

### 출발점 — "논문 때 쌓인 데이터"라는 기억 (08-31)
admin 계정으로 "완료" 사이드 메뉴를 보다가, 07-16~21 사이 auditor·auditor2·auditor3이 제출했지만 검수확정이나 인정·거절이 들어가지 않은 항목이 다수 보였다. PO는 이를 ICTC 2026 논문 실험 때 쌓인 데이터로 기억하고 있었다.

조사 결과는 달랐다(→ [RS](../6_리서치/RS_2026-08_W05_0830-0905.md)). 이 항목들은 제품 개발 작업(100건 일괄감사, RAG 재검증)의 두 번째 라운드가 남긴 검수 대기열이었다. 세 계정의 코멘트와 세션 평가는 **감사 모드 Claude 산출물**이다. 사람(세무사)의 작업이 아니다.

### 삭제 범위 확정 — `submitted`만, `reviewed`는 제외 (08-31)
1차 삭제(`session_evaluations` 확정분 39건) 뒤 auditor로 재로그인해 확인했는데 "완료" 화면이 그대로였다. 이 확인이 1차 삭제가 엉뚱한 테이블이었다는 것을 드러냈다(→ [BE](../4_백엔드인프라/BE_2026-08_W05_0830-0905.md)).

타깃을 바로잡으면서 지시한 범위는 이렇다.

> "검수실(문장단위)에서 '제출됨'으로 표시된 데이터를 지워서 admin·auditor 양쪽에서 다 안 보이게"

| 정한 것 | 내용 |
|---|---|
| 대상 | `status='submitted'` audits(52건)와 거기 딸린 reviews·line_feedback |
| 제외 | auditor3의 `reviewed`(검수저장, 이의가능) 2건. 한 단계 더 진행된 상태라서 |
| 남은 판단 | 그 `reviewed` 2건을 지울지는 따로 확인한다 |
