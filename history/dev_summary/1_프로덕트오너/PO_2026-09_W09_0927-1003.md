# 프로덕트 오너 — W09 · 2026-09-27 ~ 10-03

> **이번 주 요지** — KB3를 두고 **세 번의 묶음 결정**을 냈다. 첫째, 판례에 공제 질문이 없다는 계측을 보고 "가능한 한 풍부하게" 질의회신으로 넓혔다. 둘째, 메모리 안 계측을 보고 저장 자리, 권위 서열, 컷, 적재 범위를 정했다. 여기서 설계 마스터의 저장 자리(`rag.passages`)를 **별도 `kb3.*` 스키마로 정정**했다. 셋째, W5(LLM2 답변 단계) 설계를 KB3 배선보다 먼저 하기로 하고 W5-1~4를 확정했다. 대외로는 논문 투고처를 ACK에서 KIIS로 옮겼고, 요약문을 마감 이틀 전에 냈다.

### W5 먼저, 그리고 W5-1~4 (09-27 밤)
W5는 LLM1 피벗 작업 계획의 작업 패키지 번호다(달력 주가 아니다). 내용은 LLM2 답변 단계다.

순서를 두고 **(a) W5 설계 먼저 → KB3 배선**을 골랐다. W5가 KB3를 부르는 모양이 검색 갈래 구조를 정하기 때문이다. 이어서 네 가지를 확정했다. **재논의 금지**로 묶었다.

| # | 결정 | 근거 |
|---|---|---|
| W5-1 | 근거가 있을 때만 판정한다. 코드가 강등하고, gap이면 조건부 | 정본 §1 "판정 권위 = LLM2" |
| W5-2 | v2 = KB2 빼고 `rag, kb3, kbdict`. 판례를 따로 부르지 않는다 | 피벗의 KB2 폐기. 컷 0.40에서 판례 등장 158문항 중 10회 |
| W5-3 | 법령 KB 없이 KB3 본문 속 조문만 인용한다 | 조문 번호 포함률 판례 요지 92%(446/487) · 질의회신 99%(1,969/1,995) |
| W5-4 | 엔진 대조를 v0에 넣는다 | LLM2 판정 품질의 유일한 객관 지표 |

`0041` 적용과 KB3 적재는 PO가 확인한 뒤에 한다. 구현은 → [AIE](../2_AI엔지니어/AIE_2026-09_W09_0927-1003.md) · [KE](../3_지식엔지니어/KE_2026-09_W09_0927-1003.md).

「후일담」 10/6 프로덕션 챗은 KB3 단독(`RAG_SOURCE=kb3`)으로 전환됐고 쟁점 적합성 게이트가 붙었다. KB2는 KB 구조 교체로 범위 밖이 됐다.

## 외부 대응 — 논문

### ACK 미제출, KIIS 2026으로 전환 (09-14)
KB2 3방향 실험을 ACK 2026용으로 돌리던 중 투고처를 바꿨다. 이유는 **ICTC처럼 실제 세무사 대조를 넣으려면 일정 조율 시간이 필요했다**는 것이다. 세무사 회신은 9월 말에나 가능했다. KIIS는 10/2가 요약문 마감이고 본논문은 10/23이라 시간을 더 벌 수 있다.
- 분량은 3쪽으로 하고, 2쪽 초과분의 쪽당 1만원 추가를 감수한다.
- ACK 초안은 초안으로만 남았다.

### 원고 v1 코멘트 8개 (09-15)
1. 제목은 KB2 중심. 결선 전시에서 ICTC 논문과 나란히 걸고 "단계적으로 발전시킨 모델"로 소개한다.
2. **‘KB2’를 고유명사로 쓰지 않는다** → "새로운 지식베이스", "제안된 기법"(코멘트 2·3·6).
3. 요약의 성과와 한계를 두 문장으로 나눈다.
4. 키워드 순서: LLM, 검색 증강 생성, 지식베이스 축약, 법률 환각, 세무 상담.
5. "실패 요인의 분리" 절은 우리만 아는 정보라 실험 설계로 옮기거나 지운다.
