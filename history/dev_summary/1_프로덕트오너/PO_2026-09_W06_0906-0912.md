# 프로덕트 오너 — W06 · 2026-09-06 ~ 09-12

> **이번 주 요지** — 이 주의 결정은 거의 전부 KB2(지식베이스2) 위에서 나왔다. 질문 하나("지금 KB도 코사인으로 찾냐, 백서에도 통하냐")가 문장 단위 사전의 계기가 됐다. 이어서 "이 구조를 Upstage AI가 이해하고 구축해야 한다"(동적 재구조화), "세무사가 버튼 한 번으로 큰 작업에 들어가면 안 된다"(야간 예약)가 설계를 끌고 갔다. 주 중반에는 엔지니어에게 **"계측 먼저, 대조군 먼저"** 를 지시했다. 이 지시가 커버리지 20% → 64%의 출발점이 됐다. '기타' 세목과 세대교체 보존 전략도 정했다. 주 끝에는 **완성 기준 G1~G3** 을 정의하고 **"커버리지는 목표가 아니라 계기판"** 이라고 선을 그었다. 운영 쪽에서는 논문 세션과 제품 세션을 분리하는 정책을 세웠다.

## 운영 모델 — KB2의 권한과 기여

### 메뉴와 권한 (09-09)
요청은 이랬다. 세무사(auditor) 계정에는 "RAG 지식망" 아래 "지식베이스2"(확인 + 수정), admin 계정에는 "AI 코어 → 지식베이스 → 지식베이스2"(읽기 전용)를 둔다.

| 정한 것 | 내용 | 기각한 대안 |
|---|---|---|
| 합성 트리거 | **admin 전용**. 기존 AI 코어 파이프라인 액션(배치·재빌드)과 같은 급 | auditor도 누르게 하는 안 |
| 세무사의 문장 수정 | **즉시 반영**. 번복 근거는 `sentence_versions` 전체 이력 | `rag.passage_edits`식 제안 → admin 승인 큐 |

크레딧 쪽 설계(크레딧 2종 — RAG 크레딧과 KB 크레딧을 독립 축으로)는 엔지니어 판단으로 함께 들어왔다. 문장을 고치면 그 문장의 KB 크레딧만 편집자에게 전량 넘어가고, RAG 크레딧은 원본 passage가 살아 있는 한 유지된다. 6단계(`ledger_entries.credit_type`)로 미뤘다. → [DL](../8_결정교훈/DL_2026-09_W06_0906-0912.md)

### 재구조화는 매번 전체 재생성 (09-09)
동적 재구조화를 정하며 두 가지를 확정했다.
1. **연속성 매칭을 하지 않는다.** 레이블과 개수가 바뀌어도 AI가 이전 카테고리와 짝을 짓지 않는다. 이전 문서는 `status='archived'`로 보관한다(삭제 아님). 잠긴 문장도 보존되지만 검색과 세무사 화면에서는 빠진다.
2. **진행 UX는 job id + 폴링.** 이 레포에 처음 생기는 패턴이지만 UX가 낫다는 판단이다.

### 편집 락과 그룹 (09-09)
여러 세무사가 같은 KB2를 동시에 만지면 나중 저장이 덮어쓴다는 문제를 제기했다. 확인한 것은 둘이다.
- **기존 AI 합성 세목도 언제든 대목에 편입할 수 있다**(신규/기존 구분 없음).
- **락 자동해제는 서버 TTL(5분)** 로 한다. 하트비트 없이, 다음 사람이 획득을 시도할 때 덮어쓴다.

- 그룹 재배치는 **[확정] 버튼**을 눌러야 반영(되돌리기 어려운 큰 변경)
- 손잡이는 롱프레스 대신 클릭
- 저자 기여 배지를 버전 배지 옆으로
- 문장 **연결 끊기/재연결 + 사유 필수**(삭제 아님, 배선실 철학)

### G2 — 보존 + 의미 기반 재부착 (09-12)
'기타'에서 옮긴 그 문장이 다음 재구조화에서 정확히 한 회차 만에 원상복귀했다. 전략을 **"보존 + 의미 기반 재부착"** 으로 정했다. 문자열 매칭은 기각했다(목차 레이블이 세대를 넘어 33~67%만 남는다).

구현하면서 정할 세부 결정(원문 표기로 "L2 결정") 6건을 확정했다.

| # | 정한 것 | 근거 |
|---|---|---|
| ② | 중복 정책: **둘 다 둔다** | 원문 1건이 여러 문장에 들어가는 것은 지금도 매 회차 일어난다(1문장 251 · 2문장 46 · … · 12문장 1) |
| ③ | 기여·정산: **충돌 없음** | 기여 = 원문 passage 생존이다. 재부착은 attribution을 건드리지 않는다 |
| ④ | 보존 범위: `auditor_edit` + `moved` + `retired` **전부** | retired도 지우면 "쓰지 말라"던 문장이 매 회차 되살아난다 |
| ⑤ | 스키마 `0026`: CHECK 확장만 | 별도 플래그 컬럼은 이력과 어긋날 자리를 만든다 |
| ⑥ | 계측: **분리 계상** | 보존분을 `cited`에 더하면 커버리지가 누적치로 변한다 |
| ⑦ | 재부착 실패율을 coverage에 남긴다 | 계속 크면 임계값이나 목차 안정성의 신호 |

### 로드맵 정리 — 기능 빌드에서 완성 증명으로 (09-12)
전체 로드맵 현황을 두 계층으로 정리했다.
- **계층 1(원본 RAG `rag.passages`)**: 끝났다. §3.2 확장성은 "할 일"이 아니라 **"지켜볼 숫자"** 다(413 / 트리거 5,000~10,000). GraphRAG로 검색 엔진을 바꾸는 안은 비채택 유지.
- **계층 2(KB2)**: 기능 1~19를 전부 배포했다. 이제 "더 만들 것"이 아니라 **"작동하고 자란다는 증명"** 단계다.

완성 기준을 한 줄로 적었다.

> "세무사가 하루 쓰면 KB2가 그만큼 좋아져 있고, 다음 회차가 그걸 지우지 않으며, 지표가 편차 안에서 재현된다."

| 기준 | 뜻 | 9/12 위치 |
|---|---|---|
| G1 재현성 | 지표가 편차 안에서 재현되고, 차이를 계측으로 분해할 수 있다 | 95%, 타임아웃 값 하나 남음 → 같은 날 마감 |
| G2 축적성 | 사람이 손댄 것이 세대교체를 살아남는다 | 9/12 성립 |
| G3 임팩트 | kb2 경로의 되묻기율이 내려간다 | 미착수 → 같은 날 계측 배선 |

함께 정한 것:
- **커버리지는 목표가 아니라 계기판이다.** 자동 경로 천장 63~65%에 이미 도달했다. 숫자를 올리는 작업은 더 하지 않는다.
- 남은 3가지(타임아웃 값 · G3 계측 · 트리 가독성)가 끝나면 **KB2 개량을 일단락하고 논문으로 간다.**
- 3방향 벤치마크(무RAG / 기존 RAG / KB2)는 논문 세션 사안이다. 제품 세션은 G3 계측 배선까지만 한다.

- **`TIMEOUT_SYNTHESIZE` 240 → 60초.** 정상 호출 48건이 전부 15초 이하였다. 45초도 잘리는 정상 호출이 0건이지만, 아직 못 본 느린 호출에 여유를 남기는 보수적 선택을 했다.
- G3 계측 결정 3건:
  1. 적재 위치는 **백엔드 전용 테이블**. 프론트 payload에 얹으면 curl로 도는 논문 벤치가 통째로 유실된다.
  2. **분모를 스키마에 박지 않는다.** 모든 턴을 `outcome`으로 구분해 남긴다. `no_precedent`(선례 없어 되묻음)가 G3의 분자이고, `undecided`(판정형 결정변수 부족)는 섞지 않는다.
  3. **화면 노출은 범위 밖.** 표본 0에서 시작하는 패널은 만들지 않는다.
- 커버리지가 66.3% → 53.3%로 내려갔다. **기록만 한다.** 이번 코드 변경과 인과가 없고, 목차까지 새로 뽑는 전체 파이프라인의 편차는 잰 적이 없다.
