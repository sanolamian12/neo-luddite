# 프로덕트 오너 — W13 · 2026-10-25 ~ 10-31

> **이번 주 요지** — 시연(11/3~5 예정) 앞에서 **"11/2까지 기능·성능을 올릴 수 있는 한 최대로"** 라고 방향을 정하고 순서를 매겼다. 계산 갈래는 범위를 매번 **표를 먼저 보고** 정했다. 증여 질문 라우팅 표를 보고 결혼 자금 질문(S03)만 계산 갈래로 보냈고, 부담부증여 결함이 나오자 게이트에서 빼자는 권고 대신 **계산에 넣기**를 골랐다. DB에 없는 계산식은 법령 API 원문에서 복원하게 했다. 관리자 화면에서는 직접 게시 코드를 등록하고 시크릿 창으로 유입이 잡히는 것을 확인했다. 팀 미팅의 요청으로 대문을 바꿨고, 시연 기간에 미리 시작을 끄자는 권고를 받았다.

### 일반 증여세 — 라우팅 표를 먼저 보고 (10-26)
평가 세트의 증여 질문이 어느 갈래로 가는지 표를 먼저 봤다. 그리고 셋을 정했다.
- **S03(결혼 자금 1억)만 계산 갈래로 보낸다.** 세액 물음에 '내야'가 들어 있다. 나머지(한도 질문, 차용·무상 거주·명의 통장, 10년 한도)는 종전대로 간다.
- 혼인·출산 공제(상증법 §53의2)를 넣는다.
- 이어서 10년 합산(§47② + §58)까지 넣는다.

### 부담부증여 — 빼지 말고 계산에 넣는다 (10-26)
일반 증여세를 올린 뒤 "전세 3억 낀 시가 10억 아파트를 아들에게 증여하면"이 채무를 빼지 않고 2억1,825만으로 나왔다. 세 가지를 골랐다.

| 고른 것 | 다른 길 |
|---|---|
| **계산에 넣는다** — 증여세 + **조건부** 양도세(권고안) | 게이트에서 빼서 계산 갈래로 보내지 않기(권고) |
| 시행령 §159 계산식을 **API 원문으로 복원**(권고안) | — |
| 혼인 공제 §53의2⑤⑥ 확인 문장 **넣음** | — |

원문은 첫 줄에서 게이트 제외를 "권고"라고, 계산에 넣기의 범위를 "권고안"이라고 적었다. 계산에 넣는 쪽을 골랐다. 구현은 → [AIE](../2_AI엔지니어/AIE_2026-10_W13_1025-1031.md) · [KE](../3_지식엔지니어/KE_2026-10_W13_1025-1031.md).

## 운영

### 게시 코드 등록 · 시크릿 창 E2E (10-27)
운영 `/admin/usage` 맨 아래 '게시 코드'에서 두 개를 등록했다.
- '아프니까 사장이다' 채널용 — 글 이름 '10월 첫 소개글'
- 경리나라용

시크릿 창으로 게시 링크 → 질문 → 관리자 화면 새로 고침을 했다. 유입 경로 '아프니까 사장이다'에 방문자 1, 질문한 비율 100%(1), 세션당 질문 1.0이 잡혔다. 퍼널은 방문 5 · 질문 2 · 카드 2 · 연결 클릭 1(직접 방문 쪽)이었다.

직접 써 보며 하나를 찾았다. 코드·채널 칸의 예시 글자가 입력값처럼 보여서, 저장 버튼이 왜 꺼져 있는지 몰랐다. 예시 앞에 '예:'를 붙이기로 했다(다음 push에 묶음). → [FE](../5_프론트엔드/FE_2026-10_W13_1025-1031.md)

- **알아 둘 것** — E2E로 만든 방문 1건은 실제 집계에 남는다. 본선용 데이터에서 팀 시험을 빼려면 그 브라우저를 집계 제외로 둔다.
- **남은 결정** — 팀원에게 관리자 계정을 줄지(사용자).
