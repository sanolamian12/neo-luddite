# 6. 리서치

## 개요

**제품에서 나온 질문을 실험으로 바꾸고, 그 결과를 논문으로 내서 외부의 검증을 받는 사람이다.**
이 프로젝트는 대회 출품작이면서 학회 논문의 실험장이었다. ICTC 2026(채택, 카메라레디 4쪽)과
KIIS 2026(요약문 제출)이 이 시기에 진행됐다. 논문 작업은 제품 코드와 **다른 세션**에서 한다.
오프라인 채점에 쓴 도구가 제품 경로에 섞이지 않게 하기 위해서다.

## 역할

| 축 | 하는 일 |
|---|---|
| **실험 설계** | 비교 조건(KB2·번들·없음 등), 표본, 채점 기준(strict judge), 대조군을 정한다 |
| **맹검 채점·대조** | 채점자에게 조건을 가리고, 세무사 대조로 개봉해 하한을 정직하게 보고한다 |
| **데이터 출처 관리** | 미확정 검수 데이터, 감사 모드 산출물이 인용에 섞이지 않게 정정한다 |
| **투고 절차** | 지면 제한, 카메라레디, 등록, eCF 같은 마감 일정을 관리한다 |

## 다루는 것

- `docs/academic paper/` — 원고, 조판, 채점 결과
- `history/*리포트*` · 실험 샘플 CSV(답변 원문 CSV는 git 비추적)

## 다른 포지션과의 계약

- **← AI·지식 엔지니어**: 실험 조건마다 같은 파이프라인 버전과 같은 표본을 받는다.
- **→ 프로덕트 오너**: 논문 숫자가 제품 논지(예: "RAG는 범위를 넓힌다")를 지지하는지, 거스르는지 보고한다.
- **↔ 평가·검증**: 벤치 도구를 함께 쓰되, 논문용 채점은 **미확정 데이터를 쓰지 않는다**.

## 이 자리에 필요한 역량

긍정적인 결과보다 **하한을 먼저 보고하는 정직함**. 그리고 데이터가 누구 손에서 나왔는지를 끝까지 추적하는 습관.
