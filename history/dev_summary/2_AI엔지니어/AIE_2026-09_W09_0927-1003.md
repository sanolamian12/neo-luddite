# AI 엔지니어 — W09 · 2026-09-27 ~ 10-03

> **이번 주 요지** — LLM2 답변 단계(작업 패키지 W5)를 처음 코드로 짰다. 원칙은 하나다. **근거가 있을 때만 판정하고, 근거가 없으면 코드가 강등한다.** 모델이 낸 판정을 `enforce()`가 근거 본문과 대조해 `판정 보류`나 `조건부`로 내리고, 근거에 없는 조문 문장은 지운다. 판정 품질을 잴 객관 지표로 규칙엔진 대조를 붙였다. 스모크 2문항이 끝까지 돌았다. 짜는 동안 지뢰 다섯이 드러났다. openai 지연 import 교착, 거짓 출처 문구, "날조 조문은 numeric_guard가 잡는다"는 설계 오류, 숫자 없는 basis의 부분일치 구멍, 개인/법인 혼입이다.

W5는 달력의 주가 아니라 9/23 LLM1 피벗 작업 계획의 작업 패키지 번호(W0~W5)다. 이 피벗에서 **판정 권위는 LLM2**로 정해졌다(엔진은 대조용으로 남는다).

## LLM2 답변 단계 (09-27 밤)

### 설계 — 근거 있을 때만 판정
설계 마스터는 `design/W5_LLM2_답변단계_설계.md`다. PO가 확정한 네 결정(W5-1~4)이 코드의 모양을 정했다. → [PO](../1_프로덕트오너/PO_2026-09_W09_0927-1003.md)
- W5-1: 근거가 있을 때만 판정한다. 근거가 없으면 코드가 강등한다(설계의 장치 M1). 근거에 빈틈(gap)이 있으면 조건부다.
- W5-2: v2 검색 갈래 = `rag, kb3, kbdict`(KB2 제외).
- W5-3: 법령 KB 없이 KB3 본문 속 조문만 인용한다.
- W5-4: 엔진 대조(설계의 장치 M4)를 v0에 넣는다.

### `api/llm2.py` (agentic-v2)

| 붙은 것 | 내용 |
|---|---|
| 근거 4블록 라벨 | 검수 선례 > 판례 요지 > 국세청 해석 > 참고 사전. 4a에서 PO가 정한 권위 서열 그대로다 |
| 충돌 규칙 | 판례와 해석이 부딪치면 둘 다 밝히고 조건부 또는 보류 |
| 도구 출력 | `emit_answer{verdict, verdict_basis, segments}` |
| `enforce()` | basis가 rag·kb3 본문에 없으면 **`판정 보류`** + 결론·적용 문장 제거 · gap인데 확정이면 **`조건부`** · 근거에 없는 `제N조` 문장 제거 · 인용 대조 |
| 규범 머리말 | 공통 규범은 본문만 빌리고 머리말은 자체 것을 쓴다 |

- `enforce()`는 **모델 호출과 분리**했다. W5 하니스가 그대로 재사용하게 하려는 것이다(`구현 판단`).
- 규범 머리말을 바꾼 이유: `llm._with_norms`의 "판정은 규칙엔진의 권위"는 v2에서 거짓이다. v2에서는 LLM2가 판정 권위다(`구현 판단`).
