# 2. AI 엔지니어

## 개요

**LLM이 무엇을 말하고 무엇을 말하지 않을지를 정해서 코드로 만드는 사람이다.**
이 제품의 LLM은 모두 Upstage `solar-pro3`이다(국내 AI 트랙 조건으로 외산 모델은 제품 경로에 쓰지 않는다).
이 자리의 일은 모델을 고르는 것보다 **모델에게 어떤 일을 맡길지 정하는 것**에 가깝다.
분류, 추출, 되묻기, 답변 생성처럼 맡길 일을 정하고, 맡기면 안 되는 일(판정, 수치 생성)을 걷어 낸다.

## 역할

| 축 | 하는 일 |
|---|---|
| **프롬프트·function-calling** | 분류기(`classify_tax_category`), 답변 생성 규칙, 근거 규칙, `tool_choice` 강제 호출을 짠다 |
| **가드** | 날조된 수치를 막고(numeric_guard), 판정형 답변이 섞이는 것을 막고, 근거 없이 판정하지 않게 한다 |
| **역할 설계** | LLM1(사장님 질문 추출·되묻기)과 LLM2(답변)의 경계, 엔진 판정과 LLM 판정의 관계를 정한다 |
| **모델 적합성** | 모델 교체 전에 과제 정의부터 의심하고, 오라클 천장과 블라인드 기준선을 잰다 |

## 다루는 것

- `backend/api/llm.py` — 분류·생성 호출, 시스템 프롬프트
- `backend/api/pipeline.py` · `engine_adapter.py` — 엔진 판정과 RAG 자문 경로
- LLM1 few-shot 데이터, 충분성 판정 레코드

## 다른 포지션과의 계약

- **← 프로덕트 오너**: 분류 체계와 정책을 **설명 문장까지** 받는다. 카테고리 이름만으로는 미묘한 경우를 놓친다.
- **↔ 지식 엔지니어**: 검색이 준 근거의 **출처와 권위 등급**을 라벨로 받아 답변 규칙에 쓴다. 근거가 없으면 판정하지 않는다.
- **→ 리서치·평가**: 개선 회차마다 같은 채점 기준(가능하면 strict)으로 잴 수 있게 출력 형식을 고정한다.

## 이 자리에 필요한 역량

프롬프트보다 **과제 정의를 먼저 의심하는 눈**. 72%를 넘는 회차가 하나도 없으면 모델이 아니라
문제를 바꿔야 한다는 것을 아는 정도.
