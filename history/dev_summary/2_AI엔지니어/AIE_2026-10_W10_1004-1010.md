# AI 엔지니어 — W10 · 2026-10-04 ~ 10-10

> **이번 주 요지** — 한 문장으로 줄이면 **"solar 에게 말로 부탁한 것은 하나도 지켜지지 않았고, 입력과 출력을 코드로 잡은 것만 효과가 났다"** 이다. 같은 결론이 다섯 번 나왔다.
> - 원문 "복사"를 시키면 어미를 고쳤다(48%) → 근거 번호로 받고 코드가 꺼낸다.
> - "쟁점 다른 근거 쓰지 말 것" 규칙은 효과 0 → 작문 전에 카드를 빼는 **쟁점 게이트**.
> - 추출 도구를 안 부르거나 이상하게 포장했다 → 파싱 보정 + 강제 호출 1회(시민 되묻기 30 → 0).
> - "가게(개인)에 법인세법"이 프롬프트로 3회 연속 실패 → 후보에서 빼는 코드.
> - "7문장·반복 금지"를 무시하고 23문장을 썼다 → 2-gram 반복 제거 + 8문장 상한 + 출력 토큰 상한.
>
> 그 위에 **LLM3**(후보 조문 중 고르기만)를 세워 순서를 LLM1 → 검색 → LLM3 → LLM2 로 정했다. 근거 라벨은 권위 층별로 나누고 들어온 층만 말하게 했다. 출처 배지는 서버가 붙인다.

`_issue_gate` 는 **자문 경로에만** 건다. 판정형은 엔진이 판정하고, 관찰된 문제도 자문 쪽이었다. KB3 가 아닌 근거는 판정하지 않는다. 전부 빠지면 outcome `off_issue` + 안내 문구 + 세무사 연결 제안을 낸다. 뺀 근거는 `ragPassages` 에 `rank=None, issueFit='different'` 로 남긴다. `_CONDITION_RULE`(조건 붙은 법리)은 기존 규칙에도 들어갔다(PO 승인).

게이트의 성질은 이렇다. **분명한 경우(다른 제도 / 같은 쟁점)만 믿을 만하다.** solar 는 same/different 이분으로 기울고 related 를 거의 쓰지 않는다. 경계 판정은 함께 들어온 카드에 따라 바뀌었다. C30 의 같은 심판례 2건이 fusion 에선 different, KB3 단독에선 same 이었다.

## LLM3 — 관련 법령을 고르기만 한다 (10-07 ~ 10-08)

### 진단 — 지어낸 조문이 아니었다
KB3 단독 회차 시민 48문항에서 법령 인용 58개 중 **54개가 근거 카드에 있던 조문**이었다. 그런데 법령을 인용한 26턴 중 10턴 안팎이 무관하거나 설명이 틀렸다(C48 연기 → 가산세 감면 조문, C27 상증법 §45 를 '과세표준'으로, C43 조특법 §32 를 '세액감면 승계'로 등). 남의 사건 카드(당시 법 기준)의 조문을 질문 적합성 확인 없이 옮긴 것이다. 카드 기준 화이트리스트로는 못 잡는다.

### 구조
`api/law_select.py`(LLM3):
1. 후보 = 근거 카드 조문 + 질문 속 조문 + 조문 벡터 검색 6(최대 16).
2. Solar `emit_law_picks` 가 최대 4개를 고른다. `fit` 이 direct/supporting 인 것만 남긴다.
3. `[관련 법령]` 블록(현행 원문, 900자) + 인용 규칙을 작문에 넣는다.
4. 작문 뒤 본문과 `citations` 칸을 대조한다.

배선은 자문·판정 두 경로 모두다. 출처 배지는 고른 조문만 단다. 심판례 카드의 '조문:' 줄은 프롬프트에서 뺐다. numeric_guard 출처에 조문을 넣었다. `LAW_ONLY` — 사례 근거가 0건(off_issue · no_precedent)이면 조문만으로 일반 안내를 하고 outcome `law_advisory` 를 낸다. 조문 DB 와 파서는 → [KE](../3_지식엔지니어/KE_2026-10_W10_1004-1010.md).

### 작문 반복 루프와 출력 상한 (10-08)
지연을 재다 보니 꼬리는 작문 반복 루프였다. 같은 요청 6회 중 1회가 6,000토큰 · 44.8초까지 가서 `finish=length` 로 끝났다. 무응답 헤지(같은 요청을 한 번 더)로는 못 막았다. 두 요청이 같은 확률로 루프에 빠졌다(3/12 가 둘 다 45초 → 폴백).
- 작문 `max_tokens` 1,800.
- 잘린 도구 JSON 에서 온전한 문장을 복구하는 `parse_segments`.
- 무응답 헤지 20초, 챗 경로 상한 120 → 45초.
- 결과: 폴백 3/12 → **0/12**.

규칙으로 남겼다. 새 작문 호출에도 `hedged_create` + `max_tokens` + `parse_segments` 를 붙인다. 메모리 벡터 등 나머지 지연 대응은 → [BE](../4_백엔드인프라/BE_2026-10_W10_1004-1010.md).
