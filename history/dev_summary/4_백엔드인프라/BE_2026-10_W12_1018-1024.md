## 스키마 · 권한

### 0064 — 사용 현황 읽기 RPC (10-24)
M1(0061 방문 기록)·M2(0063 챗 턴 보강·질문 원문) 위에 관리자 화면이 읽을 함수를 붙였다. 모두 security definer이고, 안에서 `is_admin()`을 검사하며, authenticated만 실행할 수 있다.

| RPC | 돌려주는 것 |
|---|---|
| `admin_traffic_overview(p_days, p_source)` | KPI 6칸, 직전 기간, 퍼널, 경로표(경로+게시글), 일별, 지금 접속 중, 미연결 턴 |
| `admin_question_stats` | 세목, 유형, outcome 원값, 대화당 질문 수 |
| `admin_question_feed(…, p_outcomes text[], …)` | 가린 원문 목록 |
| `admin_handoff_demand` | 화면 이벤트 퍼널, 서버 사유별, 최근 요청 |
| `admin_list_campaigns` · `admin_save_campaign` | 게시 코드 목록·저장 |

집계 규칙은 내부 함수 한 곳에 모았다(`analytics._excluded_visitors`·`_visitors`·`_conv_visitor`·`_requests`·`source_of`·`host_group`). 이 함수들의 실행 권한은 0이다.

설계와 다르게 한 곳은 다섯이다.
- 결과 필터는 `p_outcomes text[]`다. 묶음은 화면이 풀어서 넘긴다. 묶음표를 SQL에 두 번 쓰지 않으려는 것이다.
- 등록 안 된 게시 코드만 있는 방문은 경로 `unregistered`("등록 안 된 코드")다. 코드를 나중에 등록하면 지난 방문도 그 경로로 잡힌다(조회 때 분류).
- 방문 기록과 잇지 못한 고객 챗 턴은 KPI에서 빼고 숫자만 따로 둔다(`unattributedTurns`).
- 연결 성립의 방문자는 대화 id로 찾고, 없으면 신청 회원이 로그인했던 첫 브라우저로 본다.
- 퍼널은 방문자 단위이고, 연결 수요 퍼널은 대화 단위다.

운영에 적용하고 `check_0064.py`가 모두 OK였다(0.3~0.4초). 백엔드 코드 변경은 없어서 배포 스크립트는 돌리지 않았다(a2c94f7, main·import-credigraph push). 화면은 → [FE](../5_프론트엔드/FE_2026-10_W12_1018-1024.md).
