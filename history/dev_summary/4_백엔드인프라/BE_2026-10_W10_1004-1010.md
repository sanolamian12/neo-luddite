### 호출 경로
`POST /api/rooms/{id}/agent-reply` — 토큰 · 방 참여 · 트리거 · 스위치를 서버가 확인한다(viewer 허용 경로). 선점한 뒤 BackgroundTasks 로 `room_agent.run` → `run_clinic(room_mode, agent_expert_id=방 세무사 uid)` 를 돌린다.

### 0045 가 생긴 이유
운영 확인에서 상대 쪽 브라우저의 **10초 백업 호출이, 스위치를 꺼 둔 동안의 메시지에 늦게 답했다.** 스위치를 다시 켜는 순간 지난 메시지들이 "답할 자격 있음"이 됐기 때문이다. 0045 로 켜는 시점에 그동안의 메시지를 skipped 로 닫았다. 적용 뒤 늦은 답은 0 이었다.

### 세무사 가입 승인 · 관리자 모니터링 — 0049 (10-08 밤)
**진단에서 알게 된 것**
- 세무사 계정은 `seed.sql` 직접 insert 로만 생겼다. 관리자 "새 평가자 등록"은 `auditors` 행만 만들어 **로그인할 수 없는 세무사**를 만들었다.
- 역할은 로그인 후 `profiles.role` 로 정해진다(JWT 아님). DB 에서 role 만 바꾸면 다음 동기화 때 `/audit` 로 간다. 0047 `guard_profile_identity` 는 security definer 안에서도 `auth.role()='authenticated'` 라 호출자가 admin 이면 통과한다.
- **P1** — `auditors_read` 가 로그인 사용자 전원이었다. 고객 화면 3곳(상담·제안·카드)이 세무사 이메일·전화·관리자 메모까지 받고 있었다. 고객이 실제로 쓰는 것은 이름뿐이었다.
- **P2** — 0048 `_purge_account` 가 `auditors`·`expert_profiles` 를 몰라, 세무사 삭제 후에도 카드가 남았다.
- `rag.chat_turns` 는 클라이언트 권한 0, 사용자 열이 없다. 463건 중 444건이 대화 행 없는 비회원 턴이었다.

### 세무사 승인 취소 — 0050 · 0051 (10-09)
**진단 — 권한 판정이 둘로 갈려 있었다**

| 기준 | 해당 권한 | role 만 바꾸면 |
|---|---|---|
| 역할 기준 | 원문 열람·수락·제안·풀·카드·스위치·에이전트·백엔드 쓰기 | 끊긴다 |
| domain_id 기준 | 방 읽기 · **메시지 쓰기** · 자기 앞 신청/제안 · 검수 CRUD · 코멘트 · 평가 · 리뷰 · 이의 | **남는다** |

강등자가 열린 방에 여전히 "세무사"로 글을 쓸 수 있었다. 그 밖에 0049 승인은 auditors 행이 이미 있으면 실패했고(재승인 불가), `expert_agents` 는 auth FK 가 없어 고아가 됐고, `kb3.documents.expert_id` 는 set null 이라 공용 승인 사례가 이름째 남았다.

**0050**
- `is_staff()`(auditor·admin) — anon 실행권을 둔다(9월 W08 의 Realtime 함정). 정책 **16개**에 세무사 쪽 조건으로 붙였다. `is_room_member`·`my_conversation_ids` 재정의.
- `auditors.status` check(active·suspended·revoked), `expert_applications.status` 에 revoked, 파기 cron 대상에 revoked(30일).
- `admin_expert_revoke_preview(domain)` · `revoke_expert(domain, reason)` — admin, 사유 필수(≤500), 관리자·비세무사·이미 취소 거부. 한 트랜잭션에서 차례로: 신청/제안/방 정리 + 우편 → draft 검수 cancelled + 이 사람 audit 이 전부 취소된 일감의 픽업 슬롯 반납 → 카드 삭제 → 세무사 사례 archived → 최근 승인 신청서 revoked(사유) → auditors revoked(이름 유지, 연락처 비움, 메모에 `[승인 취소 날짜] 사유` 누적) → role user.
- `review_expert_application` 재정의 — revoked 행이면 다시 살린다(메모에 `[재승인 날짜]`).

**0051** — `_purge_account` = 0049 본문 + `expert_agents` 삭제 + 세무사 사례 문서 삭제(chunks cascade). 원장은 보존한다.

운영 롤백 드라이런을 2회 했다. 0050 은 실제 세무사 데모 계정 하나를 취소해 본 뒤 롤백했고 다른 세무사는 영향이 없었다. 0051 은 가짜 세무사를 탈퇴시킨 뒤 롤백했다. 백엔드의 프로필 캐시가 60초라 강등 직후 최대 1분은 백엔드 쓰기 API 가 그 계정을 auditor 로 본다. 방이 이미 닫혀 있어 실제 피해는 없다. 앞으로 domain_id 로 권한을 주는 정책을 새로 만들 때는 세무사 쪽에 `is_staff()` 를 붙인다.
