## 1. 결과 한 줄

> **세무사가 샘플 형태를 승인했고, 키워드 29개로 487건을 모았다. 기계 기준은 통과했지만 요지 키워드 적중은 63% — 공제·일부 병의원 키워드는 판례 요지에 거의 안 나온다.**

## 2. 세무사 확인 (단계 2)

사용자가 `kb3_pilot_sample.md` 를 전달 → **"원하는 게 이게 맞다."** 건별 판정(≥16/20)·키워드 보강·근사중복 의견은 없었다 → 정성 승인으로 기록, 키워드는 설계 §4 표("병의원" 제외 29개) 그대로.

## 3. 본 수집 (단계 3)

- 명령: `collect --per-keyword 17 --total-cap 500 --max-pages 5` (29 × 17 ≈ 500). 1회차 ~35분.
- 1회차: raw 459. 서버가 응답 없이 연결을 닫은 것 15건 + `필요경비` 검색 실패 1 → **같은 명령 재실행(재개)** 으로 30건 채움 → raw 489, 미수 2.

## 4. 알게 된 것

1. **공제 질문은 판례에 없다** — 의료비 세액공제 0/10 · 월세 세액공제 0/17 · 교육비 공제 0/16 · 부양가족 0/17 · 부모 자녀 증여 1/17 · 한의원 0/17 · 의료업 1/17 · 성실신고 0/17.
   공통점: ① 검색에서 **제목 적중 0** → 본문 어딘가 한 줄로 걸린 무관 사건들. 판례는 다툼이라 공제 요건처럼 다툼이 드문 주제는 요지에 안 나온다. 파일럿의 "예규 쪽이 맞을 수 있다"는 열린 질문이 수치로 확인됨(범위 확장은 안 함).
2. 잡음 키워드로 들어온 건도 **요지 자체는 국세청 판례로 멀쩡하다** — 키워드 표지만 틀림. 임베딩 검색에선 표지가 안 쓰이므로 적재 범위는 단계 4 에서 precision 으로 정한다(후보 487/307/267).
3. **`HttpClient` 인코딩 추측 버그** — `resp.apparent_encoding` 이 짧은 UTF-8 JSON 을 키릴 인코딩으로 읽어 제목이 `мқҳлЈҢлІ•мқё…` 이 된 건 1건. `get`/`post`/`get_json` 에 `encoding` 인자(기본 동작 불변) 추가, 수집기는 `utf-8` 고정, 해당 건 재수신.
4. 세목 코드 추가: 210 조세범처벌 · 301 국세기본 · 302 국세징수(사해행위취소·배당이의 등 **국가가 원고인 민사**) · 306 부가가치세 · 311 종합부동산세 · 312 근로·퇴직(원천). 999 는 '기타' 코드라 관련 법령 보조 판정.
5. taxlaw 서버는 1.5초 간격에도 가끔 연결을 끊는다(1회차 ~3%) — 재시도 로직 대신 **재실행 = 재개**로 충분했다.
