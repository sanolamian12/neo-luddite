# 260909 · 지식베이스2(KB2) 2단 트리(대목/세목) + 문장 이동 + 편집 락 (로드맵 4.6단계)

## 배경

같은 날 진행한 KB2 AI 동적 카테고리 재구조화([[project_rag_kb_graph_visualization]] 계열
작업, `260909_지식베이스2_AI동적카테고리재구조화.md`) 결과를 실제 화면에서 확인하던 중,
사용자가 다음 두 가지를 요청:
1. 기존 지식베이스(v1)처럼 좌측 사이드바에 문서 트리 + 우측 콘텐츠 패널 구조로 통일 —
   다만 카테고리가 20개를 넘어가는 상황을 대비해 대목(상위 그룹) → 세목(문서) 2단 트리로.
2. 여러 세무사가 같은 KB2를 동시에 만지는 상황에서 "git merge" 개념이 없어 나중 저장이
   덮어쓰는 문제 — 문장 단위 비관적 락(수정 버튼 클릭 시 락 획득, 1분 무입력 자동저장,
   브라우저 크래시 대비 서버 TTL 자동회수) 요청.

Plan 모드로 들어가 Explore 에이전트 2개(락/롱프레스 패턴, KB1 트리 CRUD/다이얼로그 패턴)로
조사 후 설계 검토 목록을 정리하고, 사용자 확인 2건(기존 20개 세목의 그룹 편입 방법, 락
강제해제 방식)을 받은 뒤 구현.

## 설계 검토에서 확정한 것

- **기존 20개 AI 합성 세목도 그룹 편입 가능해야 함** — 문서(세목)에 "그룹 지정" 드롭다운을
  추가해 언제든 재배치 가능하게 함(신규/기존 구분 없음).
- **락 자동해제는 서버 TTL(5분)로** — 하트비트 인프라 없이, 락 레코드에 타임스탬프만
  저장하고 TTL 초과 시 다음 사람의 락 획득 시도가 자동으로 덮어씀. 이 레포의 기존
  "락" 개념(`line_feedback`/`session_evaluations`의 finalized/submitted 락, migrations
  0012/0013)은 영구 상태 전이형(하트비트/TTL 없음)이라 성격이 달라 재사용하지 않고 새로
  설계.
- 이동(move)·이름수정·그룹지정은 원자적 단발 작업이라 편집 락 대상에서 제외(텍스트 편집만
  락 걸림).
- 문장 이동 시 attribution(크레딧)은 유지 — 이동은 분류 정리이지 내용 수정이 아님(4단계
  "직접 수정"과의 차이).
- 삭제(대목/세목) 기능은 이번 범위 밖 — "삭제 전까지 0개로 남겨두자"는 요구를 "자동으로
  안 지운다"로만 구현.

## 구현

  `create_empty_document`/`rename_document`/`set_document_group`, `move_sentence`(버전+1,

  저장 성공 시 락도 같이 클리어. `backend/api/main.py`에 라우트 9개 추가(대목 CRUD, 세목
  생성/이름수정/그룹지정, 문장 이동/락/언락).
- **프론트**: `frontend/hooks/use-long-press.ts` 신설(이 레포 최초 롱프레스 훅, Pointer
  Events 기반). `frontend/components/audit/kb/kb2-view.tsx` 대규모 개편 — 좌측 대목→세목
  2단 트리(펼침/접힘), `[대목 추가]`/`[세목 추가]` 다이얼로그, 우측 헤더에 `[이름 수정]`
  다이얼로그 + `[그룹 지정]` select, 문장 카드에 롱프레스→이동 다이얼로그(`GripVertical`
  손잡이 아이콘에만 붙여 편집/버튼 클릭과 충돌 안 나게 분리), 수정 버튼이 먼저 락 획득
  시도 후 실패 시 "OOO님이 수정 중" 배지 표시, 편집 중 textarea onChange마다 60초 타이머
  리셋 → 무입력 시 자동저장+락해제, 컴포넌트 언마운트 시에도 편집 중이었으면 락 해제
  시도(탭 완전 종료는 못 잡음 — 그 경우는 서버 TTL이 안전망).
- `frontend/components/ui/dialog.tsx`(base-ui 기반, 그동안 실사용처 0건)의 첫 실사용 —
  대목/세목 추가, 이름 수정, 이동 피커 4곳에서 사용.

## 검증

프론트 `tsc --noEmit` + `next build` 통과(`/audit/kb2` 정적 라우트 정상). 백엔드는 로컬
서버로 실제 프로덕션 Supabase에 대해 전체 플로우를 curl로 검증:
- 대목 생성 → 그 아래 세목 생성 + 미분류 세목 별도 생성 → 이름 수정 → 그룹 재배치, 전부
  정상 반영 확인.
- 락: auditorA 획득 성공 → auditorB 시도 시 실패(`lockedBy: auditorA` 반환) → auditorA가
  이동 실행(락과 무관하게 원자적 처리 확인, version 1→2) → auditorA unlock → auditorB
  재시도 성공.
- 버전 히스토리: v2가 `editor_type='moved'`, `meta`에 `fromDocumentId`/`toDocumentId` 정확히
  기록됨을 확인.
- **TTL 자동회수**: DB에서 락 타임스탬프를 6분 전(TTL 5분 초과)으로 강제 UPDATE한 뒤
  auditorC가 락 획득 시도 → 성공, `list_sentences` 응답의 `effectivelyLocked`도 새 보유자
  기준으로 정확히 갱신됨을 확인.
- 기존 17개 활성 세목(재구조화 결과)이 새 `groupId` 필드(전부 `null`, 아직 미분류)와 함께
  정상 조회됨을 확인 — 회귀 없음.
- 브라우저 수동 스모크(다이얼로그 실제 렌더, 롱프레스 실제 터치/마우스 동작)는 자동화
  도구가 없어 미실시 — 사용자 직접 확인 필요.

## 후속 — "미분류" 17개 세목 자동 대목 배정

배포 후 화면 확인 중 사용자가 17개 세목이 전부 "미분류"인 것을 지적, 표준 세무 대분류로
자동 재분류할 수 있는지 요청. 하드코딩된 분류표 대신 Solar Pro의 세무 지식으로 판단하게
하는 것이 국내 AI 트랙 취지에 맞다고 판단해 작은 스코프로 바로 구현(17건이라 map-reduce
불필요, Plan 모드 생략).

- `backend/api/llm.py`: `propose_document_groups(documents)` 신설 — 세목 제목 목록만
  (내용 없이 가벼움) tool-forced 로 표준 세무 대분류 3~8개로 묶어 반환, `documentIds`는
  실제 존재하는 id로 enum 제약해 환각 방지.
- `backend/api/rag/kb2_taxonomy.py`: `auto_group_ungrouped_documents()` — `group_id is
  null`인 세목만 골라 제안받고 그대로 적용(이미 그룹 지정된 세목은 안 건드림).
- `POST /api/kb2/documents/auto-group` 라우트 + `frontend/services/kb2.ts`의
  `autoGroupKb2Documents()` + `kb2-view.tsx` 트리 헤더에 지팡이(Wand2) 아이콘 버튼 추가.

**실제 프로덕션 데이터로 실행 검증**: 기존 17개 활성 세목 전부에 대해 실행 →
"인건비·복리후생", "차량·자산 관련비", "사업용 카드·비용 구분", "공동 개원·시설 관련비",
"부가가치세·적격증빙", "기타·특수 상황" 6개 대목 생성, 16/17 세목 정확히 배정. 1건
("유튜브콘텐츠제작비용처리")은 모델이 놓쳐 미분류로 남았으나 데이터 유실은 아니고 —
다음에 버튼을 다시 누르면 "미분류만" 다시 대상이 되므로 자연스럽게 재시도 가능(설계
그대로 동작). 이 실행 결과는 되돌리지 않고 그대로 프로덕션에 반영해뒀다(정리 목적의
정상 동작이라 롤백 불필요).

## 후속 — 롱프레스 실사용 버그 수정 + Playwright로 실제 브라우저 검증

배포 후 사용자가 직접 클릭해보고 "손잡이를 눌러도 아이템이 안 따라온다"고 피드백. 원인은
이동 기능이 실제 드래그앤드롭이 아니라 "길게 눌렀다 떼면 다이얼로그가 뜨는" 방식인데
(이 레포에 DnD 라이브러리가 없어 계획 때 다이얼로그 피커로 결정), `GripVertical` 손잡이
아이콘의 히트 영역이 작아서 사용자가 드래그하듯 살짝만 움직여도 `onPointerLeave`로
타이머가 취소돼 아무 반응이 없었던 것.

**수정**: `frontend/hooks/use-long-press.ts`에 `setPointerCapture`/`releasePointerCapture`
적용 — 캡처 상태에서는 커서가 요소 밖으로 나가도 이벤트가 계속 이 요소로 온다. `onPointerLeave`
핸들러 자체를 제거(더 이상 필요 없음). 손잡이 UI도 `cursor-grab`(드래그를 암시) 대신
호버/액티브 배경 + 명시적 안내 문구("드래그 아님 — 누른 채로 잠깐 기다리세요")로 변경,
히트 영역도 살짝 넓힘. 부수적으로 안 쓰이는 `didFire` 반환값이 `{...longPress}` 스프레드로
DOM에 새어나가 React 경고를 내던 것도 제거(죽은 코드였음).

**실제 브라우저 검증**: 이 레포에 `chromium-cli`가 없어 Playwright를 직접 스크립트로
구동(`npx next dev --webpack` — Turbopack이 이 Windows 환경에서 postcss 서브프로세스
스폰에 실패해 계속 크래시해서 webpack 모드로 전환). `auditor2`로 로그인 → `/audit/kb2`
접속 → 손잡이를 마우스로 누른 채 700ms 대기 후 뗌 → "다른 세목으로 이동" 다이얼로그가
실제로 뜨는 것을 스크린샷으로 확인, 콘솔 에러 0건. 대조군으로 100ms 짧은 클릭은 다이얼로그가
안 뜸을 확인(오발동 방지도 정상). 이번 세션 처음으로 실제 브라우저 조작까지 검증 완료.

## 후속 — UI 4건 추가 개편 (그룹 이동 확정, 클릭 방식 변경, 배지 위치, 연결 끊기/재연결)

배포된 화면을 사용자가 직접 써보며 준 피드백 4건을 한 번에 반영:

1. **그룹 재배치를 [확정] 버튼 확인형으로** — 문서(세목) 전체가 다른 대목으로 옮겨가는 건
   되돌리기 까다로운 큰 변경인데, 지금까지는 select 값이 바뀌는 즉시 적용됐다. select는
   로컬 드래프트로만 바꾸고, 실제 이동은 "이 세목을 여기로 이동 [확정]" 버튼을 눌러야
   반영되도록 변경(`groupChoiceDraft` state 추가, 세목 선택이 바뀌면 드래프트도 리셋).
2. **손잡이(점 6개)를 롱프레스 대신 클릭으로** — 지난 롱프레스 UX 자체가 다시 헷갈린다는
   피드백. 이동 다이얼로그를 여는 트리거를 단순 클릭으로 변경, 이제 아무 데도 안 쓰이는
   `frontend/hooks/use-long-press.ts`는 삭제(죽은 코드).
3. **저자 기여 배지를 v{n} 배지 바로 옆으로** — 기존엔 본문 아래 별도 줄에 있던
   `auditorId·weight%` 배지를 상단 배지 줄(v버전, 잠금 상태 옆)로 이동.
4. **연결 끊기/재연결 토글 + 사유 필수 입력** (신규 기능, 배선실의 `rag.passages` 재연결
   패턴을 kb2.sentences 에 적용) — `[버전 히스토리]` 오른쪽에 `[연결 끊기]`/`[연결]` 토글
   버튼 추가. 클릭하면 사유를 묻는 `StatusReasonDialog`가 뜨고, 사유 없이는 확정 버튼이
   비활성화된다. 확정하면 즉시 상태 전환 + `sentence_versions`에 `editor_type='retired'`
   또는 `'reconnected'` + `meta.reason`으로 기록 — 누가 왜 끊었는지/왜 다시 연결했는지
   버전 히스토리에서 추적 가능. `retired` 상태 문장은 카드가 옅어지고 "연결 끊김" 배지가
   붙지만 목록에서 사라지진 않음(배선실과 동일 철학 — 삭제 아님).

**스키마** (`supabase/migrations/0022_kb2_sentence_status.sql`): `kb2.sentences.status`
컬럼 추가(`active`/`retired`), `kb2.sentence_versions.editor_type` 체크 제약에
`'retired'`/`'reconnected'` 추가, `kb2.match_sentences()` SQL 함수가 `s.status='active'`도
같이 필터링하도록 갱신(재합성·A/B 검색 경로 전부 자동으로 반영, 코드 변경 불필요).

**백엔드**: `kb2_store.py`에 `set_sentence_status(sentence_id, status, editor_id, reason)`
추가(내용은 그대로 두고 status만 전환 + version+1 + 이력 기록), `POST
/api/kb2/sentences/{id}/status` 라우트 신설.

**실제 검증**: 백엔드 curl로 연결 끊기→버전 히스토리에 `retired`+사유 확인→재연결→
`reconnected`+사유 확인, `kb2.match_sentences()` SQL 정의에 `s.status='active'` 필터
반영 확인. Playwright로 실제 브라우저 4건 전부 확인 — ①클릭 한 번에 이동 다이얼로그
