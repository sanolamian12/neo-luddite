## 무엇이 생겼나
세무사가 상담 신청을 **수락하면 그 사장님과의 1:1 채팅방이 앱 안에 열린다**(설계 D3 — 연락처는 부가 정보로 남는다).
양쪽 신청 상세에 `[채팅방 열기]`(안 읽은 수 표시)가 생기고, 사장님은 `/rooms/<id>`, 세무사는 `/audit/rooms`(목록 + 방)에서
같은 화면으로 이야기한다. 메시지는 실시간으로 오가고, 세무사 사이드바 "채팅방"과 사장님 "세무사 상담"에 안 읽은 수가 뜬다.
방을 열면 읽음 처리되고 뱃지가 준다. 본인 메시지는 지울 수 있고(상대에겐 "삭제된 메시지"), 방은 양쪽 누구나 닫을 수 있다(닫힌 방은 읽기만).

## 결정
- **방 종료 = 양쪽 누구나 + admin**, **대화당 열린 방 3**(사용자, 착수 전 — 설계 §10-2·4).
- 방은 DB 함수 하나(`open_room`)로만 열리고, 사용자가 직접 부를 수 없다 — 수락 전이 안에서만 불린다. 출처(수락된 신청)를 검증한다.
  같은 세무사가 같은 대화를 다시 수락하면 닫힌 방이 다시 열린다(이전 대화 유지). 상한을 넘으면 **수락 자체가 롤백**된다.
- 보낸 사람·역할·시각은 DB 트리거가 호출자로 정한다(클라이언트 값 무시 — 사칭 불가). admin 은 읽기만.
- 알림 메일은 **받는 사람마다 방당 1건**(처음 받은 메시지 때만), 그 뒤는 뱃지만. 기존 수락 메일은 문구만 "채팅방 열기" 안내로.

## 도중에 잡은 것 (전부 고쳤다)
1. **드라이런**: `open_room` 에서 뒤따른 `count(*)` 가 PL/pgSQL `FOUND` 를 덮어써, 없는 방을 "다시 열기" 분기로 보냈다(방이 안 생김) → 조회 직후 플래그로 잡아 둠.
2. **E2E**: 세무사가 신청 목록 "대기" 필터에서 수락하면 그 신청이 필터에서 빠지며 상세가 사라져 `[채팅방 열기]`에 못 간다 → 전이 후 선택 유지.
3. **E2E → A/B**: 방 INSERT 는 오는데 **메시지 INSERT 가 세무사 화면에 안 왔다.** Node 클라이언트 단독으로는 온다.
   anon 구독자를 하나 붙이면 로그인한 세무사도 **못 받는다**(A/B 확정). 모든 페이지는 로그인 전에 anon 으로 한 번 구독하는데,
   메시지 정책이 부르는 `is_room_member()` 를 anon 에서 revoke 해 두었다 → Realtime 의 anon 정책 평가가 권한 오류 → **그 이벤트가 통째로 사라짐**.
   적용 뒤 `grant execute ... to anon`(사용자 확인. anon 이 부르면 항상 false라 열람 범위는 그대로), 파일도 고치고 `--fresh` 로 파일=DB 일치 확인.
   **교훈: RLS 정책이 부르는 함수는 anon 실행 권한을 빼면 안 된다.**
4. **E2E → 프레임 계측**: 페이지를 연 지 몇 초 안에 생긴 방·닫힘이 유실. 채널의 `SUBSCRIBED` 는 join 응답일 뿐이고,
   서버가 `"Subscribed to PostgreSQL"` 을 보내야 변경이 흐른다 — 로그인 직후 **2.5~3초**, 채널 많은 새 페이지에서 **7초** 늦다(실측).
   9/21 (c)에서 고친 "구독 → 적재" 순서도 이 틈은 못 막았다. → `makeCollectionSync` 에 `waitForPostgresReady` 옵션:
   준비 신호 뒤 적재, 준비가 5초 타임아웃보다 늦으면 **준비 시점에 한 번 더 적재**. 채팅방·메시지만 켰다.
5. 방어 fetch: `[채팅방 열기]` 는 방이 안 보이면 직접 조회(0·1.5·4초), 방 화면은 탭 복귀·전송 실패 때 다시 당긴다(설계 §7 "열 때 한 번 더").
