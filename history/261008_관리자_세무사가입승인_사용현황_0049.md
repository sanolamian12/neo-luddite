## 3. 진단에서 알게 된 것

- 세무사 계정은 `seed.sql` 직접 insert 로만 생겼고, 관리자 "새 평가자 등록"은 `auditors` 행만 만들었다(로그인 불가 세무사).
- 역할은 로그인 후 `profiles.role` 로 정해진다(JWT 아님) → DB 에서 role 만 바꾸면 다음 동기화 때 `/audit`.
  0047 `guard_profile_identity` 는 security definer 안에서도 `auth.role()='authenticated'` 라 **호출자가 admin 이면 통과**.
- **P1**: `auditors_read` = 로그인 사용자 전원 → 고객 화면 3곳(상담·제안·카드)이 registry 구독으로 세무사 이메일·전화·관리자 메모까지 받고 있었다. 고객이 실제로 쓰는 건 이름뿐.
- **P2**: 0048 `_purge_account` 가 `auditors`·`expert_profiles` 를 몰라, 세무사 삭제 후에도 `list_experts` 카드가 남았다.
- `rag.chat_turns` 는 클라이언트 권한 0 · 사용자 열 없음. 463건 중 444건이 대화 행 없음 = 비회원 턴.
- 고객에게는 일반 우편함이 없다(상담·제안 화면 안에서만) → 신청 결과는 `/expert/apply` 상태로 보여 주고, 승인 메일은 세무사 우편함으로.
