## 2. A(b) — query 임베딩 1회 공유 (✅ 3ffb011)

- `Retriever.retrieve()` 에 `qvec` 키워드 추가. `SupabaseRetriever`·`Kb2Retriever`·`KbdictRetriever` 는 받은 벡터가 있으면
  임베딩을 건너뛴다. `FusionRetriever`·`HybridRetriever` 는 갈래를 펼치기 전 `_shared_query_vector()` 로 한 번 만든다.
- 임베딩 실패 → 빈 결과(graceful 동일). 갈래가 전부 `NullRetriever`(DB 미설정)면 임베딩을 부르지 않는다.
- **검증**: HEAD 버전과 새 버전을 같은 캐시 임베딩으로 4질문 × {fusion, hybrid, rag, kb2} 비교 → corpus·id·score·순서
  **16/16 동일**, fusion 임베딩 호출 **3 → 1**. 벤치(`bench_fusion.py`)의 `embeddings.embed_query` 캐시 패치도 그대로 동작.
- 의미: 전시 동시 부하(B)에서 같은 Upstage 키에 쌓이는 호출을 턴당 2회 덜어낸다.

## 3. A(a) — 판정형 경로 혼입 측정 (통과)

### 3.1 설계
- P4·P7 혼입 측정은 전부 자문 경로(`write_advisory`)였다. 판정형은 엔진 판정이 프롬프트 위에 박히고 근거는 법리 보강으로만
  들어가 모양이 다르다.
- 결정변수를 모두 말한 질문 3개 — 접대(조건부) · 업무용승용차(안분) · 복리후생(전부인정). `extracted` 를 손으로 고정해
  엔진을 결정적으로 돌리고, 근거는 **제품 팩토리**로 rag·fusion 을 뽑아 JSON 으로 고정(`a_fixtures.py`).
- `write_segments` 만 32회 × 2경로 × 3질문 = 192회, 4워커(`a_verdict_mixing.py`).
- 서버 `.env` 를 SSH 로 먼저 확인: `RAG_MIN_SCORE=0.50`, `RAG_SOURCE`·KB2/KBDICT/FUSION 변수 없음(=코드 기본값) — 로컬과 동일.

### 3.2 결과

1차 정규식은 양쪽을 과대 집계했다(엔진 근거 문구 "한도 초과분은 부인됩니다", 올바른 문장 "한도와 무관하게"까지 잡음).
걸린 문장을 **전부 눈으로 본 뒤** 규칙을 좁혀 재분류(`a_reclassify.py`).

| 질문 (엔진 판정) | 혼입 = 남의 사안 고유 사실 (rag / fusion) | 판정·법리 모순 (rag / fusion) |
|---|---|---|
| 접대 (조건부) | 0 / 1 (일반어 "법인카드") | 0 / 0 |
| 승용차 (안분) | 1 / 1 ("가족 여행") | **4 / 2** — 운행기록부가 있는데 1,500만원 한도 적용 |
| 복리후생 (전부인정) | 1 / 0 ("15명") | 2 / 0 (1차 정규식) |

- 1차 원시 수치로도 방향 같음(혼입 23 vs 22).
- **판정형은 자문형보다 혼입이 훨씬 적다**(자문 rag 25/32 대비 여기 0~1/32). 엔진 판정이 사실관계를 붙잡아 주는 것으로 보인다.
- 지연: 중앙 2.9~3.6s. fusion 쪽 최대 124.5s 1회 = P7 C 에서 본 동시 호출 멈춤과 같은 모양.
- 승용차 fusion 모순 2건 중 하나(run 21)는 **kb2 의 틀린 문장을 "검수 선례"로 인용** → §5 로 이어짐.

### 3.3 곁다리: "회원권 명의"
복리후생 답변 32회 중 rag 21·fusion 17회에 "회원권 명의"가 나왔다. 혼입이 아니라 **엔진 필요증빙 목록**(`rule_복리후생비`)에서
온 것 — 명절 떡값에도 회원권 명의를 요구한다. 근거 코퍼스의 세무사 코멘트가 이미 이것을 "환각 증빙"으로 지적해 두었다 → §6.

## 5. KB2 합성이 틀린 [AI 답변]을 옮겨 적던 문제 (✅ f26da92 + 은퇴 1건)

### 5.1 발견
fusion 근거의 kb2 문장 "운행기록부를 작성하여 업무사용비율을 입증할 경우, 연 1,500만원 한도 내에서 실제 사용비율에 따라
인정받을 수 있다"는 **법리 오류**다(운행기록부 작성 시 한도 무관·실제 비율, 1,500만원은 미작성 시 간편 한도 — 소득세법 시행령
§78의3). 원 번들의 [AI 답변] 문장이었고, 같은 번들 세무사 코멘트는 "1,500만 원 한도의 의미를 반대로 이해했습니다"라고 지적했다.
사용자가 세무사에게 공유해 수정 필요를 확인했다.

### 5.2 규모 — 활성 446건 중 최소 30건 (`kb2_ai_inherit_scan.py`, 읽기 전용)
판정(근사): kb2 문장이 출처 번들의 [AI 답변] 어느 문장과 문자 bigram 포함률 ≥ 0.6, 코멘트 쪽보다 +0.15 이상, 출처 코멘트에
오류 태그. 예: "폐기물 처리비는 업무 전용 회선별 사용분에 대해서만 인정"(통신비 룰 오염), "사업용·개인 카드를 섞어 쓰면 비용
인정 불가"(코멘트: 결론이 틀림), "포르쉐 카이엔을 업무용으로 등록하면 전액(150,000,000원)". 확인된 1건은 태그 없는 세션 평가
출처라 이 스캔에 안 걸렸다 → **30은 하한.** 후보엔 올바른 문장도 섞여 있다(조문을 바르게 인용한 것 등).

### 5.3 원인
재구조화(`run_dynamic_restructure`)는 활성 rag.passages 전체를 매번 처음부터 합성한다. 합성 프롬프트 규칙 5("모든 묶음을 최소
한 문장의 근거로")의 커버 압력 아래, 코멘트가 짧으면 모델이 긴 [AI 답변]에서 문장을 뽑았다. 프롬프트는 "세무사가 인정한
지식"이라고만 했지 코멘트가 AI 답변을 뒤집는다는 규칙이 없었다. 수동 은퇴는 재구조화 뒤에도 유지되지만(`list_human_touched_sentences`)
**같은 주장이 새 system_synthesis 문장으로 다시 생긴다.**

### 5.4 수정 — 드라이런으로 고름 (`kb2_prompt_dryrun.py`, 후보 출처 13문서 × 2회, DB 쓰기 0)
