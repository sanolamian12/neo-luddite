## 1. A — 근거 코퍼스 분포 계측 (✅ 배포)

### 1.1 결정
- 저장 형태(사용자): **원시 목록 + 개수 둘 다.** 개수만이면 "왜 그 청크가 들어왔나"를 못 되짚는다(0027의 교훈).

### 1.2 구현 (97b3b20)
- `Passage.id` — rag/kb2/kbdict 세 store가 이미 id를 돌려주고 있었다. 프롬프트에는 안 쓰는 계측 전용 필드.
- `pipeline._corpus_distribution(passages)` → `({"kb2":2,"rag":2,"kbdict":1}, [{corpus, sourceKind, score, rank, id}…])`.
  rank = **프롬프트에 박힌 최종 순서**(1-based). 본문은 싣지 않는다(원본 테이블에 있고, 복사하면 갈라진다).
- `ChatMeta.ragCorpora` / `ragPassages` — Optional, `response_model_exclude_none`. 프론트는 `chatMetaSchema`가
  `.passthrough()`라 변경 불필요.
- `_recorded()`는 meta 값을 그대로 넘긴다(계측이 따로 재계산하면 화면과 DB 분포가 갈라질 수 있다).
- **0033** `rag.chat_turns.rag_corpus_counts` / `rag_passages` jsonb + GIN(`jsonb_path_ops`, `@>`·`?` 질의용).
  검색 0건 = `{}` / 검색 미도달(되묻기) = `null` — 0027 `rag_searched`와 같은 이유로 다른 사실이다.

### 1.3 검증
- 오프라인: helper 정합, exclude_none 동작(미도달 갈래는 필드 자체가 빠짐).
- 프로덕션 DB **읽기 전용** 실검색: 세 코퍼스 모두 id가 실려 나옴.
- 0033: 프로덕션 **롤백 트랜잭션**에서 DDL·3종 insert(분포/0건/미도달)·집계 질의(`? 'kbdict'`, `jsonb_each` 합계,
  `jsonb_array_elements` 평균 점수)·인덱스 확인 → 롤백 후 컬럼·행 0 확인 → `apply_migration.py` 적용.
