## 2. 그런데 지난 세션은 왜 40/38/75% 를 봤나

"모델이 갈 곳 없다고 판단한 건"과 "물어보지도 못한 건"이 똑같이 보였다.

> 9/11 오전의 "같은 결과 = 그 단계가 둘 다 안 돌았다" 교훈과 같은 계열이다.

이로써 갈래가 하나 정리됐다: **미분류 ~44% 는 안정적이고 실재하는 값**이다(회차 편차가
아니다). 남은 커버리지 누수는 merge 품질 문제로 확정된다.

## 3. 조치 (커밋 `58a981f`)

### ① 실패 ≠ 미분류 — `llm.classify_dynamic_category`

반환을 `(카테고리, 실패사유)` 튜플로. 사유는 `RateLimitError` 같은 예외명,
`no_tool_call`(tool_choice 로 강제했는데 안 지킴), `off_enum`(목차 밖 레이블).
모델이 진짜로 '미분류'를 고른 경우만 사유가 `None` 이다. 재시도도 1 → 2.

### ② 나쁜 회차 가드 — `kb2_taxonomy._assess_run`

`archive_all_active_documents()` **직전**에서 호출한다. 거기가 되돌릴 수 있는 마지막
지점이다 — 카테고리 생성도 archive 뒤라, 중단 시점엔 아무것도 안 건드린 상태다.

중단 조건 두 개:

| 조건 | 값 | 근거 |
|---|---|---|
| 호출 실패율 | > 2% | 순차 실측 0/600건이라 평시값이 0. 실제 사태는 16% 로 자릿수가 다르다 |
| 배정률 | < `max(35%, 직전세대×0.75)` | 상대 25% 하락 = 관측 편차(3.8%)의 6배 |

기준선은 신설한 `kb2_store.get_latest_generation_job()` — `status='done'` **이면서
coverage 가 있는** job 만 본다. 기존 `get_latest_finished_job` 은 error 를 포함해서,
**가드가 한 번 중단시키면 그 error job 이 기준선이 돼 가드가 스스로를 무력화**한다.

설계를 정한 비대칭: 좋은 회차를 한 번 놓치는 비용은 "내일 밤 다시 돌린다"지만, 나쁜
회차를 한 번 통과시키는 비용은 "세대가 사라졌다"다. 그래서 애매하면 중단 쪽으로 기운다.

중단된 회차는 `stage='aborted'` + 계측을 함께 남긴다. 스케줄러는 `status='error'` 를
재시도하지 않는다(새벽에 조용히 API 예산을 태우지 않는다).

### ③ 화면 — "실패"가 아니라 "중단됨"

가드가 멈춘 회차는 빨간 "실패"가 아니라 호박색 **"중단됨 — 기존 세대를 지켰습니다"**
로, 이번/직전/요구 배정률과 실패 사유를 함께 보여준다. 제일 중요한 한 줄은 "기존 세대는
그대로다"이다 — 재구조화 실패 화면을 보면 KB 가 비었을까 봐 놀라는데 가드는 정확히 그
반대를 한 것이다. 통과한 회차도 실패 건수가 0 이 아니면 노출한다.

### ④ 맵 단계 `maxItems` (로드맵 §7 "다음 세션 후보" 3번)

맵 도구 스키마에 `minItems 3 / maxItems 6`. 산문으로 "3~6개"라고만 말해 배치당 18~32개를
내던 것을, 리듀스에서 통한 처방과 같게 맞췄다.

### 가드 검증 — 실제 기준선(57.9%)에 대고 8개 시나리오, 읽기 전용

| 시나리오 | 판정 |
|---|---|
| 51.3 / 53.3 / 57.9% (실측 정상) | 통과 |
| 27.4% / 14.5% / 0% (실측 붕괴) | **중단** |
| 배정률 정상 + 429 16% | **중단** |
| 배정률 정상 + 429 1건 | 통과 |

### 읽는 법 — 커버리지는 **개선되지 않았다**

- 커버리지 54.0% → 52.1%(−1.9%p), 배정 57.9% → 55.9%. 상대 3.5% 하락으로 **측정된 회차
  편차(3.8%) 안**이다. 즉 **좋아지지도 나빠지지도 않았다** — `maxItems` 는 미분류를
  건드리지 못했다. (그리고 §1 의 규칙대로, 1회 측정으로 "나빠졌다"고도 말할 수 없다.)
- **가드가 정상 회차를 막지 않았다**(55.9% vs 요구 43.4%). 오탐 없음이 확인됐다.
- **분류 호출 실패 0건** — 프로덕션 순차 경로에서 §1 의 예측(0/600)이 그대로 재현됐다.
  이제 이 값이 계측에 남아, 다음에 429 가 나면 '미분류'에 섞이지 않고 바로 보인다.
- 지난 세션 성과는 유지: 합성 인용률 **93.1%**(215/231), 환각 id **0**.
- 완주 1013초 → **664초**(−34%). 맵이 배치당 후보를 ≤6개만 내니 리듀스 입력이 줄었다.

### 남은 문제는 선명해졌다 — merge 가 **근사 동의어**를 못 접는다

배정 0건 세목이 4개 → **6개**로 늘었고, 겹치는 레이블이 그대로 살아남았다:

- 복리후생 계열 **4개**: `인건비·복리후생`(26) / `복리후생비`(18) / `복리후생비처리`(10)
  / `피부시술복리후생비`(6)
- `접대비`(14) / `접대비인정`(3)
- `업무용승용차특례`(14) / `업무용승용차`(10)
- `인테리어비용처리`(12) / `인테리어·개인카드`(0) / `인테리어적격증빙`(0) / `적격증빙`(11)
- 질문 하나짜리 잔존: `6세이하자녀`(1), `육아휴직수당과세`(4), `1세대1주택비과세`(0),
  `수도권공공기관이전`(0)

merge 프롬프트는 "의미가 겹치거나 동의어인 카테고리는 하나로 합치라"고 이미 말하고
있다. **개수 제약(minItems/maxItems)은 잘 듣지만 의미 병합은 안 듣는다** — 30개를 채우라고
하면 근사 동의어를 쪼개서라도 30개를 만든다. 이게 지금 미분류의 실체다: 상담이 갈 곳이
없어서가 아니라, **갈 곳이 네 갈래로 쪼개져 있어서** 분류기가 고르지 못한다.
