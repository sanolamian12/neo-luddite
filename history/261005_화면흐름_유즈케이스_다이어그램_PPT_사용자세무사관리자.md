## 4. 만든 방법

- 화면 흐름 조사: Explore 에이전트 3개를 역할별로 병렬 실행(사이드바·페이지·컴포넌트·services). '참고' 그룹 정의는 `components/layout/expert-sidebar.tsx`, 관리자 메뉴는 `components/layout/admin-sidebar.tsx`.
- 생성: Node `pptxgenjs` 스크립트. 노드 좌표와 직교 배선 경유점을 슬라이드마다 직접 지정했고, 마름모·타원은 경계까지 화살표 끝을 잘라 붙였다. 메뉴만 보여 주는 슬라이드(9·15장)는 허브 배치를 썼다. 폰트는 맑은 고딕.
- 검증: PowerPoint COM 으로 PDF 변환 → `pdftoppm` 이미지로 전 장 확인. pptx 스킬의 `validate.py` 통과(`defusedxml`·`lxml` 을 전역 pip 에 설치).
- **생성 스크립트는 세션 scratchpad 에만 있다(레포에 없음).** 화면이 바뀌어 다시 만들려면 스크립트를 새로 쓰거나 PPT 를 직접 고쳐야 한다.

### 함정

- **ELK 자동 배치(elkjs)는 버렸다.** 순환 엣지 때문에 흐름이 오른쪽→왼쪽으로 뒤집혔다. 줄바꿈(wrapping) 옵션은 일부 그래프에서 오류가 났고, 성공해도 선이 끊겨 읽기 어려웠다. 노드 10~14개짜리 흐름도는 좌표를 직접 주는 편이 빠르고 깔끔했다.
- PowerPoint 마름모 도형의 글상자는 도형 폭의 절반 정도다. 도형에 글자를 직접 넣으면 줄이 꺾인다 → 도형 위에 별도 글상자를 겹쳐 올렸다.
- 이 PC 에는 LibreOffice 가 없다. 렌더 QA 는 PowerPoint COM(`Presentations.Open` → `SaveAs(..., 32)`)으로 했다.

## 5. 그리면서 드러난 것 (20장과 같은 내용)

- **관리자 '메시지'를 남길지 정해야 한다.** 이 메뉴는 검수 결과(Audit)에 대한 이의제기를 다룬다. 이번에 뺀 검수 흐름에 묶인 기능인데 지금은 남겨서 그렸다(사용자 미결정). 상황실 카드 다수도 빠진 화면(검수실·정산·후보 풀·Task)으로 연결된다.
- **관리자 전문가 상세의 '우편 보내기'는 404 다.** `/admin/mail/new?to=<id>` 로 가지만 그 경로가 없다. 다이어그램에는 회색 점선으로 표시했다.
- **관리자 메뉴 이름과 화면 제목이 다르다.** 전문가 관리 → '평가자 관리', 메시지 → '이의제기', 공지사항 → '발송함', 상담 신청 → '상담 운영'.
- 관리자 상황실에는 상담 신청·공지사항으로 가는 바로가기가 없다(사이드바로만 이동).
- 관리자는 상담 신청을 수락·거절·완료할 수 없다(읽기 전용). 진행 중인 제안 거절·철회, 채팅방 강제 종료, 풀 동의 강제 철회만 할 수 있다.
- 관리자 '새 평가자 등록'은 즉시 활성 계정을 만든다. 초대 메일이나 인증은 없다.
- 사용자 채팅의 되묻기는 버튼이 아니라 일반 문장이다. AI 답변 속 세무사 연결 블록은 읽기 전용이고, 실제 신청은 채팅 아래 '이 대화로 세무사 상담 준비하기'(로그인 사용자)에서만 한다.
- 세무사 '내 에이전트' 데이터는 localStorage 에만 저장된다. 미리보기는 LLM 을 부르지 않는 규칙 시뮬레이션이다.
- 프로토타입 모드에서는 상담 수락·거절·완료, 연결 요청, 채팅방 닫기, 공개 사례 목록, LLM·인프라 연결 점검이 동작하지 않는다(가짜 백엔드 `lib/prototype/backend.ts` 미지원). 다이어그램은 의도된 동작(마이그레이션 0035·0038 기준)을 그렸다.
