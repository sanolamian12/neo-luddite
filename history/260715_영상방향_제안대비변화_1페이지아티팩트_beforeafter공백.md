## 한 줄 요약

프로덕트 소개 영상에서 무엇을 부각할지 정하기 위해 **초기 제안서(4/24) ↔ 실제 구현(7월)** 을 전수 대조했다. 결론: 영상은 제안서가 아니라 **3개월간 이동한 정체성**("빈 RAG로 출발해 세무사 코멘트로 자라는 살아있는 지식 + 존속연동 기여·정산")을 말해야 한다. 팀 공유용 **1페이지 웹카드**를 만들어 게시했다. 다만 카드가 완성되려면 **Before/After 비교**가 필요한데, **현재 실험은 "Before"까지밖에 없다** — RAG OFF vs ON 짝지은 임팩트 측정(260714 P1)이 미실행이다.

## 1. 제안서 대비 변화 종합 (영상 정합용)

### 정체성 이동
- **제안서(4/24)**: 비정형 세무문서(PDF·스캔) → Document Parse 정형화 + N명 검수로 만드는 **학습데이터 생산 플랫폼**.
- **실제(7월)**: 실사용 챗 상담 → 5분 정지 스냅샷 → 공용 검수 보드 → 최종승인 → **RAG로 자람**. 그 지식이 **살아있는 동안에만 기여·정산이 기계적으로 발생**. 창고 메타포(하차장/일감/검사실/배선실/RAG)로 재편.

### 원 기능 6개 → 실제

| 제안서 문구 | 실제 구현 |
|---|---|
| 문서(PDF·스캔) → Document Parse 정형화 | **폐기.** 라이브 챗 상담의 5분 정지 스냅샷(pg_cron)이 데이터 원천. 엑셀 인테이크도 `260704`에 전량 폐지 |
| N명 독립 초안 + 순환 검수 자동 배정 | **공용 검수 보드**(3인 단체방)에 코멘트 축적, 수동 픽업(자동배정 없음) — `260705` |
| Solar Pro 자동 불일치 탐지·판정 | **결정적 규칙엔진**(`clinic_expense_engine`) 판정 권위 + LLM은 추출·작문만 + 인간 문장별 검수 **두 게이트**(saved→finalized, `260707`) |
| 합의 정답 + 재사용 규칙 추출 | 최종승인본 → `rag.passages`. 규칙 증류(세션총평→원리)는 **설계만, 미구현**(`260711`) |
| 크레딧 산정 + 정산 대시보드 | 구현 + **존속연동으로 진화**(`260707`) = 특허 독립항 심장 |
| 민감정보 비식별화 + RBAC | RBAC(RLS 3중 방어, `260714 3대방어`)는 구현 · **비식별화는 미구현** |

### 창발한 새 개념 (제안서에 없던 것)
- **RAG 자체**(pgvector, Upstage 임베딩 4096d) — `260703`
- **살아있는 기여도/존속연동 정산** — `260707`. 배선실 연결끊기 → 기여도 자동 감소(라이브 auditor 2→1 실증)
- **특허 출원 초안** — `260713`. 진보성 핵심 = "(d)검색 후보 제외 + (e)적산 중단이 하나의 상태 전환으로 동시에 발생"(도4가 심장). 7/31 본선 공지 전 출원 필요(특허법 §30)
- **감사모드 세무상담 평가 + 반복오류패턴 P1~P12** — `260711`·`260712`
- **RAG 자문 경로(P0)** — `260714`. `기타` 질문에 판정 대신 코멘트 근거 자문

## 2. 영상 강조 방향 (확정)

### 부각시킬 3가지
1. **살아있는 기여도 — 버려지면 기여가 사라진다** (제품의 심장/특허 독립항). 기여도가 "약속·재량"이 아니라 **시스템 상태에서 기계적으로 파생**. 경쟁사(삼쩜삼·AI세무사)의 "RAG+전문가 검증"과 구조적 차별. → 비주얼: 특허 도4(활성 곡선이 토글 OFF에서 평평).
2. **빈 RAG로 출발 → 코멘트로 자란다** (Before/After가 눈에 보임). 판례 전량 사전 인덱싱 **의도적 금지**. RAG 세일즈 포인트 = **"답변 정확도"가 아니라 "답할 수 있는 범위"**(판정은 엔진 권위라 안 바뀜).
3. **왜 인간 검수가 가치 있는가** (정량 증명). 감사 대상 AI 100건 법률정확성 평균 **1.24/5**. 배우자 급여 "전부 인정 6,000만원" 자신 있는 오답 → 근거 있는 자문 교정 스토리.

### 조심할 것 (과장 방지)
- ❌ Document Parse / PDF·스캔 OCR — 제품에 없음
- ❌ 민감정보 비식별화/PII 마스킹 — 미구현
- ❌ LLM 자동 판정 / 자동 배정 — 실제는 규칙엔진 판정 + 수동 픽업
- ❌ 규칙 증류(세션총평→원리) — 방향만, 미착수. "로드맵"으로만
- ⚠️ RAG를 "정확도 향상"으로 말하지 말 것 → **"답변 가능 범위 확대"**가 실측 부합

### 권장 데모 시퀀스 (라이브 실화면)
1. 사장님(viewer) Upstage Solar 상담 → 5분 뒤 스냅샷 자동 생성
2. 운영자(admin) 하차장 → 일감 발행
3. 세무사 3인(auditor) 한 화면 문장별 상호검수 → 두 게이트 통과
4. 승인 순간 RAG 적재 → 재상담 시 답변 범위 확대(Before/After)
5. **클라이맥스**: 배선실 연결끊기 → 기여도 실시간 감소 = 도4의 실사판

## 4. ★ Before/After 공백 — 카드 완성의 남은 조건 ★

**사용자 지적**: "1페이지는 Before/After 비교까지 끝나야 완성. 실험은 Before 부분까지밖에 없다."

### 지금 카드에 실린 수치의 실제 성격 (정직한 재확인)
- **1.24/5**(법률정확성) = 감사 대상 AI 품질 베이스라인 = **Before**(존재, `260712`).
- **0→362 passage** = 적재량 성장(사실이지만 A/B 대조가 아니라 누적치).
- **미지원 11→0** = 자문 경로 **전/후** 비교(`260714`)지, RAG **OFF vs ON**의 짝지은 임팩트 측정이 아니다. 같은 코드에서 `기타` 분기를 열기 전/후일 뿐.

→ 즉 **"세무사 지식이 있고/없고(RAG ON/OFF)로 무엇이 달라지는가"** 라는 진짜 Before/After는 아직 안 돌렸다. `260714` P1로 정의만 돼 있고 미실행.

### After 실험 설계 (이미 260714에 정의됨, 실행만 남음)
- **베이스라인(Before=OFF)**: `POST /api/chat?rag=false` — 전역 토글 안 건드림(라이브 데모 안 깨짐).
- **After(ON)**: `?rag=true` 또는 현재 프로덕션 상태(`ragEnabled:true`, `RAG_MIN_SCORE=0.50`, kb 362).
- **핵심 지표: `advisory`(자문) 응답률**. RAG OFF면 선례 0 → 자문 경로 통째로 죽음(미지원). → **"KB 없으면 미지원 11/20, KB 있으면 자문 14/20"이 곧 임팩트 그래프.**
- **3군 대조 유지**: ① KB 학습 질문 ② 미학습 병의원 질문 ③ 도메인 밖. (유사도 분리구간: 학습 최저 top1 0.599 vs 도메인밖 최고 0.471 — `260714 RAG개선`)
- **주의**: 판정 자체는 엔진 권위라 ON/OFF로 안 바뀌는 게 정상 — 심사위원에게 미리 설명. 임팩트는 "범위"에서 난다.
- **재사용 자산**: `bulk_ask.py`(RAG 미경유 100문항, `260710`), scratchpad `ab_test2.py`/`score_dist.py`(`260714`, 필요 시 repo로 이동), `/api/rag/stats`.
- **덤 데모 소재**: 특정 대화 retire → 그 질문 `ragHits` 감소 실증(배선실 연결끊기 효과, 아직 미실행).

### 카드에 반영할 것 (실험 후)
- 도4 옆/아래에 **RAG OFF vs ON 막대(또는 미지원→자문 전환)** 를 실측치로 추가 → 그래야 "Before/After까지 끝난" 1페이지가 됨.
- 실행 전까지는 카드의 After 슬롯을 실측 대신 **"측정 예정"** 으로 두거나, 실험을 먼저 돌린 뒤 채운다(사용자 판단 필요).
