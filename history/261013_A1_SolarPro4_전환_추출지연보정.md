## 원인
작문은 Pro 4 가 답을 짧게 써서(출력 560→430토큰) Pro 3 와 비슷했다. 늘어난 건 추출: Pro 4 는 자동 호출에서
도구를 안 부르고 산문을 쓴다(첫 턴 12/41, 이력 턴 14/16, 1~8초) → 강제 재호출이 겹쳤다. 계산 갈래 2턴째가 4.9→8.8초.

## 처방
1. 추출 지시문 규칙 5 "매 메시지 도구 1회 호출" — 첫 턴 미호출 12→3/41, 날조 0.
2. 이력 있는 턴은 자동 호출을 건너뛰고 곧바로 강제 호출(`EXTRACT_FORCE_WITH_HISTORY=off` 로 끔). 결과는 종전에도
   강제 호출 값이었다(화이트리스트 병합 + verify_decisive).

## 기각한 것
- `solar-mini4` 추출: 1.1초로 빠르나 "법인세율"→사업경비 오분류.
- 첫 턴부터 강제/`tool_choice=required`: 결정변수(증빙·명의·비율)를 지어 채운다.

## 함정
- 로컬 `.env` 에 운영 플래그가 없다(RAG_SOURCE=kb3·LAW_SELECT·LAW_ONLY…) — 없으면 법령 갈래가 no_precedent 로 보인다.
- 로컬 uvicorn 2대 + 운영이 Supabase 세션 풀(15)을 채웠다 → 로컬은 1대만, 종료는 PID kill.
- 되돌리기: 서버 `.env.bak_pro3_1013` + `systemctl restart neo-luddite-api`.
