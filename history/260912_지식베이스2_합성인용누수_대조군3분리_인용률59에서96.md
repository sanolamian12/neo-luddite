**세션 성격**: 제품 코드 전용(논문·벤치마크는 다른 세션 — `docs/doing/HF_사용정책_국내AI트랙.md` §5)

## 0. 한 줄 요약

들어갈 때의 1차 용의자(합성 프롬프트가 "모든 묶음을 인용하라"고 요구하지 않는다)는
**절반만 맞았다.** 같은 크기의 대조군에서 프롬프트 단독 처방은 59% → 75% 에 그쳤고,
나머지는 **36자 uuid 를 옮겨적는 부담**과 **한 프롬프트에 든 묶음 개수** 였다.
셋을 함께 고쳐 96%(3회 전부, 편차 0).

## 1. 측정 설계 — 분류 단계를 일부러 배제했다

합성 인용률을 재려면 "같은 세목에 속한 원문 N건"이 필요한데, 그 그룹을 LLM 분류로
만들면 측정이 오염된다. 세션 초반에 분류가 **회차 단위로 통째로 흔들린다**는 것을
발견했기 때문이다(§4).

그래서 그룹은 `rag.passages.tax_category`(레거시 17세목, 2026-08-28 소급 분류분)로
고정했다 — LLM 을 타지 않아 결정적이고, 주제 응집도도 실재한다. `인건비·가족직원`
48건(평균 654자)은 프로덕션에서 문제가 제일 심했던 `가족인건비`(27투입/6인용)와
크기·성격이 겹쳐 대역으로 적합했다.

측정은 전부 오프라인(적재 없음), 재구조화 없이 1~2분.

## 2. 대조군 — 2×2 에서 시작해 크기 축을 더했다

용의자를 둘로 두고 직교로 갈랐다.

- **커버 규칙**: "주어진 묶음은 하나도 빠짐없이 최소 한 문장의 근거로 쓰여야 한다"
  + 출력 전 id 목록 점검 지시.
- **짧은 별칭**: 프롬프트에 uuid 대신 `P1..Pn` 을 보여주고 출력에서 되돌린다.

### N=6 / N=17 (초기 2×2, 2회씩)

| N | 조건 | 인용률 |
|---|---|---|
| 6 | 현행 | 83% |
| 6 | 짧은id | 100% |
| 17 | 현행 | 74% |
| 17 | 커버규칙만 | 71% |
| 17 | 짧은id만 | 71% |
| 17 | 둘 다 | 91% |

여기서 이미 이상하다: **단독 처방은 둘 다 효과가 없는데 합치면 듣는다.**

### N=27 (프로덕션 최대 세목 크기, 3회씩)

| 조건 | 평균 인용률 | 개별 |
|---|---|---|
| 현행 | **59%** | 37% / 70% / 70% |
| 커버규칙만 | 75% | 74 / 81 / 70 |
| 짧은id만 | 74% | 74 / 78 / 70 |
| 둘 다 | 89% | 74 / 96 / 96 |
| 둘 다 + 예산 6000 | **96%** | 96 / 96 / 96 |

세 가지가 각각 독립적으로 작동하고, **예산(=한 프롬프트에 든 묶음 개수)이 마지막
한 겹**이었다. 27건을 예산만 반으로 줄여 청크 2개→4개로 나누니 편차까지 사라졌다.
청크당 ~9건이면 모델이 끝까지 읽는다.

`현행` 조건의 편차(37~70%)도 그 자체로 발견이다 — 지난 세션의 세목별 수치
(가족인건비 27/6 = 22%)는 나쁜 회차를 한 번 본 것일 수 있다. 1회 측정으로 세목별
인용률을 비교하면 안 된다.

부수 확인: uuid 조건에서만 환각 id 가 나왔고(4·2·1건), 별칭 조건에서는 **전부 0**.
`P3` 는 틀릴 여지가 없다.

## 3. 조치 (커밋 `9ae9b9d`)

| 파일 | 무엇이 바뀌었나 |
|---|---|
| `backend/api/llm.py` | `_KB2_SYNTHESIS_SYSTEM` 에 커버 규칙(5번) 추가 · `synthesize_kb2_sentences` 가 `P1..Pn` 별칭으로 프롬프트를 만들고 출력에서 uuid 로 복원 · `SYNTHESIS_INPUT_BUDGET` 12000 → **6000** · 안전망 절단 기준을 예산 → **실제 bundle 길이** |
| `backend/api/rag/kb2_synthesis.py` | `synthesize_members`(**신설**, 청크 분할+병렬 합성+dedup — 두 경로 공유) · `_dedup_sentences`(kb2_taxonomy 에서 이동) · `SYNTHESIS_WORKERS=4` · `_synthesize_category` 가 이 함수를 쓰도록 |
| `backend/api/rag/kb2_taxonomy.py` | `_synthesize_members` 는 위임만(심장박동 콜백) · `_dedup_sentences` 제거 |

설계상 짚은 것 셋:

1. **별칭 복원 시 모르는 값은 그대로 흘린다.** 호출측의 `valid_ids` 교집합이
   떨어뜨리고 `hallucinatedIdsDropped` 로 계측되게 — 조용히 버리면 환각 계측이 죽는다.
2. **안전망 절단을 예산 기준으로 두면 안 된다.** 예산보다 긴 단일 passage 는 `fit` 이
   통째로 넘기는데(그래야 안 사라진다), 절단이 예산 기준이면 그 건을 도로 훼손한다.
   예산을 반으로 줄이는 이번 변경에서 처음 위험해졌다.
3. **레거시 경로를 같이 묶었다.** `main.py:460` → `kb2_synthesis.synthesize` 는 세목
   전체를 한 프롬프트에 밀어넣고 예산 초과분을 조용히 버리고 있었다(분할이 재구조화
   쪽에만 있었다). 예산 반감은 **그쪽 유실만 두 배로** 키웠을 변경이라, 분할을 공유
   함수로 올려 둘 다 쓰게 했다.

### 병렬화 (로드맵 §7 "합성 32분" 항목도 여기서 해소)

예산 반감으로 청크 수가 2배가 되는데 합성은 이미 파이프라인 최장 단계(30세목 32분)라
순차로 두면 그대로 배가 된다. 청크는 서로 독립이므로 `ThreadPoolExecutor(4)` 로
호출하고 결과는 제출 순서로 되돌려 문장 순서를 결정적으로 유지했다.
실측 세목당 60초+ → **4~10초**.

빈 청크는 1회 재시도한다 — `synthesize_kb2_sentences` 가 타임아웃·도구호출 누락을
전부 빈 리스트로 삼키는데, 48건짜리 세목의 한 청크가 그렇게 통째로 날아가 인용률이
96% → 81% 로 내려앉는 것을 실측했다.

### 제품 경로 실측 (수정한 코드를 그대로 호출)

```
N= 6 | 인용  6/6 (100%)  청크 2  환각id 0   5s
N=17 | 인용 16/17 (94%)  청크 3  환각id 0   4s
N=27 | 인용 26/27 (96%)  청크 4  환각id 0   4s
N=48 | 인용 40/48 (83%)  청크 7  환각id 0  10s
```

문장 품질도 눈으로 확인했다(27건 → 27문장): 전부 독립 완결형 조항이고 법령 조문
인용이 붙어 있으며, 근사 중복(0.85 이상) **0쌍**, 평균 93자. 커버 규칙이 채우기용
문장을 유도하지는 않았다. 다만 의미가 겹치는 문장(같은 사안의 다른 국면)은 남는다 —
청크가 잘아질수록 늘 수 있는 쪽이라 실사용에서 볼 것.

## 4. 곁다리 발견 — 분류가 **회차 단위로** 무너진다

측정 준비 중 413건을 재분류했더니 미분류 72% 가 나왔다. 프로덕션 실측 43% 와 안 맞아
추적한 결과:

- 같은 60건·같은 목차·`temperature=0` 로 3회: **미분류 40% / 38% / 75%**.
- 판정이 갈린 건 22/60 인데, 대부분이 세 번째 회차에서 왔다.
- 예외(API 오류)는 0건이었고 동시성(8 vs 1 워커)도 차이 없었다 — 즉 우리 코드 탓이
  아니라 **한 회차가 통째로 나빠지는** 현상이다.

**미분류 재시도는 듣지 않는다**(표본 100건): 1차 33% → 2차 33% → 3차 32%. 평시에는
같은 건이 안정적으로 미분류로 돌아온다. 되는 회차/안 되는 회차가 갈릴 뿐이다.

⚠️ **이게 남긴 진짜 리스크**: `run_dynamic_restructure` 는 새 목차를 만든 뒤
`archive_all_active_documents()` 로 **멀쩡한 세대를 먼저 내리고** 새로 쌓는다. 나쁜
회차에 걸리면 좋은 KB 가 나쁜 KB 로 교체되고, 야간 예약(새벽 3시)은 아무도 안 보는
중에 그 일을 한다. 지금은 방어가 없다. 계측(coverage)은 이미 있으니 **직전 회차 대비
배정률이 크게 나빠지면 적재를 중단하고 error 로 남기는** 가드가 다음 후보다.

## 7. 측정 방법 (재현용)

지난 세션 §10 의 방식을 합성용으로 옮긴 것. 스크립트는 임시 폴더라 남지 않는다.

1. 그룹은 **LLM 분류를 타지 않는** `rag.passages.tax_category` 로 고정한다. 분류를
   거치면 §4 의 회차 편차가 합성 측정에 섞여 들어온다.
2. `인건비·가족직원`(48건) 을 `random.seed(11)` 로 섞어 앞에서 N 건씩 잘라 크기 축을
   만든다. N=27 이 프로덕션 최대 세목과 같은 크기다.
3. 조건마다 **최소 3회** 반복하고 평균과 개별값을 같이 본다 — 현행 조건의 편차가
   37~70% 라 1회로는 아무것도 못 가린다.
4. 지표는 `투입 N 대비 유효 인용 distinct` + `환각 id 수` + `문장 수`.
5. ⚠️ `load_dotenv("backend/.env")` 를 빼먹으면 키 미설정 예외가 폴백으로 삼켜진다
   (지난 세션과 동일한 함정). 그리고 Windows 콘솔은 한글이 깨지므로
   `PYTHONIOENCODING=utf-8` + 결과를 파일로 받아 읽을 것.
