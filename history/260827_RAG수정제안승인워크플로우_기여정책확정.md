## 기여 정책 결정 (사용자, AskUserQuestion)
질문: 세무사가 기존 KB passage 를 수정했을 때 크레딧을 누구에게 어떻게 주나.
선택지 4개 중 **"원작성자 유지 + 수정 이력만 기록"** 채택 — 수정해도 크레딧이 이동/분할되지 않고, 정산 로직(`contribution_counts`)을 전혀 안 건드려도 되는 가장 단순한 선택.

## 구현
- `supabase/migrations/0017_rag_passage_edits.sql` — `rag.passage_edits` 큐 테이블. pending 동안 `rag.passages` 불변. 같은 passage 에 대기 제안은 1건만(부분 unique 인덱스 `passage_edits_one_pending_per_passage`). **프로덕션 도쿄 DB에 적용 완료**(`apply_migration.py`).
- `backend/api/rag/store.py` — `propose_edit` / `list_edits` / `get_edit` / `approve_edit` / `reject_edit`. `approve_edit`은 재임베딩된 벡터를 인자로 받는다(store 는 Upstage 클라이언트를 모르는 설계 원칙 유지 — 임베딩은 `main.py`에서).
- `backend/api/schema.py` / `backend/api/main.py` — `POST /api/rag/edits`(제안) · `GET /api/rag/edits`(목록, status/passageId 필터) · `POST /api/rag/edits/{id}/approve`(Upstage `embedding-passage` 재임베딩 후 content/embedding 갱신, reviewer/auditor_id 불변) · `POST /api/rag/edits/{id}/reject`.
- `frontend/services/rag.ts` — `proposeEdit` / `listEdits` / `approveEdit` / `rejectEdit`.
- `frontend/components/audit/kb/kb-passage-detail-view.tsx` — 중심 passage 카드에 "수정 제안" 버튼 + textarea. 제안 즉시 반영 안 됨, pending 배너로 표시("승인 전까지 원문은 그대로 검색됩니다"). 하단에 "존속기간 기여는 원작성자에게 그대로 남는다" 안내 문구 추가.
- `frontend/components/admin/rag-edits-view.tsx` + `frontend/app/admin/pipeline/edits/page.tsx` — pending 큐를 현재/제안 diff 2단 컬럼으로 보여주고 승인/반려. `rag-duplicates-view.tsx`와 같은 패턴(카드형 목록 + 새로고침 + dbConfigured 배지).
- `frontend/components/layout/admin-sidebar.tsx` — "AI 코어" 섹션에 "수정 제안 승인" 링크 추가.

## 검증
- `tsc --noEmit` 클린.
- FastAPI `TestClient`로 실제 프로덕션 DB against 스모크: propose→list(pending)→reject 확인, 그리고 별도로 propose→approve(실제 Upstage 재임베딩)→content 갱신 확인→reviewer/auditorId 불변 확인→원문으로 다시 propose+approve해서 원복. 실 passage 1건(`dff35aea-...`)을 대상으로 실측, 정상 원복 확인.
