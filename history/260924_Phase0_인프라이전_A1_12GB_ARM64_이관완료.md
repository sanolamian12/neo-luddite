## 3. 계획이 틀렸던 것 세 가지

### 3-1. 비용이 약 10배 과대였다

착수계획의 **37,000원/월**은 A1 단가($0.01/OCPU·시 + $0.0015/GB·시)를 그대로 곱한 값이었다. 실제 생성 화면 견적은:

| 항목 | 월 |
|---|---|
| Compute (2 OCPU/12GB) | **항목 없음 = $0** |
| Boot volume | $2.76 |
| 합계 | **$2.76 ≈ 3,700원** |

**2 OCPU/12GB 가 A1 Always Free 한도(4 OCPU/24GB) 안에 통째로 들어간다.** 셰이프의 `Always Free-eligible` 뱃지가 2/12 에서도 유지되고, A1 Usage 가 0이었다. 남는 건 부트 볼륨뿐.

→ **"예산의 10%를 쓰는 증설"이 아니라 사실상 무료 증설**이고, 환급·인보이스 타이밍·주최측 정산 마감 논의가 통째로 실익을 잃었다. 다만 견적 면책 문구를 끝까지 읽지 못해 **며칠 뒤 Cost Analysis 실측으로 확정**해야 한다.

부수 발견: 테넌시는 **2026-07-07부터 이미 PAYG** 였다(오늘 "유료 전환"이라는 구매 행위는 없었다). 청구 통화는 **KRW 가 아니라 SGD**(개설 시 고정, 변경 불가). 8/1~9/24 청구가 전 항목 0.00 이라 "유료 계정이어도 Always Free 는 무료"가 실측으로 확인됐다 — 구 micro 를 stop 으로 남기는 비용이 0이라는 전제의 근거.

### 3-2. Reserved IP 를 "처음부터" 붙일 수 없다

착수계획 §3-3 은 *"Reserved Public IP를 처음부터 할당"* 하면 IP 가 한 번도 안 바뀐다고 적었지만, **콘솔에 그런 경로가 없다.** 생성 마법사는 Ephemeral 여부만 묻는다. 실제는 3단계:

1. Ephemeral 로 인스턴스 생성 (`140.245.86.37`)
2. Networking → IP Management 에서 Reserved IP **별도 발급** (`158.179.177.51`)
3. VNIC → IP administration → 사설 IP 행 Edit 에서 교체

게다가 **Ephemeral 이 붙어 있는 동안에는 Reserved 선택지 자체가 목록에 안 나온다** — `No public IP` 로 한 번 저장한 뒤 다시 Edit 해야 항목이 생긴다.

→ 공인 IP 가 결국 한 번 더 바뀌었다. **Caddy·Vercel 을 그 전에 설정하지 않은 덕에 재작업은 0이었다.** 다음에도 **IP 확정 → 그다음 Caddy/Vercel** 순서를 지킬 것.

콘솔 표시 함정 하나: 교체 후에도 VNIC 목록의 `IP lifetime` 열이 `Ephemeral` 로, Reserved 목록의 `VNIC` 열이 빈 칸으로 남는다. **판단 근거는 Reserved IP 의 State=`Assigned`** 와 실제 SSH 접속이다(둘 다 확인).

### 3-3. 의존성이 조용히 드리프트한다

`requirements-api.txt` 가 전부 `>=` 하한뿐이라, 오늘 새로 깐 박스는 **오늘자 최신**을 받았다:

```
openai      2.44.0 → 3.19.2   ★ 메이저. HTTP 스택 httpx → httpx2 교체
starlette    1.3.1 → 1.7.0
certifi / distro / tqdm       openai 3.x 가 의존성에서 떨궈 소멸
```

코드가 쓰는 API(`OpenAI(...)`, `.with_options(timeout=, max_retries=)`, `.chat.completions.create`, `.embeddings.create`)는 3.x 에도 대개 남아 있어 "아마 됐을" 것이다. 그러나 **이전과 SDK 메이저 업그레이드가 한 회차에 섞이면 동작 차이의 원인을 박스와 라이브러리로 가를 수 없다.** Phase 0 의 검증 기준이 "이전과 같은 결과"인 이상 도박할 이유가 없었다.

→ 구 박스 `pip freeze` 원본을 `backend/requirements-api.lock.txt` 로 커밋하고 venv 를 다시 만들어 **35개 완전 일치**를 확인했다. SDK 업그레이드는 별도 과제로 분리.

## 4. `bootstrap.sh` 가 안 만드는 것

- **iptables 80/443 ACCEPT 규칙** — 구 박스에 수동으로 들어가 있었다. 빠지면 Caddy 가 떠도 외부에서 안 붙는다. 이식 후 `iptables-persistent` 로 영구화.
- **`.env`** — 서버 실물이 9/18 수정본이었고 로컬 사본은 7/27자였다. **드리프트가 실재했다** → 반드시 서버에서 회수.

## 5. §5-3 답 — KB2 배치는 Oracle 서버에서 돈 적이 없다

journal 이 7/9 기동부터 9/24 까지 한 번도 잘리지 않고 남아 있는데, HTTP 액세스 로그를 걷어내면 스케줄러 줄이 **2개뿐**이다:

```
Sep 10  [kb2_scheduler] 재시작으로 중단 — job 1건 정리
Sep 17  [norms_scheduler] 디폴트 승인 반영 1건
```

재구조화·합성 배치는 그동안 로컬에서 돌았다. → **"1GB 로 복귀하면 KB2 배치를 못 돌린다"는 걱정에 근거가 없다.** 무료 복귀 경로(착수계획 §7-B)의 리스크가 그만큼 낮아졌다.

덤으로 9/10 줄은 **§4-2 리퍼가 실제로 도는 코드임을 실측으로 확인**해준다 — 두 인스턴스를 동시에 켜면 안 된다는 근거가 문서상 추론에서 관측으로 올라섰다.

## 7. Vercel 쪽에서 새로 걸린 것

`NEXT_PUBLIC_` 접두사 변수는 이제 **Secret 타입으로 저장할 수 없다**(정책 변경). 기존 값은 Secret 으로 만들어져 있었고 *"저장된 Secret 은 Config 로 전환 불가"* 라, **지우고 Config 타입으로 새로 만들어야** 했다(Environments = Production + Preview 로 기존과 동일 재설정).

⚠️ **`NEXT_PUBLIC_SUPABASE_URL` / `_ANON_KEY` 도 여전히 Secret 인데 지금 건드리면 안 된다** — Secret 은 열람이 안 되므로 지웠다가 값을 못 넣으면 프론트가 통째로 죽는다. 별도 건으로 남긴다.
