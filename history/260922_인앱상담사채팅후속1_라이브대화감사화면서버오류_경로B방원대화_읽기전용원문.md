## 무엇이 바뀌었나
1. **`/audit/chat-logs/<라이브 대화 id>` 가 열린다.** 전에는 서버 오류("An error occurred in the Server Components render")였다.
   서버 페이지가 클라이언트 전용 대화 스토어를 부르고 있었다. 이제 서버는 대화를 찾지 않고, 화면이 브라우저에서 대화를 당긴다 —
   불러오는 동안 스피너, 없거나 볼 수 없는 대화면 "대화를 찾을 수 없습니다". 정적 데모 대화(`clinic-vehicle` 등)는 전과 같다.
2. **세무사가 경로 B(연결 요청) 방에서도 원래 AI 상담을 본다.** 방 헤더에 "AI 상담 원문 보기" → 목록 옆에 읽기 전용 원문이 뜬다
   (검수와 같은 정지 스냅샷, 코멘트·평가 입력 없음, ← 는 그 방). 경로 A(상담 신청) 방은 전처럼 신청 상세로 간다.
   그 방의 세무사가 아니면 같은 주소에서 원문 없이 안내만 나온다.
3. **admin 풀 상세의 "감사 워크스페이스에서 보기"를 전문 펼치기로 바꿨다.** 감사 화면(`/audit/*`)은 세무사 전용이라
   admin 이 누르면 대시보드로 튕기던 죽은 링크였다.

## 결정 (사용자)
- 착수 전: 경로 B 원 대화 = **읽기 전용 원문 화면**(경로 A 링크는 그대로) · 라이브 id 감사 작업 공간의 쓰기 = **동작 그대로, 오류만** · 원문 = **정지 스냅샷**.
- 도중: admin 링크 = **풀 상세 안 전문 펼치기**(고치기 전 회귀를 돌리다 admin 이 튕기는 것을 발견).

## 설계를 따르며 정한 것
- 한 대화를 보여 주는 화면용 훅 `useConversationLookup(id)` — 기존 `useConversationRecord` 는 "조회가 끝났는데 없다"를 알려 주지 않아
  스피너와 "없음" 안내를 가를 수 없었다. 스토어를 구독하고, 없으면 DB 에서 한 번 당기고, 그 결과가 나오면 settled.
  세무사에게 "늦게 보이게 된" 대화(방이 생기며 열린 대화 — Realtime 이벤트 없음, 설계 §3.7)도 이걸로 메운다.
- 원 대화 화면은 방 주소 아래(`/audit/rooms/<방id>/conversation`)에 뒀다 — 방 목록이 옆에 그대로 있고, 권한 판단이 "내 방인가" 하나로 끝난다.
- 경로 A 신청 상세는 최신 대화, 경로 B 원문은 정지 스냅샷 — 기준이 다르다는 것을 설계 §3.7 에 적어 뒀다.
