## 무엇이 생겼나
사장님이 세무사 상담을 신청할 때 **"이 대화를 비식별 처리해 상담사 풀에 올려도 됩니다"** 에 체크할 수 있다(기본 꺼짐, 선택).
체크 전에 **"무엇이 가려지는지 보기"** 로 세무사에게 보일 모습과 가려진 항목 수를 그대로 본다. 동의하면 7일 동안
모든 세무사의 `/audit/pool` 에 비식별 사례로 뜨고, 사장님은 `/consultations` 에서 언제든 철회한다(즉시 내려감·사본 삭제).
동의가 실패해도 고른 세무사에게 가는 신청은 그대로 간다.

## 결정
- **열람 기록은 남기되 고객에게 보이지 않는다**(사용자, 착수 전). `pool_case_views` 는 admin 만 읽는다.
  기록은 상세를 여는 `open_pool_case()` 안에서만 쌓인다 — 목록 RPC 는 본문을 싣지 않으므로 "보고도 기록이 안 남는" 경로가 없다.
- 마스킹·동의·등재는 한 DB 함수 안에서. 마스킹 함수는 사용자가 직접 부를 수 없고, 세무사는 동의 테이블을 직접 읽지 못한다(0행).
  클라이언트가 마스킹을 건너뛰고 등재하거나, 원문을 풀 경로로 빼낼 자리가 구조적으로 없다.

## 도중에 잡은 것 (전부 고쳤다)
적용 전 드라이런이 전부 통과한 뒤에도, **실데이터와 실제 화면**이 여섯 가지를 더 잡았다.

1. 실데이터 218건 감사 — 실데이터엔 개인정보가 거의 없으므로 걸린 것은 대부분 오탐이다.
   "공간이 원장"·"명의가 원장님" 이 이름으로 잡혔다 → 띄어 쓴 경우 끝 글자가 조사면 명사+조사로 본다.
   단 '은'은 빼지 않았다: 이름 끝(지은·하은)에 흔해서 빼면 실명이 샌다. "인정은 원장" 과잉 마스킹 2건을 감수한다.
2. E2E 문장을 쓰다가 "원장 김철수입니다"(직함이 앞) 가 안 가려진다는 걸 발견 → 반대 방향 규칙.
3. 그 규칙이 브라우저에서 "세무사 연결해 주세요" 를 "세무사 [이름] 주세요" 로 바꿨다 → 직함에서 세무사를 빼고, 이름 뒤에 서술어·호칭·문장부호가 와야 하며, 용언 어미는 버린다.
4. 번호 하나를 넣었는데 "전화 3건" — 제목·주제 제목이 첫 질문의 사본이라 같이 셌다 → 리포트는 messages 안에서만.
5. 풀 카드에 **"사장님2"** 가 떴다. `persona.label`·`businessType` 이 계정 표시명이다 — 세무사가 어느 계정의 사례인지 알 수 있고,
   실가입자라면 이름이다. 규칙과 무관하게 `[고객]` 으로 바꾸고 목록 열에서도 뺐다. **정규식 단위시험으로는 못 잡는 종류** — 화면을 봐야 보인다.
6. 끝 쉼표 가드(`1,000-2,000` 보호용)가 "02-555-1234," 처럼 문장 속 쉼표 앞 전화를 놓쳤다 → `숫자,` 모양만 제외.

2~5번은 0037 적용 뒤라, 함수만 `create or replace` 로 바꿔 끼웠다(매번 사용자 확인). 마지막에 0037 객체를 전부 지우고 파일을
처음부터 다시 실행해 시험하는 모드(`--fresh`)로 **파일과 운영 DB 가 같다**는 것을 확인했다.
