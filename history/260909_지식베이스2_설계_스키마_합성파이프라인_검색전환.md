# 260909 · 지식베이스2(KB2) 설계 + 스키마·합성 파이프라인·검색 전환 구현

## 요약

지금 RAG(`rag.passages`)는 [질문/AI답변/세무사코멘트] 세트를 **문서 전체 단위**로 임베딩해 코사인 검색한다 — 짧은 상담 세트에는 맞지만, 백서·조항 형태로 길어지면 벡터 하나가 여러 주제의 평균이 되어 정보가 희석된다(실제로 기존 `kb_documents`도 같은 경로로 들어가 이미 이 결함을 안고 있었다). **지식베이스2(KB2)**는 RAG를 원재료로 Solar Pro가 **문장(조항) 단위**로 응축·재구성한 별도 정책 사전이다 — 검색 단위를 문서에서 문장으로 낮춰 정보 희석을 피하고, 세무사가 직접 수정 가능한 "액기스" 지식만 LLM이 참고하도록 유도한다.

이번 세션에서: **설계 문서를 아티팩트로 발행**하고, **로드맵 1~3단계(스키마·admin 합성 트리거·검색 전환 A/B)를 실제로 구현·배포 전 로컬 검증**까지 마쳤다. 기존 RAG 경로는 한 줄도 건드리지 않고 완전히 병렬로 얹었다 — `?ragSource=rag|kb2|hybrid` 쿼리 파라미터(기본값 `rag` = 기존과 100% 동일 동작)로 같은 질문을 세 갈래로 호출해 A/B 비교가 가능하다.

설계 아티팩트: https://claude.ai/code/artifact/01dacb58-7b40-40f5-aaae-09e0654cb7d4

## 1. 설계 — auditor/admin 메뉴 구조 + 폐루프 아키텍처

요청 배경: auditor 계정에 "RAG 지식망" 아래 새 메뉴 "지식베이스2"(확인+수정 가능), admin 계정에 "AI 코어" 아래 "지식베이스" 서브챕터 → "지식베이스2"(읽기전용, 수정 불가)를 만들고 싶다는 요청에서 출발.

핵심 설계 결정:
- **데이터 모델**: `kb2.documents`(세목:tax_category 1:1 컨테이너) + `kb2.sentences`(검색·크레딧·수정이력의 최소 단위, 문장별 임베딩) + `kb2.sentence_versions`(전체 이력 — 관리자 번복의 근거).
- **문장 단위 임베딩이어야 하는 이유**: 대화 중 사용자가 "지금 지식 베이스도 코사인 유사도로 찾아오냐, 백서 형식에도 같은 방식이 통하냐"고 질문 → 코드 확인 결과 `ingest_kb_document()`가 title+body 전체를 통째로 `embed_passage()`하는 것을 확인, "문서 전체 임베딩은 정보 희석을 일으킨다 → 청킹 단위를 문장/조항으로 낮춰야 한다"는 결론으로 이어짐. Solar Pro가 KB2 문장을 합성할 때 "이 경우/위와 같이" 같은 앞 문장 의존 표현 없이 **독립 완결형**으로 쓰도록 프롬프트로 강제.
- **배선실 폐루프 확장(양방향 최신화)**: 이미 있는 배선실(`packaging-eval-list-view.tsx`, `set_status(active↔retired)` = 연결/끊기, `contribution_counts()`가 active만 집계)에 KB2 훅을 얹는 설계. KB2 문장이 수정/삭제되면 그 출처가 된 `rag.passages`를 배선실의 "끊김 후보"로 자동 표시(자동으로 끊진 않음 — 관리자가 최종 판단) → 관리자가 끊으면(retired) 다음 KB2 재합성부터 자동 제외 + RAG 크레딧에서도 자동 제외. **아직 미구현, 5단계 예정.**
- **크레딧 2종 모델**: RAG 크레딧과 KB 크레딧을 독립 축으로 분리. 합성 직후엔 소스가 된 세무사들이 두 크레딧을 동시 보유(의도된 설계 — RAG 원본이 살아있는 한 RAG 크레딧 유지), 세무사가 KB2 문장을 수정하면 그 문장의 KB 크레딧만 전량 새 편집자에게 이전. **아직 미구현, 6단계 예정.**
- **admin 전용 트리거로 결정**: 합성 버튼을 admin 전용으로 할지 auditor도 누르게 할지 논의 후, 기존 AI코어 파이프라인 액션(배치·재빌드)과 동급으로 admin 전용 결정.

## 2. 로드맵 1~2단계 구현 — 스키마 + 합성 파이프라인

- **`supabase/migrations/0019_kb2_schema.sql`**: `kb2.documents`/`kb2.sentences`/`kb2.sentence_versions` + `kb2.match_sentences()` SQL 함수(`rag.match_passages`와 대칭, exact scan). `rag.*`와 동일 컨벤션(방어적 RLS: enable+정책없음, vector(4096)). 도쿄 Supabase에 적용 완료, 테이블·함수 생성 확인.
- **`backend/api/rag/kb2_store.py`**: `store.py` 컨벤션 그대로(모듈 캐시 커넥션, `%s` 바인딩). 문서/문장 CRUD, `delete_unlocked_sentences()`(재합성 시 `locked_by_auditor=false`만 정리), `match_sentences()`.
- **`backend/api/llm.py`**: `synthesize_kb2_sentences()` 신설 — tool-forced JSON 출력(`emit_kb2_sentences`)으로 조항형 단문 + 근거 passage id 배열을 강제.
- **`backend/api/rag/kb2_synthesis.py`**: 세목별 오케스트레이션. active passage → Solar Pro 합성 → 문장별 임베딩 → `locked_by_auditor=true` 문장은 보호하고 나머지만 교체.
- **`POST /admin/kb2/synthesize`** (`backend/api/main.py`) + admin 전용 프론트(`frontend/app/admin/kb2/`, `kb2-synthesis-view.tsx`, `frontend/services/kb2.ts`) + 사이드바 "AI 코어" 그룹에 "지식베이스2" 메뉴 추가.

**실제 호출 검증**: 부가가치세 세목(원천 28건)으로 실행 → 200 OK, 14문장 생성. 생성된 문장이 대명사 없이 독립 완결된 조항형("의사업·한의사업·약사업·수의사업은 부가가치세법 시행령 제109조 제2항에 따라 간이과세 배제업종으로 규정되어..."), `source_passage_ids`로 원 RAG passage 추적 가능, `attribution`에 원 세무사(auditor2/auditor3)가 자동 채워짐을 확인.

## 3. 곁가지 — Upstage API 키 확인

대회 측(메가존클라우드) 발송 "결선 인프라 안내" 메일을 근거로, 결선용 API 키가 새로 발급됐는지 확인 요청. `backend/.env`의 `UPSTAGE_API_KEY`(수정일 2026-07-27)와 사용자가 콘솔에서 새로 받아온 값을 대조 → **완전히 동일한 문자열**임을 확인. 결론: Upstage 측은 새 키를 발급한 게 아니라 **기존 키에 크레딧만 재충전**했다(사용자가 대회 측에 직접 확인). `.env` 수정 불필요.

## 4. 로드맵 3단계 구현 — 검색 전환 (RAG ↔ KB2 A/B)

- **`backend/api/rag/retriever.py`**: `Kb2Retriever`(kb2.match_sentences 검색), `HybridRetriever`(kb2 우선, 결과 없으면 rag 폴백) 신설. `get_retriever(force_enabled, source)` 확장 — `source`가 없거나 `"rag"`(또는 미인식 값)면 **기존과 완전히 동일한 코드 경로**(회귀 없음이 핵심 설계 제약).
- **`backend/api/pipeline.py`**: 두 검색 호출부(자문형 경로/엔진 판정 경로)에 `rag_source_override` 전달, 실제 사용된 소스를 `passages[0].source_kind`로 판별해 `ChatMeta.ragSource`에 기록.
- **`backend/api/schema.py`**: `ChatMeta.ragSource` 필드 추가("kb2"|"rag"|"none").
- **`backend/api/main.py`**: `/api/chat`에 `?ragSource=kb2|rag|hybrid` 쿼리 파라미터 추가(기존 `?rag=` on/off와 직교하는 축).

**실제 3-way 호출 검증**(같은 질문 "병의원이 간이과세자로 등록할 수 있나요?"):
- `?ragSource=kb2` → `ragSource:"kb2"`, 짧은 조항형 문장을 그대로 인용하는 논증.
- `?ragSource=rag` → `ragSource:"rag"`, 기존과 동일한 번들형 서술.
- 파라미터 생략(기본값) → `?ragSource=rag`와 완전히 동일한 결과 — **회귀 없음 확인**.

**발견 및 보정**: kb2 문장은 rag 번들보다 짧고 응축돼 있어 코사인 점수 분포가 낮게 형성됨(명백히 관련 있는 매치도 0.4985로 기존 `RAG_MIN_SCORE=0.50`에 근소 미달). `KB2_MIN_SCORE`(기본 0.35) 별도 임계값을 신설해 분리 — `RAG_MIN_SCORE`는 rag 전용으로 그대로 둠.

## 5. 다음 세션 후보 (로드맵 4~6단계)

- **4단계 — auditor 수정 UI**: `/audit/kb2` 페이지(문서→문장 리스트, 인라인 수정, "출처 보기", 버전 히스토리). 백엔드 `kb2.sentences` update API — 수정 시 `locked_by_auditor=true` 전환 + `sentence_versions`에 `editor_type='auditor_edit'` 기록 + `attribution` 전량 교체.
- **5단계 — admin 뷰 + 배선실 확장**: `/admin/kb2` 읽기전용 뷰(현재는 트리거 버튼만 있음) + 문장별 번복 버튼 + 배선실 "끊김 후보" 필터(§1 설계 폐루프 실제 구현).
- **6단계 — 크레딧 2종 분리**: `ledger_entries.credit_type('rag'|'kb')` 컬럼 + `kb2_contribution_counts()`(라이브 집계, `rag.store.contribution_counts()`와 같은 패턴).
- 전체 17개 세목 풀 합성은 아직 미실행(테스트는 부가가치세 1개 세목만) — 4단계 진행 전이든 후든 필요 시 admin 화면 버튼으로 실행 가능.
