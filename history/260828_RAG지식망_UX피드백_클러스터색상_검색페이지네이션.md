세션 시작 시 `git log --oneline origin/import-credigraph..import-credigraph`로 로컬-서버 동기화 확인(§3.6 교훈) — 깨끗한 상태로 시작.

## 2. 피드백 → 수정 내역 (시간순)

### 2.1 그래프 탭 우선순위 + 미분류 정렬 + 스크롤 + 토글 UI (`5fe11dc`)

사용자가 4가지를 한 번에 지적:
1. "전체 그래프" 탭을 첫 번째로, "클러스터" 탭을 두 번째로 순서 교체(기본 뷰도 그래프로 변경).
2. 세목 클러스터에서 "기타"와 "미분류"가 따로 있는 이유를 질문 → **다르다고 설명**(기타 = LLM이 세무 관련 내용은 맞다고 적극적으로 고른 잔여 카테고리, 미분류 = 분류 자체가 실패/보류된 상태, `backend/api/llm.py: classify_tax_category` 참고). 병합은 안 하되 미분류만 정렬 맨 뒤로.
3. 페이지 스크롤이 전혀 안 먹던 버그 — 원인은 `AuditShell`(`overflow-hidden` 고정 높이 컨테이너)이고, 페이지 루트에 `overflow-y-auto`가 빠져 있었음. 다른 admin 화면(`inspection-workspace.tsx` 등)의 컨벤션대로 루트 div에 `overflow-y-auto` 추가.
4. "연결끊김 포함" 버튼이 세목/직업군/유형 버튼과 디자인이 같아 혼동 — 텍스트 라벨 + ON/OFF 토글 스위치(슬라이드형)로 교체.

### 2.2 클러스터 선택 시 한줄 설명 구분선 (`bb54f97`)

카드를 선택했을 때 항목 리스트 위에 구분선 + 해당 클러스터의 한줄 설명을 추가. 세목 카테고리 설명은 `backend/api/llm.py`의 `_CLASSIFY_SYSTEM` 분류 기준 문구를 프론트에 그대로 옮겨 백엔드 분류 기준과 동일하게 유지(`TAX_CATEGORY_DESC`). 유형(세무사 코멘트/세션 총평/판례 시드/큐레이션 문서)·직업군(clinic)도 짧은 설명 추가.

### 2.3 클라이언트 사이드 페이지네이션(20건) + 전역 검색 (`8b85f3e`)

사용자 의견 요청("페이지네이션·검색이 필요할 것 같은데 넣을 수 있을까?")에 클라이언트 사이드로 충분하다고 답변(이미 `/api/rag/passages`가 전체 KB를 한 번에 내려주고 있어 병목은 전송량이 아니라 렌더링/스크롤 UX) — 서버사이드는 KB가 수천 건을 넘어 §3.2 트리거에 도달할 때 재검토하기로. 실제 워크플로우(세무사가 일감 검토 중 특정 코멘트가 KB에 이미 있는지 확인)에 맞춰:
- 클러스터 펼침 리스트 20건 단위 페이지네이션(`PaginationBar`).
- KB 전체 검색창(질문/답변/코멘트 본문·태그·작성자 대상) — 클러스터 선택 없이도 바로 검색 가능, 검색 중엔 클러스터 그리드 대신 "검색 결과" 섹션 표시.

### 2.4 클러스터 카드 색상을 그래프 노드 색과 일치 + 가나다순 정렬 (`aeeb325`)

- 카드 건수 배지 색을 `kb-graph-view.tsx`와 같은 해시 공식으로 계산해 그래프 노드 색과 일치.
- 선택 시 배지 색은 유지, 테두리(초록)+`bg-brand-green/30`(70% 투명 음영)만 추가(기존 ring 제거).
- 정렬을 건수 내림차순 → 가나다순으로 변경, "기타"·"미분류"는 값 자체가 애매/잔여 카테고리라 항상 맨 뒤(기타 → 미분류 순).

### 2.5 미분류 클러스터 설명·정렬 버그 수정 (`2269bce`)

사용자가 "미분류 설명이 안 뜬다"고 지적. 원인 파악: 프론트의 "빈 메타데이터" 플레이스홀더 상수가 `"(미분류)"`(괄호 포함)였는데, 백엔드(`taxonomy.py`)가 실제로 저장하는 값은 괄호 없는 `"미분류"`라 문자열이 안 맞았음. 2.4에서 넣은 "맨 뒤 정렬"도 사실 이 버그 때문에 작동 안 하고 있었다(우연히 건수순이라 티가 안 났을 뿐). 플레이스홀더를 `"미분류"`로 통일해 설명·정렬 둘 다 수정.

### 2.6 검색 입력 0.5초 디바운스 (`2841e27`)

타이핑마다 즉시 필터링하지 않고, 입력이 0.5초간 멈춘 뒤에만 실제 검색어에 반영. 입력창 값(`searchInput`)은 즉시 반영해 타이핑 자체는 끊김 없이 보이도록 하고, 지우기 버튼은 디바운스 없이 즉시 해제.

### 2.7 검색 결과 항목에 뿌리 클러스터 색상 태그 추가 (`e61cf7f`)

검색 결과 리스트의 각 항목 맨 왼쪽에 현재 선택된 축(세목/직업군/유형) 기준 클러스터를 색상 배경 태그로 표시. 클러스터 카드 배지·그래프 노드와 같은 색상 공식 재사용.

### 2.8 클러스터 색상 충돌 발견 + 골든앵글 배정으로 해소 (`38a8449`)

사용자가 "색상이 겹치는 것 없이 전부 다른 색인지 체크해달라"고 요청 → **실제로 문제 있었음**. 기존 `hashHue`(문자열 해시 % 360) 방식으로 18개 세목(17개+미분류)의 색을 계산해보니 최소 간격이 1도까지 붙는 쌍이 여럿:
- 출장비 ↔ 미분류: gap = 1도
- 접대성지출 ↔ 임차료: gap = 2도
- 시설·인테리어 ↔ 기타: gap = 5도
- 가사관련비 ↔ 복리후생비: gap = 4도
- 매출관리 ↔ 광고선전비: gap = 5도

사실상 같은 색으로 보이는 조합이 다수. 공용 모듈 `frontend/lib/kb-cluster-colors.ts` 신설 — 알려진 라벨 목록(세목 17+미분류, 유형 4종, 직업군)에 **골든 앵글(137.508°) 간격**으로 hue를 미리 배정, 목록에 없는 라벨만 기존 해시로 폴백. 세목 축 최소 간격이 1도 → 12도로 개선(이론적 균등 배치 최댓값은 18개 기준 20도). `kb-map-view.tsx`·`kb-graph-view.tsx`가 각자 갖고 있던 중복 색상 로직 제거하고 이 모듈 하나로 통일. 부수 발견: `kb-graph-view`의 대표 라벨 계산이 `sourceKind` 원시값(`"feedback"` 등)을 쓰고 있어 `kb-map-view`의 유형 축(매핑된 라벨 `"세무사 코멘트"` 등)과 미세하게 어긋나 있던 것도 같이 정리(`primaryClusterLabel`).

### 2.9 항목 리스트를 질문/AI답변/세무사코멘트 3줄로 고정 (`baa324f`)

기존엔 `[질문]`/`[AI 답변]`/`[세무사 코멘트]`가 합쳐진 `content` 문자열을 한 문단에 `line-clamp-2`로만 잘라 보여줘 라벨 구분이 안 됐다. `build_bundle_text()`(`backend/api/rag/ingest.py`)가 `"\n"`으로 구분해 조립하는 포맷을 그대로 파싱(`parseBundleContent`)해 항상 3줄로 분리 렌더링, 각 줄은 `truncate`(1줄 말줄임)로 카드/컬럼 너비에 맞춰 "..."이 자동으로 찍히도록 함. 클러스터 펼침 리스트·검색 결과 둘 다 `PassageListItem` 컴포넌트를 공유하므로 동시 적용.
