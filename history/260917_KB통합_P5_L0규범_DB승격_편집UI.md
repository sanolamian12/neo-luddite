## 0. 한 문단 요약

규범 md 3종을 DB(`norms.*`)로 올리고, 사람이 화면에서 규범을 검토·수정하게 했다. **초안은 운영자·세무사 누구나,
확정은 세무사만** 할 수 있고, 확정하면 재배포 없이 1분 안에(같은 프로세스는 즉시) 모든 답변에 반영된다. 매 턴 DB를
읽지 않는다 — 60초마다 확정본 지문 하나만 확인한다. DB가 원본이고 md는 장애 시 폴백이다. v1은 기존 md 그대로라
**배포 전후 답변 프롬프트는 글자 단위로 같다.** 실제 확정은 한 건도 하지 않았다(세무사 컨펌 대상) — 확정 경로는
롤백 트랜잭션 안에서만 검증했고, "화면 확정 → 논지 변경" 실호출 확인이 P5의 남은 완료 판정이다.

## 1. 설계 결정 (사용자, 세션 초)

| 질문 | 결정 | 버린 안 |
|---|---|---|
| ① 누가 편집 | 초안 누구나(admin·auditor), **확정은 세무사** | auditor 초안→admin 확정 / admin만 |
| ② 반영 시점 | **확정 즉시** | 재배포 시 / 저장 즉시(게이트 없음) |
| ③ 원본 | **DB 원본, md 폴백** | md 원본 + DB 초안함 |
| ④ 편집 단위 | **문서 3개** | 항목(M-1 등) 단위 |

①은 기존 절차 "수정안 → 세무사 컨펌 → md → 점검 → 커밋 → 배포"의 컨펌 게이트를 화면으로 옮긴 것이다. 커밋 메시지에
남기던 컨펌자·날짜는 `versions.confirmed_by/confirmed_at/note`가 대신한다.

## 2. 구현

### 2.1 0030 `norms.*`
- `documents`(name unique, order_index, origin, active_version_id, status) / `versions`(version_no, content, status
  draft|confirmed|discarded, base_version_id, note, author_id, updated_by, confirmed_by/at, discarded_by/at).
- **문서당 초안 1개** — `unique (document_id) where status='draft'`. 두 초안이 경쟁하는 확정 충돌이 원천적으로 없다.
  그래서 확정 시 "초안 뒤에 다른 확정이 끼었나" 검사는 뺐다(일어날 수 없음).
- `version_no`는 확정 때 부여 → 확정 이력 번호에 구멍이 없다. 되돌리기 = 과거본으로 새 초안 → 같은 게이트(v3 식으로 누적).
- 시드는 md에서 **생성**(손 전사 금지). 관리 주석 제거한 본문을 `$norm$` 달러 인용으로.
  - 헛걸음 1: 처음엔 `with d as (insert…), v as (insert…) update documents … from v` 한 문장으로 썼다 — **데이터 변경 CTE가
    넣은 행은 같은 문장의 본 쿼리에 안 보여** active_version_id가 안 걸린다. 문장을 나눴다.
  - 헛걸음 2: 확정 시각을 2025년 epoch로 계산 → 1789516800000(2026-09-16 00:00 UTC)로 정정.

### 2.2 로더 (`api/prompts/__init__.py`)
- `_read_sources()` → `(원문, 'db'|'md')`. DB 확정본 → 실패 시 md. `build_norms()`·예산 규칙 불변(절단 없음).
- `lru_cache` 제거 → `_State` + 락. `NORMS_CHECK_SEC`(기본 60) 동안은 메모리 블록 반환, 지나면 `active_token()`
  (active_version_id 조합 문자열) 한 번 조회 → 같으면 유지, 다르면 재빌드. **매 턴 DB 왕복 없음.**
- 실패 모드: DB 순단(지문 조회 실패) → **기존 블록 유지**. 콜드스타트 DB 장애 → md. DB 확정본이 빌드 불가(예산 초과 등) → md.
  md도 불가 → None(하드코딩 문안).
- `invalidate_norms()`(확정 API가 호출), `norms_status()`(`/rag/health`·편집 화면).
- 점검 CLI는 DB와 md 폴백을 **둘 다** 점검하고 출처를 찍는다.
  - 헛걸음 3: 첫 배포 로그가 `출처 md` — CLI는 `api/main.py`를 안 거쳐 `.env`를 안 읽었다(런타임은 db). CLI에서
    `backend/.env` 로드 → 재배포 후 `출처 db`.
- `llm.py`는 한 줄도 안 바뀜(P1 경계 약속 이행).

### 2.3 저장소·API (`api/prompts/store.py`, `main.py`, `schema.py`)
- 읽기는 모듈 캐시 커넥션, **쓰기는 호출마다 새 커넥션 + 트랜잭션**(`_tx`) — 캐시 커넥션을 스레드풀 요청이 공유하면
  여러 문장 트랜잭션에 다른 요청 문장이 섞일 수 있다. `connect_timeout=5`.
- 역할 판정: `public.profiles.domain_id → role`. 초안·폐기 = admin|auditor, 확정 = auditor. 이 레포 백엔드는 인증이 없고
  신원을 본문으로 받는 관례(kb2·rag edits와 같음) — 화면 게이팅 + 서버 역할 조회까지가 이번 범위.
- 검사: 예산(이 문서만 바꾼 주입 블록으로 `build_norms`), 빈 본문, 낙관적 잠금(`expectedUpdatedAt`), 확정 사유 필수,
  확정본과 동일 내용 거절, 동시 첫 초안(UniqueViolation) → 문구, 잘못된 UUID → "버전을 찾을 수 없음".
- 거절은 HTTP 오류가 아니라 `ok=false + error`.
- 엔드포인트: `GET /api/norms` · `GET /api/norms/{name}/versions` · `POST /api/norms/{name}/draft` ·
  `POST /api/norms/drafts/{id}/discard` · `POST /api/norms/drafts/{id}/confirm`. 확정 성공 시 경고 로그 `L0 규범 확정 — …`.
